title: History
description: Record runs into git, then track evals over time with es history, es compare and es show.
---

A scratch run in `.es/runs/` is gone when you clean up. Recording it copies it into the history folder, as files you commit like any other change.

```bash
npx es run hello --record
```

```text
…
 Results  .es/runs/20260926T170537Z_bd6205e_ada-lovelace_b50g/summary.md
recorded evals/.history/20260926T170537Z_bd6205e_ada-lovelace_b50g.json + 9 artifact files in evals/.history/20260926T170537Z_bd6205e_ada-lovelace_b50g/ (50.3 KB). Commit it with git.
```

`es record` does the same after the fact, for the latest run or the runs you name. ES never commits or pushes; you do.

## Commit the history folder

```bash
git add evals/.history
git commit -m "Record eval run"
```

```text
evals/.history/
  20260926T170537Z_bd6205e_ada-lovelace_b50g.json    the record
  20260926T170537Z_bd6205e_ada-lovelace_b50g/        its artifacts
    summary.md
    <eval>/<cell>/<n>/                              transcript, diff, checks, judge input
```

The history folder is `.history/` next to your evals. File names start with the UTC start time, so the listing is the history, and two branches that record runs merge without conflicts. A record is never edited once written.

<Warning>
  `es record` refuses any file that still looks like a secret after redaction, including the patch of uncommitted changes. Fix the leak rather than skipping the scan.
</Warning>

## Record automatically

```ts title="es.config.ts"
export default defineConfig({
  record: 'ci',                         // the default
  history: { artifacts: 'failures' },   // 'all' by default
  // …
})
```

`record: 'ci'` records every run when `CI` is set, `'always'` records every run, and `'manual'` only with `es record` or `--record`. A profile can set its own, as `nightly` does in `examples/hello`. `history.artifacts` keeps every attempt's artifacts, only failing ones', or none.

## See each eval over time

```bash
npx es history
```

```text
8 runs, oldest → newest: 20260926T170456Z_bd6205e_ada-lovelace_avn4 (bd6205e) … 20260926T170907Z_bd6205e_ada-lovelace_nfvg (bd6205e)

  ✓✓✓·✓✓·✗    5/6  evals/hello.es.ts › greet module › creates a tested greet module
  ✓✓✓·✓✓·✗    5/6  evals/hello.es.ts › greet module › adds a default name in a follow-up turn
  ····✓·✓·    2/2  evals/jq.es.ts › summarises a JSON file with jq
…
  ✓✓·✓····    3/3  evals/skill.es.ts › house greeting › greets in the house style
…

✓ pass  ✗ fail  ! infra error  ↓ skipped  · not run  ¦ eval or stack changed
```

One column per recorded run, oldest first. A `¦` marks where an eval's code or stack changed, so a new failure after it may not be a regression. `--all` adds unrecorded scratch runs, and `--json` prints the data.

## Compare two runs

```bash
npx es compare 20260926T135737Z 20260926T140020Z
```

```text
base 20260926T135737Z_931dae5_ci_zfv3 (931dae5) → head 20260926T140020Z_931dae5_cursor-agent_3sth (931dae5)
0 regressed · 0 fixed · 0 not comparable · 1 same
stack changed: environments es-good@f107f5cc4c85, es-weak@a6e7d603552c → broken-project@c435782dc82e, …

  · → ✗  new                       evals/compare.es.ts › from scratch › plans a skill compare
  · → ✓  new                       evals/fix-config.es.ts › broken project › fixes a broken config and explains it
  ✓ → ✓  same                      evals/scaffold.es.ts › from scratch › scaffolds a first eval and runs it
```

`es compare` takes a base and a head run. With none, it diffs the latest run against its nearest recorded ancestor in git. Each eval is `regressed`, `fixed`, `same`, `new`, `removed` or `not comparable`. Not comparable means something the eval depends on changed, such as its file, a helper it imports, the image or the judge, and the line says which.

<Image src="/assets/studio/compare.png" alt="The studio's compare page, listing evals as regressed, fixed or not comparable between two runs" width={800} />

```bash
npx es compare --md                   # a Markdown table for a PR comment
npx es compare --fail-on-regression   # exit 1 if anything regressed
```

## Show one run

```bash
npx es show latest
```

```text
run 20260926T170907Z_bd6205e_ada-lovelace_nfvg  2 failed
  started 2026-09-26T17:09:07.791Z  (5s) · artifacts all

  Executed at   bd6205e6903f on master, clean (the commit that adds this record is later)
  Lockfiles     pnpm-lock.yaml 31394c6a3886
  Images        evalsuite-sandbox:claude-code-1.0.128 · id 532be4b5edeb · no registry digest (built locally) · CLI 2.1.276 (Claude Code)
  Harnesses     claude-code:claude-sonnet-5 (model claude-sonnet-5)
  Environments  none
  Judge         google/gemini-3.8-flash · threshold 0.8 · version e0f032315413
…
```

`es show` prints the state a run ran in: the commit, lockfiles, images, harnesses, environments and judge. `--md` prints its `summary.md`, and `--json` the record. A run is `latest`, `latest~N`, a run id or a unique prefix, or a git SHA prefix.

## Reproduce a run

```bash
npx es checkout latest
```

```text
checked out b3ccaa3613e1 into .es/checkouts/20260926T171355Z_b3ccaa3_cursor-agent_dw8v and applied worktree.patch.
Remove it with: git worktree remove .es/checkouts/20260926T171355Z_b3ccaa3_cursor-agent_dw8v
```

`es checkout` makes a git worktree at the commit the run executed at. If the run had uncommitted changes, the record saved them as `worktree.patch`, and checkout applies it.
