title: History
description: Record runs into git, then track evals over time with reeval history, reeval compare and reeval show.
---

A scratch run in `.reeval/runs/` is gone when you clean up. Recording it copies it into the history folder, as files you commit like any other change.

```bash
npx reeval run hello --record
```

```text
…
2 pass
Set analysis.model in reeval.config.ts for answers to what each eval asks.
recorded evals/.history/20261020T213700Z_a3fbded_cursor-agent_00tz.json + 10 artifact files in evals/.history/20261020T213700Z_a3fbded_cursor-agent_00tz/ (399.2 KB). Commit it with git.
```

`reeval record` does the same after the fact, for the latest run or the runs you name. reeval never commits or pushes; you do.

## Commit the history folder

```bash
git add evals/.history
git commit -m "Record eval run"
```

```text
evals/.history/
  .gitignore                                        un-ignores recorded files
  20260926T174005Z_b010670_ada-lovelace_xdb9.json    the record
  20260926T174005Z_b010670_ada-lovelace_xdb9/        its artifacts
    summary.md
    <eval>/<cell>/<n>/                              transcript, diff, checks, judge input
```

A project `*.log` would drop `setup.log` and `checks/<n>.log`. `reeval record` writes
`.gitignore` in the history folder to keep them. If git still ignores a file it wrote, it
warns and names the rule.

The history folder is `.history/` next to your evals. File names start with the UTC start time, so the listing is the history, and two branches that record runs merge without conflicts. A record is never edited once written.

<Warning>
  `reeval record` refuses any file that still looks like a secret after redaction, naming the file, the line and the rule. A patch of your uncommitted changes that looks like it holds one is left out of the record instead. Fix the leak rather than skipping the scan.
</Warning>

## Record automatically

```ts title="reeval.config.ts"
export default defineConfig({
  record: 'ci',                         // the default
  history: { artifacts: 'failures' },   // 'all' by default
  // …
})
```

`record: 'ci'` records every run when `CI` is set, `'always'` records every run, and `'manual'` only with `reeval record` or `--record`. A profile can set its own, such as a `nightly` profile that always records. `history.artifacts` keeps every attempt's artifacts, only failing ones', or none.

## See each eval over time

```bash
npx reeval history
```

```text
7 runs, oldest → newest: 20260926T174005Z_b010670_ada-lovelace_xdb9 (b010670) … 20260926T174444Z_b010670_ada-lovelace_7gmj (b010670)

  ✓·✓✓·✓✓    5/5  evals/hello.eval.ts › greet module › creates a tested greet module
  ✓·✓✓·✓✓    5/5  evals/hello.eval.ts › greet module › adds a default name in a follow-up turn
  ·✓····✓    2/2  evals/skill.eval.ts › house greeting › greets in the house style
  ··✓·✓··    2/2  evals/jq.eval.ts › summarises a JSON file with jq
…

✓ pass  ✗ fail  ! infra error  ↓ skipped  ○ not gated  · not run  ¦ eval or stack changed
```

One column per recorded run, oldest first. A `¦` marks where an eval's code or stack changed, so a new failure after it may not be a regression. `--all` adds unrecorded scratch runs, and `--json` prints the data.

## Compare two runs

```bash
npx reeval compare
```

```text
can't compare    bills in minor units with the billing doc
  changed          environment
  base             20261020T231407Z_ea2a649_ada-lovelace_8h1n  pass
  head             20261020T231408Z_b2c98b4_ada-lovelace_fypq  fail
  amount in minor units  failed
    expected command to succeed, exit code 1

+1 same

fixed            adds a double button that builds
  build            fail → pass
  types            not run → pass

+1 same

regressed        greets in the house style
  base             20261020T231407Z_ea2a649_ada-lovelace_8h1n
  head             20261020T231408Z_b2c98b4_ada-lovelace_fypq
  house greeting   pass → fail
    expected command to succeed, exit code 1
  sign-off         not run
  +1 more passed

+2 same

removed          greets in German
  base             20261020T231407Z_ea2a649_ada-lovelace_8h1n  fail

new              greets in Spanish
  head             20261020T231408Z_b2c98b4_ada-lovelace_fypq  fail
  spanish greeting  failed
    expected command to succeed, exit code 1

1 regressed · 1 fixed · 1 can't compare · 1 new · 1 removed · 4 same
```

`reeval compare` takes a base and a head run. With none, it diffs the latest run against its nearest recorded ancestor in git. It prints a block for each eval that changed, in file order, and collapses the rest to `+N same`.

| Block | What it shows |
|---|---|
| `regressed` | Both run ids, each check that flipped (`pass → fail`) with its message, and checks that no longer ran (`not run`) |
| `fixed` | The checks that pass now |
| `can't compare` | What changed, such as the environment, the eval's file or a helper it imports, and each side's result. An eval Ctrl-C cancelled on one side reads `cancelled` there |
| `new`, `removed` | An eval only one run has, with its result |

A check that didn't run on one side reads `not run`, never `fail`. `-v` adds each cell's lift and effort, base → head.

<Image src="/assets/studio/compare.png" alt="The studio's compare page, listing evals as regressed, fixed or not comparable between two runs" width={800} />

```bash
npx reeval compare --md                   # the same blocks in a text block, for a PR comment
npx reeval compare --fail-on-regression   # exit 1 if anything regressed
```

`reeval analyze` reads the same pair of runs and explains the difference in plain words. [Analysis](/guide/analysis) covers it.

`reeval show` prints the state a run ran in, the latest by default: the commit, lockfiles, images, harnesses, environments and judge. Here that's the cross-agent run from [Harnesses](/guide/harnesses).

`--md` prints its `summary.md`, and `--json` the record. A run is `latest`, `latest~N`, a run id or a unique prefix, or a git SHA prefix.

## Reproduce a run

```bash
npx reeval checkout latest
```

```text
checked out b3ccaa3613e1 into .reeval/checkouts/20260926T171355Z_b3ccaa3_cursor-agent_dw8v and applied worktree.patch.
Remove it with: git worktree remove .reeval/checkouts/20260926T171355Z_b3ccaa3_cursor-agent_dw8v
```

`reeval checkout` makes a git worktree at the commit the run executed at. If the run had uncommitted changes, the record saved them as `worktree.patch`, and checkout applies it. A run recorded without its patch (too large, `--artifacts none`, or it looked like it held a secret) checks out as the commit alone, and says so:

```text
checked out 161d9a9f93d7 into .reeval/checkouts/20260930T165638Z_161d9a9_ada-lovelace_vkcv, without the run's uncommitted changes: they weren't saved (not kept: it looked like it held a secret (.env.example line 3: Google API key)).
```
