---
title: Harnesses
description: Run evals on Cursor, Claude Code, Antigravity, OpenCode, Goose, pi or Codex, or on several at once as separate cells.
---

A harness is the coding agent reeval drives. The same eval runs on any of them, so you can see whether your skill helps one agent and not another.

```ts title="evals/harnesses.ts"
import { antigravity, claudeCode, codex, cursor, goose, opencode, pi } from '{{ pkg }}/harness'

export const composer = cursor({ model: 'composer-2.5' })
export const claude = claudeCode({ model: 'claude-sonnet-5' })
export const agy = antigravity({ model: 'gemini-3.8-flash-medium' })
export const oc = opencode({ model: 'google/gemini-3.8-flash' })
export const gs = goose({ model: 'gemini-3.8-flash' })
export const pim = pi({ model: 'gemini-3.8-flash' })
export const cx = codex({ model: 'gpt-5.6-luna' })
```

`examples/hello` defines its harnesses once, so the config, evals and profiles share them.

## Give each harness its key

| Harness | Key | `model` |
|---|---|---|
| `cursor()` | `CURSOR_API_KEY` | Required, such as `composer-2.5` |
| `claudeCode()` | `ANTHROPIC_API_KEY` | Required: any id or alias the `claude` CLI takes |
| `antigravity()` | `GEMINI_API_KEY`, a Gemini API key | Required: a slug `agy models` lists, such as `gemini-3.8-flash-medium` |
| `opencode()` | The model's provider's, such as `ANTHROPIC_API_KEY` for `anthropic/…` | Required: `<provider>/<model>`, such as `google/gemini-3.8-flash` |
| `goose()` | `GOOGLE_GENERATIVE_AI_API_KEY`, a Gemini API key | Required: a Gemini model id, such as `gemini-3.8-flash` |
| `pi()` | `GOOGLE_GENERATIVE_AI_API_KEY`, a Gemini API key | Required: a Gemini model id, such as `gemini-3.8-flash` |
| `codex()` | `OPENAI_API_KEY`, an OpenAI API key | Required: an OpenAI model id, such as `gpt-5.6-luna` |

```bash title=".env.local"
CURSOR_API_KEY=...
ANTHROPIC_API_KEY=...
GEMINI_API_KEY=...
GOOGLE_GENERATIVE_AI_API_KEY=...
OPENAI_API_KEY=...
```

Each harness authenticates only with its own key, which stays on the host. reeval never falls back to an `AI_GATEWAY_API_KEY`, a subscription or a keychain login. Real harnesses need `docker()`.

## Run OpenCode on any provider

```ts title="evals/harnesses.ts"
export const ocClaude = opencode({ model: 'anthropic/claude-haiku-4-5' })
export const ocRouter = opencode({ model: 'openrouter/openai/gpt-5.4-mini' })
```

OpenCode's model id names its provider, and the provider picks the key: `anthropic/…` needs `ANTHROPIC_API_KEY`, and only that key is brokered. reeval runs it on any of the providers whose key OpenCode sends in a header, and refuses the rest (Vertex, Azure, subscriptions, local servers) at plan time. Bedrock runs on a Bedrock API key (`AWS_BEARER_TOKEN_BEDROCK`) in its `AWS_REGION`. The [OpenCode reference](/reference/harness/opencode#supported-providers) lists both.

## Run under another harness

```ts title="reeval.claude.config.ts"
import { defineConfig } from '{{ pkg }}'
import { claude } from './evals/harnesses.ts'

export default defineConfig({
  include: ['evals/hello.eval.ts', 'evals/skill.eval.ts'],
  harness: claude,
  judge: { model: 'google/gemini-3.8-flash', threshold: 0.8 },
  timeout: '15m',
})
```

```bash
npx reeval image build --config reeval.claude.config.ts
npx reeval run --config reeval.claude.config.ts
```

Each harness has its own sandbox image with its agent baked in, such as `reeval-sandbox:antigravity-0.1.3` or `reeval-sandbox:cursor-0.1.2`. `reeval image build` builds the images for the harnesses the config plans. Cursor's agent runs through the Cursor TypeScript SDK; Claude Code, Antigravity, pi and Codex run their CLIs, and OpenCode and Goose their ACP servers.

## Run several harnesses as cells

```ts title="reeval.agents.config.ts"
import { defineConfig } from '{{ pkg }}'
import { agy, composer } from './evals/harnesses.ts'

export default defineConfig({
  include: ['evals/hello.eval.ts', 'evals/skill.eval.ts'],
  harness: [composer, agy],
  judge: { model: 'google/gemini-3.8-flash', threshold: 0.8 },
  gate: { passRate: 0.5 },
  timeout: '15m',
})
```

`harness` is the one option that takes a list: each harness is its own [cell](/concepts/matrix), and each compare variant runs on every one. The `greet` evals and the house-greeting compare on Cursor and Antigravity, twice each:

```bash
npx reeval run --config reeval.agents.config.ts --runs 2 --log-order grouped
```

## Name cells with ids

```ts title="evals/guide-matrix.eval.ts"
harness: [
  cursor({ model: 'composer-2.5' }), // id cursor:composer-2.5
  cursor({ model: 'composer-2.5', params: { fast: 'true' }, id: 'fast' }),
],
```

A harness's id defaults to `<kind>:<model>`. It names the cell (`cursor:composer-2.5/with-house-greeting/docker`), so two harnesses of the same kind and model need distinct ids, even when their `params` differ:

```text
reeval: evals/guide-matrix.eval.ts: Two harnesses in evaluate("fast and slow") resolve to the id "cursor:composer-2.5". Give one an id, e.g. cursor({ model: '…', id: '…' })
```

`params` sets Cursor's model parameters, as strings. One you leave out takes the default variant Cursor's catalog lists (`fast=true` for `composer-2.5`), and reeval records and shows the variant that ran. The default can change, so pin every parameter, such as `params: { fast: 'false' }`, for reproducible evals.

Filter a run by id, as in `npx reeval run skill antigravity`, and a profile's `limit.harness` lists ids too.

## Compare on some harnesses

```ts title="evals/guide-matrix.eval.ts"
{
  harness: [composer, claude, agy],
  compare: {
    baseline: plain,
    variants: [withHouseGreeting],
    harness: ['cursor:composer-2.5'],
  },
  runs: 5,
}
```

```text
eval                                                         harnesses  variants  runs  attempts  notes
evals/guide-matrix.eval.ts › house greeting on every agent ›…  3          1         5     20
```

`compare.harness` runs the variants only on the listed harnesses; the others run the control alone. Here that's three controls and one variant, five times each: 20 attempts instead of 30.

## Add to the inherited list

```ts
{ harness: { add: cursor({ model: 'composer-2' }) } }
{ harness: { only: 'cursor:composer-2.5' } }
```

A list replaces the inherited harnesses. `add` appends one or a list to them, and `only` keeps those with these ids. A function, `(inherited) => [...inherited, cursor({ model: 'composer-2' })]`, gets the inherited list and returns a new one.

| Harness | Key | Key brokered | Rules file | Skills: workspace | Skills: home | MCP stdio | MCP http | MCP sse | Tokens | Served model | Web search events | Web fetch events | Sandbox |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| [Cursor](/reference/harness/cursor) | `CURSOR_API_KEY` | ✓ | `AGENTS.md` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | `docker()` |
| [Claude Code](/reference/harness/claude-code) | `ANTHROPIC_API_KEY` | ✓ | `CLAUDE.md` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | `docker()` |
| [Antigravity](/reference/harness/antigravity) | `GEMINI_API_KEY` | ✓ | `AGENTS.md` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | `docker()` |
| [OpenCode](/reference/harness/opencode) | The model's provider's | ✓ | `AGENTS.md` | ✓ | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ | ✓ | ✓ | `docker()` |
| [Goose](/reference/harness/goose) | `GOOGLE_GENERATIVE_AI_API_KEY` | ✓ | `AGENTS.md` | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ | ✗ | ✗ | `docker()` |
| [pi](/reference/harness/pi) | `GOOGLE_GENERATIVE_AI_API_KEY` | ✓ | `AGENTS.md` | ✓ | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ | ✗ | ✗ | `docker()` |
| [Codex](/reference/harness/codex) | `OPENAI_API_KEY` | ✓ | `AGENTS.md` | ✓ | ✓ | ✓ | ✓ | ✗ | ✓ | ✓ | ✓ | ✓ | `docker()` |

- **Cursor**: The gateway also swaps the session tokens the Cursor SDK exchanges its key for (`accessToken` and `refreshToken`) on `cursor.sh` and `*.cursor.sh`. Served model as the harness reports it: its API requests don't name one, so the record's `servedModels` is null. Its SDK leaves web search and fetch calls out of the stream; reeval recovers them from the stored conversation, and a turn it can't recover is marked `unreported` so web matchers refuse it.
- **Claude Code**: Served model as the harness reports it: its API requests don't name one, so the record's `servedModels` is null.
- **Antigravity**: Its CLI always tries `play.googleapis.com` and `antigravity-unleash.goog`; a restricted egress policy refuses them and records them under the record's `egress.expectedBlocked`.
- **OpenCode**: Its key is the model's provider's (`anthropic/claude-haiku-4-5` takes `ANTHROPIC_API_KEY`), on any of the 202 providers whose key OpenCode sends in a header on known hosts; the other 22 are refused at plan time. No `mcp.sse` transport: those servers are refused at plan time (exit 2). Its web searches go to Exa's hosted MCP server, keyless, from the sandbox: `mcp.exa.ai` is one of its automatic hosts. MCP servers go in its config with Code Mode off, not over ACP, where OpenCode offers them only through its `execute` tool; the first prompt waits until they've connected.
- **Goose**: No `mcp.sse` transport: those servers are refused at plan time (exit 2). MCP servers go in its `config.yaml` as enabled extensions, not over ACP, where they start disabled. No tokens recorded: its ACP server reports its last model call's usage, not the turn's, so the adapter drops it rather than record an undercount.
- **pi**: No `mcp.sse` transport: those servers are refused at plan time (exit 2).
- **Codex**: No `mcp.sse` transport: those servers are refused at plan time (exit 2). Served model and reasoning effort from each API response, which the gateway reads (e.g. `gpt-5.6-luna[effort=medium]`): its CLI doesn't report them. Its web searches and the pages it opens run on OpenAI's side, so a restricted egress policy doesn't limit them; each is in the transcript.
