---
title: "Define an environment"
description: "Give each harness attempt the files, rules, skills, and servers it needs."
---

An environment is what your harness gets in an attempt. `defineEnvironment()` defines an environment, and its `.extendEnvironment()` method derives a variant from it. Define environments in the `evals/environments.ts` file that `reeval init` writes.

## Define and use an environment

<Steps>
<Step title="Define an environment">

In the `evals/environments.ts` file, pass `defineEnvironment()` a name and a spec, or a callback that returns one. The name becomes the environment segment of the cell key.

```ts title="evals/environments.ts"
import { defineEnvironment } from '{{ pkg }}'

export const page = defineEnvironment('page', ({ directory }) => ({
  files: directory('./project'),
}))
```

For more information about each environment field, see [Workspaces](/environments/repositories), [Files](/environments/files), [Rules](/environments/rules), [Setup commands](/environments/setup), [MCP servers](/environments/mcp), [Secrets](/environments/secrets), [Egress](/environments/egress), [Sandboxes](/integrations/sandboxes), and [Environment fields](/reference/environment#environmentspec).

</Step>
<Step title="Extend an environment">

In the `evals/environments.ts` file, call `.extendEnvironment()` on `page` to derive `brand-guidelines`. The child keeps the parent's fields and adds its own, so the baseline and the variant differ by one change.

```ts title="evals/environments.ts"
export const withSkill = page.extendEnvironment(
  'brand-guidelines',
  ({ skill }) => ({
    skills: [
      skill.git('github:anthropics/skills', {
        ref: 'dbd4588f9e1033efb41dad4bef2f7947c8993d44',
        path: 'skills',
        only: ['brand-guidelines'],
      }),
    ],
  }),
)
```

The callback receives `skill`, `mcp`, `secret`, `file`, `directory`, and `git`. `defineEnvironment()` accepts the same callback. Relative paths resolve against the file that calls the helper.

For more information about skill sources, see [Skills](/environments/skills).

A child merges `files`, `env`, `skills`, and `mcp` with its parent's by name, and runs its `setup` commands after its parent's. A child that sets `sandbox`, `workspace`, `rules`, or `egress` replaces the parent's value. `extend` is an alias of `.extendEnvironment()`.

For more information about the merge rules, see [`extend`](/reference/environment#extend).

</Step>
<Step title="Use an environment in an evaluation">

In the `evals/brand.eval.ts` file, pass `page` as the `environment` and `withSkill` as a variant. reeval names each cell by its harness, environment, and sandbox.

```ts title="evals/brand.eval.ts"
import { page, withSkill } from './environments.ts'
// ...
evaluate(
  "styles the page in Anthropic's brand",
  { environment: page, compare: { variants: [withSkill] } },
  // ...
)
```

For more information about where you can set the option, see [the `environment` option](/reference/options#environment).

</Step>
<Step title="Verify with the `reeval run --dry-run` command">

Print the plan as JSON. The `reeval run --dry-run --json` command plans the run without starting a sandbox or a harness, so it needs no API key.

```bash
npx reeval run --dry-run --json
```

Each cell in an evaluation's `cells` list names its environment and the files it writes. The `brand-guidelines` cell, trimmed here to the fields that matter, lists the `index.html` file from `page`, which shows that the child kept the parent's files:

```json
{
  "key": "claude-code:claude-sonnet-5/brand-guidelines/docker",
  "environment": "brand-guidelines",
  "role": "variant",
  "files": [
    "index.html"
  ]
}
```

For a runnable project, see [`with-library-skill-lift`](https://github.com/invertase/reeval/tree/main/examples/with-library-skill-lift).

</Step>
</Steps>

## Give every evaluation an environment from the config

In the `reeval.config.ts` file, set `environment` to run every evaluation that sets none of its own in it:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { page } from './evals/environments.ts'

export default defineConfig({ environment: page })
```

A group's or an evaluation's `environment` replaces the config's.
