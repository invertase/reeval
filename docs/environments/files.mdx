---
title: "Place files"
description: "Give the agent the files an evaluation starts from."
---

You set `files` on an environment to put source in the workspace before the agent starts. A destination path is relative to the workspace, uses forward slashes, and never contains `..`. To write into the home directory, start a path with `~/`.

## Write a file

Set `files` to an object of destination paths and contents. A string is written into the sandbox as that file.

In the `evals/environments.ts` file, define the environment:

```ts title="evals/environments.ts"
import { defineEnvironment } from '{{ pkg }}'

export const csv = defineEnvironment('csv', ({ directory, file }) => ({
  files: {
    ...directory('./project', { glob: ['!NOTES.md'] }),
    'data/people.csv': file('./data/people.csv'),
    '.gitignore': 'node_modules/\n',
  },
}))
```

The `.gitignore` entry writes that string to the workspace. For a runnable project, see [`with-fixture`](https://github.com/invertase/reeval/tree/main/examples/with-fixture).

## Copy a host file

When the content already exists on your machine, pass a host path to `file`, as the `data/people.csv` entry does. A relative path resolves from the file that calls `file`. reeval uses an absolute path as given.

reeval reads the host bytes when the attempt starts. A host file with its executable bit set stays executable in the sandbox. A destination that starts with `~/` goes in the home directory, outside the workspace and its diff:

```ts title="with-multi-turn.eval.ts"
files: {
  ...directory('./project'),
  '~/checks/call.mjs': file('./checks/call.mjs'),
},
```

## Copy a directory

Pass a host directory to `directory` to copy the files in it, as the `./project` entry does. `directory` chooses the files when you call it, and reeval reads each host file when the attempt starts. A relative path resolves from the file that calls `directory`. Here `glob` leaves out the maintainer notes in `NOTES.md`.

To copy into a subdirectory, pass `into`, such as `directory('./fixtures', { into: 'src' })`. `into` is the destination directory. A value that starts with `~/` places the files under the home directory. `into` uses forward slashes and doesn't contain `..`.

`glob` is an ordered list of gitignore-style patterns over paths relative to the host directory. The last pattern that matches a path decides. A pattern that starts with `!` excludes that path. When a pattern includes files, reeval leaves out a file that no pattern matches. With only `!` patterns, or with `glob` omitted, every file starts included.

`directory` anchors a pattern that contains a `/`, other than at the end, to the host directory. Without a `/`, a pattern matches a name at any depth. A trailing `/` matches a directory and everything in it.

By default, `directory` leaves out these paths:

```text
node_modules/
.DS_Store
dist/
.next/
.turbo/
coverage/
.cache/
__pycache__/
.venv/
venv/
.pytest_cache/
.mypy_cache/
*.pyc
.dart_tool/
/build/
/target/
.gradle/
.idea/
.vscode/
```

A leading `/` anchors a pattern to the top of the host directory. The `/build/` and `/target/` patterns don't match a nested directory of that name. The other patterns match that name at any depth. `directory` copies a `vendor/` directory because an offline build needs it.

To switch the default ignores off, set `defaultIgnores` to `false`. `directory` always leaves out the `.git` directory. A `glob` pattern can't include a path excluded by the defaults.

`directory` doesn't copy an empty directory. Calling `directory` fails when the directory is missing, or when no file matches. A later entry in `files` replaces a copied file. A host file with its executable bit set stays executable in the sandbox.
