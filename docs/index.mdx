reeval is an evaluation runner for SDKs, CLIs, MCP servers, and docs. It evaluates how coding agents discover and use them, across harnesses and across changes such as adding a skill.

## What reeval does

An evaluation gives a harness a task in a sandbox, then checks what the agent did. A comparison runs the same evaluation on a control and on a variant with one change. reeval reports whether the change `helped`, `made it worse`, or `can't tell yet`. For more information about each term, see [Core concepts](/core-concepts).

This example measures Anthropic's published `brand-guidelines` skill. The control is an unstyled HTML page. The variant adds the skill from the `anthropics/skills` repository at a pinned commit. The evaluation declares the control, the variant, and the comparison in one file:

```ts title="with-library-skill-lift.eval.ts"
import { defineEnvironment, evaluate, expect } from '{{ pkg }}'

const page = defineEnvironment('page', ({ directory }) => ({
  files: directory('./project'),
}))
const withSkill = page.extendEnvironment('brand-guidelines', ({ skill }) => ({
  skills: [
    skill.git('github:anthropics/skills', {
      ref: 'dbd4588f9e1033efb41dad4bef2f7947c8993d44',
      path: 'skills',
      only: ['brand-guidelines'],
    }),
  ],
}))

evaluate(
  "styles the page in Anthropic's brand",
  {
    environment: page,
    compare: { variants: [withSkill] },
    runs: 4,
    gate: { passRate: 0.75 },
  },
  async (c) => {
    await c.send(
      "Give index.html Anthropic's look: write styles.css with Anthropic's " +
        'brand colours and fonts, and link it from index.html.',
    )

    await expect
      .soft(c, 'links styles.css')
      .toHaveFile('index.html', /href="styles\.css"/)
    await expect.soft(c, 'brand orange').toHaveFile('styles.css', /#d97757/i)
    await expect(c, 'brand fonts').toHaveFile(
      'styles.css',
      /Poppins[\s\S]*Lora|Lora[\s\S]*Poppins/,
    )
  },
)
```

The prompt doesn't name the brand's colour or fonts, so `brand orange` and `brand fonts` pass only when the harness knows them. When the variant passes all four attempts and the control passes none, the run prints this block:

```text
pass             styles the page in Anthropic's brand
  arm               pass
  page              0 of 4
  brand-guidelines  4 of 4  helped
  check             page    brand-guidelines
  brand orange      0 of 4  4 of 4
    expected styles.css to match /#d97757/i
  brand fonts       0 of 4  4 of 4
    expected styles.css to match /Poppins[\s\S]*Lora|Lora[\s\S]*Poppins/
  +1 more passed
```

The `arm` column lists the control and the variant. The variant passed both brand checks in 4 of 4 attempts and the control in 0 of 4, so the effect reads `helped`. This block comes from the example's scripted agent, and a real run's counts can differ. For more information about how reeval reaches the effect, see [Statistics](/evals/statistics). For the runnable project, see [`with-library-skill-lift`](https://github.com/invertase/reeval/tree/main/examples/with-library-skill-lift).

## What reeval supports

This table lists what reeval supports, and each area links to its section:

| Area | What reeval supports |
|---|---|
| [Evaluations](/evals/evaluate) | TypeScript files beside the tool they test, with checks on files, commands, and tool calls, and a judge for what checks can't read |
| [Comparisons](/evals/compare) | A control and one or more variants, with an effect for each variant |
| [Environments](/environments) | Skills, MCP servers, rules, files, setup commands, and secrets for the harness |
| [Harnesses](/harnesses) | Coding agents, each on the model and effort you set |
| [Sandboxes](/sandboxes) | A fresh container for each attempt, with API keys kept on the host |
| [Runs](/runs/running) | A plan before any attempt starts, profiles that size a run, and records you commit beside the code |
| [Results](/results/output) | The outcome, transcript, and analysis of each run, and queries across recorded runs |

Each kind of tool reeval evaluates has a recipe: [Test an SDK](/recipes/sdk), [Test a CLI](/recipes/cli), [Measure MCP servers](/recipes/mcp-comparison), and [Measure your docs](/recipes/docs-comparison). For more information about commands and options, see the [CLI reference](/reference/cli) and [Options](/reference/options).
