`cursor()` runs Cursor's agent in the sandbox through the Cursor TypeScript SDK's local runtime. For more information about the sandbox, see [Choose a sandbox](/integrations/sandboxes).

## `CURSOR_API_KEY`

`cursor()` reads `CURSOR_API_KEY` from the environment or the `.env.local` file. A run exits with code 2 when the variable is unset, or when the value contains whitespace or a line break.

reeval exchanges that key for `accessToken` and `refreshToken` at `api2.cursor.sh`, on `POST /auth/exchange_user_api_key`. Requests to `cursor.sh` and `*.cursor.sh` carry those tokens. A restricted egress policy allows `api2.cursor.sh` and `*.cursor.sh`.

When the API rejects the key, the attempt error begins with `The API rejected CURSOR_API_KEY: set a valid key in the environment or .env.local`.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about the variable, see [`CURSOR_API_KEY`](/reference/env-vars#cursorapikey).

## `cursor()`

`cursor()` is exported from `{{ pkg }}/harness`. The following configuration passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { cursor } from '{{ pkg }}/harness'

export default defineConfig({
  harness: cursor({
    model: 'composer-2.5',
    params: { fast: 'true' },
  }),
})
```

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  A model id `Cursor.models.list()` returns for the key. reeval refuses a missing `model` at plan time with exit code 2.
</Property>

<Property name="params" type="Record<string, string>" optional>
  Parameter ids mapped to string values, such as `{ fast: 'true' }`. An unset parameter takes the default variant in Cursor's model catalog, which reeval sends on the request. `fast` is `'false'` when the model accepts it and `params` leaves it unset.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, mapped onto the catalog parameter this model names, `reasoning_effort` or `effort`. A model with no such parameter refuses `effort`. Fast is `params.fast`.
</Property>

For more information about `id`, `maxConcurrent`, `startTimeout`, and `gateway`, see [Set the harness options](/agents#set-the-harness-options).

`params` belongs to `cursor()` alone. With no `harness` option, reeval uses `cursor()` with its default model.

For more information about choosing a harness, see [Choose an agent](/agents).

For more information about model ids, effort values, and served models, see [Set the agent's model](/agents/model).

## `rules`

The Cursor harness reads rules from the `AGENTS.md` file in the workspace.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The Cursor harness reads skills from the `.cursor/skills` directory in the workspace and from the `~/.agents/skills` directory in the home directory.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `plugins`

reeval adds each plugin's skills to the home skills directory and unpacks the rest into the workspace: rules to `.cursor/rules`, subagents to `.cursor/agents`, commands to `.cursor/commands`, and hooks into `.cursor/hooks.json`. Cursor never loads the plugins of the account that owns the key.

- Takes every plugin part: `skills`, `agents`, `commands`, `hooks`, `mcp` and `rules`.
- Runs only command hooks, on `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `SubagentStop`, `PreCompact` and `Stop`; a plugin with any other hook is refused.

## `mcp`

The Cursor harness accepts MCP servers on `stdio`, `http`, and `sse`. reeval passes each server in the Cursor SDK's `McpServerConfig` shape: a `stdio` server is `{ type: 'stdio', command, args, env }`, and an `http` or `sse` server is `{ type, url, headers }`.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The Cursor harness records tokens on each turn's `usage`. `input` excludes cache reads and writes, so the prompt total is `input` plus `cacheRead` plus `cacheWrite`. `reasoning` is part of `output`. `usage` is null when the harness reports no tokens.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

Each turn's `model` is the served model with its parameters, in the form `model[param=value]`. The attempt's `servedModels` is null, because the API requests name no model.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The Cursor harness records `web-search` events. The Cursor SDK's stream leaves web search calls out, and reeval recovers those calls from the stored conversation. A turn reeval cannot recover lists `web-search` on `unreported`, and `toHaveSearched()` refuses that turn.

For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The Cursor harness records `web-fetch` events. The Cursor SDK's stream leaves web fetch calls out, and reeval recovers those calls from the stored conversation. A turn reeval cannot recover lists `web-fetch` on `unreported`, and `toHaveFetched()` refuses that turn.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
