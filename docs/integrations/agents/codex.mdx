`codex()` runs OpenAI's Codex CLI in the sandbox as one `codex exec --json` process for each turn, and a later turn resumes the same thread. The turn bypasses approval prompts. For more information about the sandbox, see [Choose a sandbox](/integrations/sandboxes).

## `OPENAI_API_KEY`

`codex()` reads `OPENAI_API_KEY` from the environment or the `.env.local` file. A run exits with code 2 when the variable is unset, or when the value contains whitespace or a line break.

reeval brokers that key on `POST https://api.openai.com/v1/responses` only, over HTTP. A restricted egress policy allows `api.openai.com`.

When the API rejects the key, the attempt error begins with `The API rejected OPENAI_API_KEY: set a valid key in the environment or .env.local`.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about the variable, see [`OPENAI_API_KEY`](/reference/env-vars#openaiapikey).

## `codex()`

`codex()` is exported from `{{ pkg }}/harness`. The `reeval.config.ts` file passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { codex } from '{{ pkg }}/harness'

export default defineConfig({
  harness: codex({
    model: 'gpt-5.6-luna',
    effort: 'medium',
  }),
})
```

The prompt is a shell argument under 128 KiB.

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  An OpenAI model id with no provider prefix, passed as `--model`. A missing id, or a provider prefix, fails at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, written as `model_reasoning_effort` in the `~/.codex/config.toml` file. Values include `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`.
</Property>

For more information about `id`, `maxConcurrent`, `startTimeout`, and `gateway`, see [Set the harness options](/agents#set-the-harness-options).

In the sandbox, Codex's `config.toml` file turns analytics off.

For more information about choosing a harness, see [Choose an agent](/agents).

For more information about model ids and effort values, see [Set the agent's model](/agents/model).

## `rules`

The Codex harness reads rules from the `AGENTS.md` file in the workspace. Codex reads the `~/.codex/AGENTS.md` file before the workspace file.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The Codex harness reads skills from the `.agents/skills` directory in the workspace, from the working directory up to the repo root, and from the `~/.agents/skills` directory in the home directory.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `plugins`

reeval lists the plugins in a marketplace named `reeval` in Codex's home directory and installs each with `codex plugin add` as the session starts, so Codex caches a copy and loads its skills and MCP servers. In the sandbox, Codex's `config.toml` file turns the plugin sync off unless the environment has plugins, so a turn without plugins contacts only `api.openai.com`.

[//]: # (generated:harness-plugins:codex)

- Takes `skills` and `mcp`, and refuses a plugin that keeps `agents`, `commands`, `hooks` and `rules`: narrow it with `only`, or leave it out of the cell.
- Reads `plugin.json` and `.codex-plugin/plugin.json` (a root `plugin.json` only when it names an Agent Plugins `$schema`) in place of `.claude-plugin/plugin.json`, so a plugin that has one is refused.
- Refuses a plugin that bundles apps: they need a ChatGPT login.
- Names a plugin's MCP servers by their own keys, in one list with `mcp`, and keeps one of two servers of a name, so a clash is refused.
- With plugins it tries `github.com`, `api.github.com` and `chatgpt.com` (Codex's plugin sync, which it runs on every turn once plugins are on); a restricted egress policy refuses them and records them under `egress.expectedBlocked`.

## `mcp`

The Codex harness accepts MCP servers on `stdio` and `http`. An `sse` server fails at plan time with exit code 2. reeval writes a `stdio` server as `command`, `args`, and `env`, and an `http` server as `url` and `http_headers`, under `[mcp_servers]` in the `~/.codex/config.toml` file. A call is named `mcp__<server>__<tool>`.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The Codex harness records one `usage` for the turn. `input` is uncached input, and `cacheRead` and `cacheWrite` hold cached input. `reasoning` is part of `output`. `usage` is null when Codex reports no tokens.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

The egress gateway reads the served model and effort from the response body. The turn's `model` and the attempt's `servedModels` hold `<model>` or `<model>[effort=<value>]`. `servedEffort` is the reasoning effort in that label. `effort` is the factory value, or null when unset.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The Codex harness records `web-search` events. A search stores its text on `query`. The turn's `unreported` list stays empty, so `toHaveSearched()` reads those events. Searches run on OpenAI's side, and the transcript keeps each event under a restricted egress policy.

For more information about a restricted egress policy, see [Block non-automatic hosts](/environments/egress#block-non-automatic-hosts). For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The Codex harness records `web-fetch` events. An `open_page` or `find_in_page` action with a URL is `web-fetch`. The turn's `unreported` list stays empty, so `toHaveFetched()` reads those events. Page opens run on OpenAI's side, and the transcript keeps each event under a restricted egress policy.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
