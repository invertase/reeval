## `codex()`

`codex()` is one harness factory. It runs OpenAI's Codex CLI as one `codex exec --json` process for each turn, and a later turn resumes the same thread. The turn bypasses approval prompts.

`codex()` runs in the sandbox. For more information about supported sandboxes, see [Choose a sandbox](/integrations/sandboxes).

`codex()` is exported from `{{ pkg }}/harness`. The `reeval.config.ts` file passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { codex } from '{{ pkg }}/harness'

export default defineConfig({
  harness: codex({
    model: 'gpt-5.6-luna',
    effort: 'medium',
  }),
})
```

The prompt is a shell argument under 128 KiB.

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  An OpenAI model id with no provider prefix, passed as `--model`. A missing id, or a provider prefix, fails at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, written as `model_reasoning_effort` in the `~/.codex/config.toml` file. Values include `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`.
</Property>

<Property name="id" type="string" optional>
  Cell id. Defaults to `codex:<model>`, or `codex:<model>[effort=<value>]` when `effort` is set. The id uses letters, digits, and `._:@+-=[]`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most Codex attempts at the same time, across the run.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long the session may take to become ready before the attempt is an infra error, after one retry. Defaults to `90s`. A duration, such as `3m`.
</Property>

For more information about choosing a harness, see [Choose an agent](/agents).

For more information about model ids and effort values, see [Set the agent's model](/agents/model).

## `OPENAI_API_KEY`

`codex()` reads `OPENAI_API_KEY` from the host. reeval brokers that key on `POST https://api.openai.com/v1/responses` only, over HTTP.

A missing key, or a key with whitespace or a line break, stops the run with exit code 2 and names `OPENAI_API_KEY`. A rejected key names `OPENAI_API_KEY` on the turn error.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about the variable, see [`OPENAI_API_KEY`](/reference/env-vars#openaiapikey).

## `rules`

The Codex harness reads rules from the `AGENTS.md` file in the workspace. Codex reads the `~/.codex/AGENTS.md` file before the workspace file.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The Codex harness reads skills from the `.agents/skills` directory in the workspace, from the working directory up to the repo root, and from the `~/.agents/skills` directory in the home directory.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `mcp`

The Codex harness accepts MCP servers on `stdio` and `http`. An `sse` server fails at plan time with exit code 2. reeval writes a `stdio` server as `command`, `args`, and `env`, and an `http` server as `url` and `http_headers`, under `[mcp_servers]` in the `~/.codex/config.toml` file. A call is named `mcp__<server>__<tool>`.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The Codex harness records one `usage` for the turn. `input` is uncached input, and `cacheRead` and `cacheWrite` hold cached input. `reasoning` is part of `output`. `usage` is null when Codex reports no tokens.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

The egress gateway reads the served model and effort from the response body. The turn's `model` and the attempt's `servedModels` hold `<model>` or `<model>[effort=<value>]`. `servedEffort` is the effort in that label. `effort` is the factory value, or null when unset.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The Codex harness records `web-search` events. A search stores its text on `query`. Searches run on OpenAI's side, and the transcript keeps each event under a restricted egress policy.

For more information about a restricted egress policy, see [Block non-automatic hosts](/environments/egress#block-non-automatic-hosts). For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The Codex harness records `web-fetch` events. An `open_page` or `find_in_page` action with a URL is `web-fetch`. Page opens run on OpenAI's side, and the transcript keeps each event under a restricted egress policy.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
