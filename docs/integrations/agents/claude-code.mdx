`claudeCode()` runs Claude Code in the sandbox. For more information about the sandbox, see [Choose a sandbox](/integrations/sandboxes).

## `ANTHROPIC_API_KEY`

`claudeCode()` reads `ANTHROPIC_API_KEY` from the environment or the `.env.local` file. A run exits with code 2 when the variable is unset, or when the value contains whitespace or a line break.

The gateway swaps the key in only on these requests to `api.anthropic.com`:

- `POST /v1/messages`
- `POST /v1/messages/count_tokens`
- `GET /api/claude_code/settings`
- `GET /api/claude_code/policy_limits`

The gateway answers HTTP 403 when a request carries the key and is not one of those endpoints. A restricted egress policy allows `api.anthropic.com` and `*.anthropic.com`.

When the API rejects the key, the attempt error begins with `The API rejected ANTHROPIC_API_KEY: set a valid key in the environment or .env.local`.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about the variable, see [`ANTHROPIC_API_KEY`](/reference/env-vars#anthropicapikey).

## `claudeCode()`

`claudeCode()` is exported from `{{ pkg }}/harness`. The `reeval.config.ts` file passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { claudeCode } from '{{ pkg }}/harness'

export default defineConfig({
  harness: claudeCode({
    model: 'claude-sonnet-5',
    effort: 'high',
  }),
})
```

`model` is required. reeval exits with code 2 for a missing `model`, an `effort` outside the allowed values, or an unknown option.

<Property name="model" type="string" required>
  A model id or alias the `claude` CLI accepts.
</Property>

<Property name="effort" type="'low' | 'medium' | 'high' | 'xhigh' | 'max'" optional>
  Reasoning effort for the Agent SDK `/effort` control. The Claude Code UI labels `xhigh` as **Extra**.
</Property>

For more information about `id`, `maxConcurrent`, `startTimeout`, and `gateway`, see [Set the harness options](/agents#set-the-harness-options).

reeval turns `askUserQuestions` off, so Claude Code asks in its reply. reeval sets `IS_SANDBOX` to `1`, so Claude Code skips permission prompts as root. The adapter also sets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` to `1`, so a turn sends no telemetry, error reports, or feature-flag requests.

For more information about choosing a harness, see [Choose an agent](/agents).

For more information about model ids, effort values, and served models, see [Set the agent's model](/agents/model).

## `rules`

The Claude Code harness reads rules from the `CLAUDE.md` file in the workspace.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The Claude Code harness reads skills from the `.claude/skills` directory in the workspace and from the `~/.claude/skills` directory in the home directory.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `plugins`

reeval copies the plugins into a generated marketplace named `reeval` and enables each as `<plugin>@reeval` in `~/.claude/settings.json`, merging into a settings file the environment wrote there. Claude Code installs and loads them as it starts, and loads each plugin's MCP servers itself.

## `mcp`

The Claude Code harness accepts MCP servers on `stdio`, `http`, and `sse`. reeval passes each server in the shape of the `.mcp.json` file: a `stdio` server is `{ type: 'stdio', command, args, env }`, and an `http` or `sse` server is `{ type, url, headers }`.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The Claude Code harness records tokens on each turn's `usage`. `usage` is null when the harness reports no tokens.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

Each turn's `model` is the model id Claude Code reports. The attempt's `servedModels` is null, because the API requests name no model.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The Claude Code harness records `web-search` events. A `webSearch` call records `query` and `references`. `ok` is false when the call fails. The turn's `unreported` list stays empty, so `toHaveSearched()` reads those events.

For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The Claude Code harness records `web-fetch` events. A `webFetch` or `WebFetch` call records `url`. `ok` is false when the call fails. The turn's `unreported` list stays empty, so `toHaveFetched()` reads those events.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
