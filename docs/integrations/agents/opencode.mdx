`opencode()` runs OpenCode in the sandbox on the provider the model id names, with that provider's key. For more information about the sandbox, see [Choose a sandbox](/integrations/sandboxes).

## `provider/model`

The harness runs on any provider whose key OpenCode sends in a header on known hosts. The table lists each provider's model id prefix, key variable, header, and hosts.

`opencode()` reads the provider's key from the environment or the `.env.local` file, under the variable in the `Key` column. reeval swaps it into the `Header` on each request to the `Hosts`, and refuses it anywhere else. A host with a `{NAME}` placeholder takes that variable from the host too, or the provider's default. A run exits with code 2 when the `Key` variable is unset, or when its value contains whitespace or a line break. A restricted egress policy allows the provider's `Hosts` and `mcp.exa.ai`.

When the API rejects the key, the attempt error begins with `The API rejected <Key>: set a valid key in the environment or .env.local`, with the provider's `Key` variable.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about every provider variable, see [Environment variables](/reference/env-vars).

## `opencode()`

`opencode()` is exported from `{{ pkg }}/harness`. The following configuration passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { opencode } from '{{ pkg }}/harness'

export default defineConfig({
  harness: opencode({
    model: 'google/gemini-3.8-flash',
  }),
})
```

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  OpenCode's model id, `<provider>/<model>`. The part before the first `/` picks the provider and its key. reeval refuses a bare id, an unknown provider, or a provider whose key it cannot broker at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, as a value the provider takes. reeval sets it as `options.thinking` on an `anthropic/` model and as `options.reasoningEffort` on every other provider.
</Property>

For more information about `id`, `maxConcurrent`, `startTimeout`, and `gateway`, see [Set the harness options](/agents#set-the-harness-options). The cell id is `opencode:` followed by the part of `model` after its last `/`.

In the sandbox, OpenCode runs with its `question` and browser tools off, self-update, share links, and the model-catalog fetch off, session titles on the run's model, and its model calls over HTTP. That configuration overrides the workspace's own `opencode.json` file where both set a key.

For more information about model ids and effort values, see [Set the agent's model](/agents/model). For rules, skills, MCP servers, usage, served models, and web events, see [Harness behavior](/reference/options#harness-behavior).

## `plugins`

reeval adds each plugin's skills to the home skills directory and unpacks subagents and commands into `.opencode/agents` and `.opencode/commands`. OpenCode skips a file whose frontmatter it refuses, so reeval keeps only `description`, and `mode: subagent` for a subagent. OpenCode's own plugins are code modules, and reeval never loads them from an environment's plugin.
