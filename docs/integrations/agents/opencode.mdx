## `opencode()`

`opencode()` is one harness factory. It runs OpenCode in the sandbox on the provider the model id names, with that provider's key.

`opencode()` is exported from `{{ pkg }}/harness`. The following configuration passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { opencode } from '{{ pkg }}/harness'

export default defineConfig({
  harness: opencode({
    model: 'google/gemini-3.8-flash',
  }),
})
```

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  OpenCode's model id, `<provider>/<model>`. The part before the first `/` picks the provider and its key. reeval refuses a bare id, an unknown provider, or a provider whose key it cannot broker at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, as a value the provider takes. reeval sets it as `options.thinking` on an `anthropic/` model and as `options.reasoningEffort` on every other provider.
</Property>

<Property name="id" type="string" optional>
  Cell id. Defaults to `opencode:` followed by the part of `model` after its last `/`, in the form `opencode:<model>`, or `opencode:<model>[effort=high]` with `effort` set to `high`. The id uses letters, digits, and `._:@+-=[]`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most OpenCode attempts that run at the same time, across the run. A whole number of at least 1.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long the session may take to become ready before the attempt is an infra error, after one retry. A duration, such as `3m`. Defaults to `90s`.
</Property>

In the sandbox, OpenCode runs with its `question` and browser tools off, self-update and share links off, and its model calls over HTTP. That configuration overrides the workspace's own `opencode.json` file where both set a key.

For more information about choosing a harness, see [Choose an agent](/agents).

For more information about model ids and effort values, see [Models and providers for each harness](/agents/model).

## `provider/model`

The harness runs on any provider whose key OpenCode sends in a header on known hosts. The table lists each provider's model id prefix, key variable, header, and hosts.

`opencode()` reads the provider's key from the host, under the variable in the `Key` column. reeval swaps it into the `Header` on each request to the `Hosts`, and refuses it anywhere else. A host with a `{NAME}` placeholder takes that variable from the host too, or the provider's default.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about every provider variable, see [Environment variables](/reference/env-vars).

## `rules`

The OpenCode harness reads rules from the `AGENTS.md` file in the workspace.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The OpenCode harness reads skills from the `.opencode/skills` directory in the workspace and from the `~/.config/opencode/skills` directory in the home directory, and also from the `.agents/skills` and `.claude/skills` directories in both places.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `mcp`

The OpenCode harness accepts MCP servers on `stdio` and `http`. reeval refuses an `sse` server at plan time with exit code 2. The servers go in OpenCode's configuration with Code Mode off, so the agent calls their tools directly, and the first prompt waits until every server has connected.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The OpenCode harness records tokens on each turn's `usage`, as one total for the whole turn. `usage` is null when OpenCode reports none.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

OpenCode's stream names no model, so each turn's `model` is the model on the turn's last brokered request. The attempt's `servedModels` comes from the request URL on a `google/` model and from the response body on every other provider, with `[effort=<value>]` when the response names an effort.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The OpenCode harness records `web-search` events. A web search runs on a hosted MCP server at `mcp.exa.ai`, which needs no key and is one of the harness's automatic egress hosts.

For more information about the automatic hosts, see [Block non-automatic hosts](/environments/egress#block-non-automatic-hosts). For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The OpenCode harness records `web-fetch` events.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
