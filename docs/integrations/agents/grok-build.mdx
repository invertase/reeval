## `grokBuild()`

`grokBuild()` is one harness factory. It runs Grok Build in the sandbox on an xAI API key. The factory comes from `{{ pkg }}/harness`, and its return value sets the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { grokBuild } from '{{ pkg }}/harness'

export default defineConfig({
  harness: grokBuild({
    model: 'grok-4.6',
  }),
})
```

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  An xAI model id, with no provider prefix, using letters, digits, and `._-`. reeval refuses a missing or other id at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, for a model that takes one, such as `low`, `medium`, or `high`. reeval sets it as `default_reasoning_effort` in Grok Build's `config.toml` file.
</Property>

<Property name="id" type="string" optional>
  Cell id. Defaults to `grok-build:<model>`, or `grok-build:<model>[effort=<value>]` when `effort` is set. The id uses letters, digits, and `._:@+-=[]`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most Grok Build attempts that run at the same time, across the run. A whole number of at least 1.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long the session may take to become ready before the attempt is an infra error, after one retry. A duration, such as `3m`. Defaults to `90s`.
</Property>

In the sandbox, Grok Build runs with a private home, whose `config.toml` file puts the session and its title on the run's model and turns off telemetry, self-update, and the summary, recap, and title-refresh calls, so a turn contacts only `api.x.ai`.

For more information about choosing a harness, see [Choose an agent](/agents).

For more information about model ids and effort values, see [Models and providers for each harness](/agents/model).

## `XAI_API_KEY`

`grokBuild()` reads `XAI_API_KEY` from the host. reeval swaps it into the `Authorization: Bearer` header on Grok Build's requests to `api.x.ai`, `GET /v1/models`, `GET /v1/api-key`, `POST /v1/chat/completions`, and `POST /v1/responses`, and refuses it anywhere else.

When xAI refuses the key, Grok Build drops its `xai.api_key` sign-in, and reeval reports that the API rejected `XAI_API_KEY`.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about the variable, see [`XAI_API_KEY`](/reference/env-vars#xaiapikey).

## `rules`

The Grok Build harness reads rules from the `AGENTS.md` file in the workspace. reeval marks the workspace trusted, since Grok Build ignores an untrusted folder's rules and skills.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The Grok Build harness reads skills from the workspace's `.grok/skills` directory, the private home's `.grok/skills` directory under the `~/.ai-sdk-harness/.harness-bootstrap/grok-build/implementation/home` path, and the `.agents/skills` and `.claude/skills` directories.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `mcp`

The Grok Build harness accepts MCP servers on `stdio`, `http`, and `sse`. reeval passes them on the ACP `session/new` call: a `stdio` server as `command`, `args`, and `env`, and an `http` or `sse` server as `type`, `url`, and `headers`.

Grok Build calls a server's tool through its `use_tool` tool, which the transcript names `mcp__<server>__<tool>`, so [`toHaveCalledMcp()`](/reference/matchers#tohavecalledmcp) matches it.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The Grok Build harness records tokens on each turn's `usage`, summed over the turn's model calls. `input` excludes cache reads, so the prompt total is `input` plus `cacheRead`. `cacheWrite` records cache creation tokens, and `reasoning` is part of `output`. `usage` is null when Grok Build reports none.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

Grok Build's stream names no model, so each turn's `model` and the attempt's `servedModels` come from the model xAI's responses name.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The Grok Build harness records `web-search` events. A search runs through Grok Build's `web_search` tool on xAI's Responses API at `api.x.ai`, one of the harness's automatic egress hosts.

For more information about the automatic hosts, see [Block non-automatic hosts](/environments/egress#block-non-automatic-hosts). For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The Grok Build harness records no `web-fetch` events.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
