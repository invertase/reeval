---
title: "Run in a macOS VM with Tart"
description: "Run each attempt in its own macOS VM on an Apple Silicon Mac."
---

`tart()` returns a sandbox that runs each attempt in a fresh macOS VM, cloned from an image with [Tart](https://tart.run) and deleted when the attempt ends.

<Warning>
`tart()` runs `cursor()`, `pi()` and `codex()` so far: reeval refuses the other real harnesses at plan time with exit code 2.
</Warning>

## Requirements

- **A Mac with Apple Silicon.** On any other machine, reeval exits with code 2 before the run.
- **Tart on `PATH`.** Install it with `brew install cirruslabs/cli/tart`.
- **Node and passwordless `sudo` in the image.** The harness runs on Node, and so does the egress gateway's forwarder, as root. Cirrus Labs' `macos-sequoia-base` has both; for another image, `brew install node`. Without `sudo`, an attempt runs unrecorded, or fails if it brokers a key. `cursor()` needs Node 22.21 or later.

## `tart()`

Set `sandbox` to `tart()`, from `{{ pkg }}/sandbox`:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { tart } from '{{ pkg }}/sandbox'

export default defineConfig({
  sandbox: tart({ image: 'ghcr.io/cirruslabs/macos-sequoia-base:latest' }),
  egress: 'allow-all',
})
```

Each attempt clones `image`, boots the clone headless, and runs the harness, the setup commands, and the assertions over `tart exec`, as the image's user, in `~/workspace`. Without the Tart Guest Agent, `ssh: { key }` uses SSH instead. For each option, see [the `tart()` options](/reference/options#tart).

## Real agents

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'

export default defineConfig({})
```

```ts title="evals/mac.eval.ts"
import { defineEnvironment, evaluate, expect } from '{{ pkg }}'
import { cursor } from '{{ pkg }}/harness'
import { tart } from '{{ pkg }}/sandbox'

const mac = defineEnvironment('mac', {
  sandbox: tart({ image: 'ghcr.io/cirruslabs/macos-sequoia-base:latest' }),
  egress: 'allow-all',
})

evaluate('swift-version', {
  harnesses: cursor({ model: 'composer-2.5' }),
  environments: mac,
}, async (c) => {
  await c.send('Write the output of sw_vers -productVersion to version.txt')
  expect(await c.readFile('version.txt')).toMatch(/^\d+\./)
})
```

Each attempt clones a copy of the image with the harness's CLI and pnpm baked in (see [Images](#images)), so it installs nothing. Its `PATH` starts with reeval's pnpm, as in Docker. Other clients get the system's CA bundle plus the gateway's CA in `SSL_CERT_FILE`, `CURL_CA_BUNDLE`, `GIT_SSL_CAINFO` and `REQUESTS_CA_BUNDLE`.

## Images

`reeval run` never pulls an image: a macOS image is about 25 GB. Pull them first with `reeval image build`:

```text
$ npx reeval image build
warning: tart(ghcr.io/cirruslabs/macos-sequoia-base:latest) uses the moving tag "latest": …
tart pull ghcr.io/cirruslabs/macos-sequoia-base:latest
…
✓ tart:macos-sequoia-base:latest: ghcr.io/cirruslabs/macos-sequoia-base:latest eee659985b01
1 image ready
```

For a real harness, the build then bakes its CLI and pnpm into a copy that attempts clone:

```text
Baking pi onto ghcr.io/cirruslabs/macos-sequoia-base:latest as reeval-sandbox-pi-0.2.9-macos-sequoia-base-latest-6db8ddc6
Installing pnpm 10.33.3
Installing pi
pi 1.4.0
✓ tart:macos-sequoia-base:latest · pi-0.2.9: reeval-sandbox-pi-0.2.9-macos-sequoia-base-latest-6db8ddc6 f570f6db9e21
1 image ready
```

A new adapter, bootstrap or base disk bakes a new copy, and `reeval run` bakes a missing one. `--force` bakes anew, and `reeval clean --images` deletes every baked copy.

| When | What happens |
| :--- | :--- |
| `reeval run`, and `tart list` doesn't show an image | Exit code 2, naming the image, its size, and `tart pull <image>` |
| `reeval image build`, and the pulls fit once Tart prunes its cache | A warning |
| `reeval image build`, and they don't fit even then | Exit code 3 before any pull |
| `reeval image build --dry-run` | Each image's state, and whether the pulls fit |
| A plan with no `docker()` sandbox | `reeval image build` runs no Docker |

The disk check skips, and names, an image its registry won't size. Make a local VM with `tart clone` or `tart create`.

<Warning>
`:latest` or no tag warns: the tag can move between runs. Cirrus Labs' base images publish only `latest`, so pin one by digest, `…/macos-sequoia-base@sha256:…`. Each attempt records the digest it cloned in [`vmImage`](/reference/run-record).
</Warning>

## Egress

| Policy | Under `tart()` |
| :--- | :--- |
| `allow-all` | Runs. The VM keeps Tart's network; what ignores the proxy goes out directly, unrecorded |
| `proxy`, the default | Refused with exit code 2: the gateway isn't the VM's only way out |
| `deny-all`, `{ allow }` | Refused with exit code 2: `tart()` enforces no policy yet |

Brokered secrets and harness keys still stay on the host: the agent sees placeholders.

## Concurrency

macOS runs at most two VMs at a time, so reeval runs at most two `tart()` attempts at once. VMs you run outside reeval take the same slots: an attempt that finds none free fails as an infrastructure error. To run fewer, set `maxConcurrent`:

```ts title="reeval.config.ts"
  sandbox: tart({ image: 'ghcr.io/cirruslabs/macos-sequoia-base:latest', maxConcurrent: 1 }),
```

reeval refuses more than `2`.

See also [Choose a sandbox](/configuration/sandboxes) and [Restrict sandbox egress](/configuration/environments/egress).
