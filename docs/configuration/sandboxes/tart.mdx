---
title: "Run in a macOS VM with Tart"
description: "Run each attempt in its own macOS VM on an Apple Silicon Mac."
---

`tart()` returns a sandbox that runs each attempt in a fresh macOS VM, cloned from an image with [Tart](https://tart.run) and deleted when the attempt ends.

<Warning>
Of the real harnesses, only `cursor()` runs in `tart()` so far: reeval refuses the others at plan time with exit code 2.
</Warning>

## Requirements

- **A Mac with Apple Silicon.** On any other machine, reeval exits with code 2 before the run.
- **Tart on `PATH`.** Install it with `brew install cirruslabs/cli/tart`.
- **Node in the image and passwordless `sudo` for its user,** for the egress gateway's forwarder, which runs as root. Cirrus Labs' `macos-sequoia-base` has both, with Node 24. For another image, add Node with `brew install node`. Without them, an attempt runs unrecorded, or fails if it brokers a key. `cursor()` needs Node 22.21 or later.

## `tart()`

`{{ pkg }}/sandbox` exports the function. The `sandbox` option accepts its return value:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { tart } from '{{ pkg }}/sandbox'

export default defineConfig({
  sandbox: tart({ image: 'ghcr.io/cirruslabs/macos-sequoia-base:latest' }),
  egress: 'allow-all',
})
```

Each attempt clones `image`, boots the clone headless, and runs the harness, the setup commands, and the assertions over `tart exec`, as the image's user, in `~/workspace`. When the Tart Guest Agent doesn't answer and `ssh: { key }` is set, it uses SSH instead. The clone is deleted when the attempt ends, and a canceled run's clones when the run does. For each option, see [the `tart()` options](/reference/options#tart).

## Real agents

```ts title="evals/mac.eval.ts"
import { defineEnvironment, evaluate, expect } from '{{ pkg }}'
import { cursor } from '{{ pkg }}/harness'
import { tart } from '{{ pkg }}/sandbox'

const mac = defineEnvironment('mac', {
  sandbox: tart({ image: 'ghcr.io/cirruslabs/macos-sequoia-base:latest' }),
  egress: 'allow-all',
})

evaluate('swift-version', {
  harnesses: cursor({ model: 'composer-2.5' }),
  environments: mac,
}, async (c) => {
  await c.send('Write the output of sw_vers -productVersion to version.txt')
  expect(await c.readFile('version.txt')).toMatch(/^\d+\./)
})
```

Each attempt installs the Cursor SDK with npm as it starts. Clients other than Node get the system's CA bundle plus the gateway's CA in `SSL_CERT_FILE`, `CURL_CA_BUNDLE`, `GIT_SSL_CAINFO` and `REQUESTS_CA_BUNDLE`. reeval also tries the System keychain, and logs a failure.

## Images

`reeval run` never pulls an image: a macOS image is about 25 GB. Pull them first with `reeval image build`, which prints Tart's progress:

```text
$ npx reeval image build
warning: tart(ghcr.io/cirruslabs/macos-sequoia-base:latest) uses the moving tag "latest": …
tart pull ghcr.io/cirruslabs/macos-sequoia-base:latest
…
✓ tart:macos-sequoia-base:latest: ghcr.io/cirruslabs/macos-sequoia-base:latest eee659985b01
1 image ready
```

| When | What happens |
| :--- | :--- |
| `reeval run`, and `tart list` doesn't show an image | Exit code 2, naming the image, its size, and `tart pull <image>` |
| `reeval image build`, and the pulls fit once Tart prunes its cache | A warning |
| `reeval image build`, and they don't fit even then | Exit code 3 before any pull |
| `reeval image build --dry-run` | Each image ready or to pull, and whether the pulls fit |
| A plan with no `docker()` sandbox | `reeval image build` runs no Docker |

The disk check skips, and names, an image its registry won't size. Make a local VM with `tart clone` or `tart create`.

<Warning>
`:latest` or no tag warns: the tag can move between runs. Cirrus Labs' base images publish only `latest`, so pin one by digest, `…/macos-sequoia-base@sha256:…`. Each attempt records the digest it cloned in [`vmImage`](/reference/run-record).
</Warning>

## Egress

| Policy | Under `tart()` |
| :--- | :--- |
| `allow-all` | Runs. The VM keeps Tart's network; what ignores the proxy goes out directly, unrecorded |
| `proxy`, the default | Refused with exit code 2: the gateway isn't the VM's only way out |
| `deny-all`, `{ allow }` | Refused with exit code 2: `tart()` enforces no policy yet |

Under `allow-all` too, brokered secrets and harness keys stay on the host: the agent sees placeholders.

## Concurrency

macOS runs at most two macOS VMs at a time, so reeval runs at most two `tart()` attempts at once, whatever `concurrency` says. VMs you run outside reeval take the same slots: an attempt that finds none free fails as an infrastructure error, naming them. To run fewer, set `maxConcurrent`:

```ts title="reeval.config.ts"
  sandbox: tart({ image: 'ghcr.io/cirruslabs/macos-sequoia-base:latest', maxConcurrent: 1 }),
```

`maxConcurrent: 1` runs one at a time; reeval refuses more than `2`.

See also [Choose a sandbox](/configuration/sandboxes) and [Restrict sandbox egress](/configuration/environments/egress).
