## `antigravity()`

`antigravity()` is the Antigravity harness factory. For more information about supported sandboxes, see [Sandboxes](/sandboxes).

`antigravity()` is exported from `{{ pkg }}/harness`. The following configuration passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { antigravity } from '{{ pkg }}/harness'

export default defineConfig({
  harness: antigravity({
    model: 'gemini-3.8-flash-medium',
    effort: 'high',
  }),
})
```

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  A model slug `agy models` lists for the key, such as `<model>-medium`. A `-low`, `-medium`, or `-high` suffix sets effort in the slug. reeval refuses a missing `model` at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort passed as `agy --effort`, such as `low`, `medium`, `high`, or `max`. The cell's `effort` field copies this option.
</Property>

<Property name="id" type="string" optional>
  Cell id. Defaults to `antigravity` followed by the model, such as `antigravity:<model>`. With `effort` set to `high`, the id is `antigravity:<model>[effort=high]`. The id uses letters, digits, and `._:@+-=[]`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most Antigravity attempts that run at the same time, across the run. A whole number of at least 1.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long the session may take to become ready before the attempt is an infra error, after one retry. A duration, such as `3m`. Defaults to `90s`.
</Property>

For more information about choosing a harness, see [Choose a harness](/harnesses).

For more information about model ids, effort values, and served models, see [Models and providers for each harness](/harnesses/models).

## `GEMINI_API_KEY`

`antigravity()` reads `GEMINI_API_KEY` from the host. A missing key stops the harness before the session starts. The gateway brokers the key in the `x-goog-api-key` header on `POST /v1beta/models/<model>:streamGenerateContent` at `generativelanguage.googleapis.com`.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about the variable, see [`GEMINI_API_KEY`](/reference/env-vars#geminiapikey).

Antigravity opens `play.googleapis.com` and `antigravity-unleash.goog` in every session. The requests are telemetry and feature flags, and no setting stops them. A restricted egress policy refuses those hosts and records them on `egress.expectedBlocked`.

For more information about blocked requests, see [Read blocked requests](/environments/egress#read-blocked-requests).

## `rules`

The Antigravity harness reads rules from the `AGENTS.md` file in the workspace.

For more information about writing rules, see [Add project rules](/environments/rules).

## `skills`

The Antigravity harness reads skills from the `.agents/skills` directory in the workspace and from the `~/.gemini/config/skills` directory in the home directory.

For more information about placing skills, see [Give the agent skills](/environments/skills).

## `mcp`

The Antigravity harness reads MCP servers from the `~/.gemini/config/mcp_config.json` file. The Antigravity harness accepts `stdio`, `http`, and `sse`. reeval writes a `stdio` server as `command`, `args`, and `env`, and an `http` or `sse` server as `serverUrl` and `headers`.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## `usage`

The Antigravity harness records tokens on each turn's `usage`. `input` excludes cache reads, `cacheRead` holds those reads, and `cacheWrite` is 0. `output` includes thinking tokens, and `reasoning` holds that count. `usage` is null when the harness reports no tokens.

For more information about the token fields, see [`TokenUsage`](/reference/record#tokenusage).

## `servedModels`

Each turn's `model` is the model the CLI reports at the start of the turn. Otherwise the turn uses the last brokered request's model.

The attempt's `servedModels` lists the model id in each brokered path `/v1beta/models/<model>:streamGenerateContent`. The path names the model that served the call. The list can include a model the CLI calls for a title or a checkpoint.

For more information about the attempt fields, see [`AttemptRecord`](/reference/record#attemptrecord).

## `web-search`

The Antigravity harness records `web-search` events in the transcript. `unreported` is empty, so `toHaveSearched()` reads those events.

For more information about the matcher, see [`toHaveSearched()`](/reference/matchers#tohavesearched).

## `web-fetch`

The Antigravity harness records `web-fetch` events in the transcript. `unreported` is empty, so `toHaveFetched()` reads those events.

For more information about the matcher, see [`toHaveFetched()`](/reference/matchers#tohavefetched).
