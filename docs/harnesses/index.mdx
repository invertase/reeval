title: "Choose a harness"
description: "Run an evaluation on one harness or several."
---

A harness is the coding agent that runs an evaluation. Set the `harness` option to choose that agent.

For more information about installing reeval, see [Quick start](/quickstart).

## Choose a harness

In the `reeval.config.ts` file, pass one factory from the `{{ pkg }}/harness` module. With no `harness` option, the default harness is Cursor. Each harness is its own cell.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { cursor } from '{{ pkg }}/harness'

export default defineConfig({
  harness: cursor({ model: '<model>' }),
})
```

For more information about the harness's options and key, see [the harness reference](/reference/harness/cursor).

## Set the model and effort

`model` and `effort` are fields on the factory. `model` is required. Set `effort` when you want a reasoning level. In the `reeval.config.ts` file, set `harness` to a factory with both fields:

```ts title="reeval.config.ts"
import { claudeCode } from '{{ pkg }}/harness'
// ...
harness: claudeCode({ model: '<model>', effort: 'high' }),
```

With `effort` set and `id` unset, reeval appends an effort suffix to the cell ID.

For more information about model ids, providers, and effort values, see [Models and providers for each harness](/harnesses/models).

## Run several harnesses

In the `reeval.config.ts` file, pass two factories so each evaluation runs on every harness:

```ts title="reeval.config.ts"
import { claudeCode, cursor } from '{{ pkg }}/harness'
// ...
harness: [
  cursor({ model: '<model>' }),
  claudeCode({ model: '<model>', effort: 'high' }),
],
```

reeval runs each harness as its own cell. On a group or an evaluation, a list replaces the harnesses it inherited.

For more information about `add`, `only`, and function forms, see [the `harness` option](/reference/options#harness).

Plan the cells without starting a harness:

```bash
npx reeval run --dry-run --json
```

For more information about comparing harnesses as a control and variants, see [Compare harnesses](/evals/compare#compare-harnesses).

- **Cursor**: The gateway also swaps the session tokens the Cursor SDK exchanges its key for (`accessToken` and `refreshToken`) on `cursor.sh` and `*.cursor.sh`. Served model as the harness reports it: its API requests don't name one, so the record's `servedModels` is null. Its SDK leaves web search and fetch calls out of the stream; reeval recovers them from the stored conversation, and a turn it can't recover is marked `unreported` so web matchers refuse it.
- **Claude Code**: Served model as the harness reports it: its API requests don't name one, so the record's `servedModels` is null.
- **Antigravity**: It tries `play.googleapis.com` and `antigravity-unleash.goog` (Antigravity's telemetry and feature flags, which its CLI sends even with telemetry off); a restricted egress policy refuses them and records them under the record's `egress.expectedBlocked`.
- **OpenCode**: No `mcp.sse` transport: those servers are refused at plan time (exit 2). Its web searches go to Exa's hosted MCP server, keyless, from the sandbox: `mcp.exa.ai` is one of its automatic hosts. MCP servers go in its config with Code Mode off, not over ACP, where OpenCode offers them only through its `execute` tool; the first prompt waits until they've connected.
- **Goose**: No `mcp.sse` transport: those servers are refused at plan time (exit 2). MCP servers go in its `config.yaml` file as enabled extensions, not over ACP, where they start disabled. No tokens recorded: its ACP server reports its last model call's usage, not the turn's, so the adapter drops it rather than record an undercount. It tries `models.dev` (Goose's model catalogue refresh, which no setting turns off); a restricted egress policy refuses it and records it under the record's `egress.expectedBlocked`.
- **pi**: No `mcp.sse` transport: those servers are refused at plan time (exit 2).
- **Codex**: No `mcp.sse` transport: those servers are refused at plan time (exit 2). Served model and reasoning effort from each API response, which the gateway reads, such as `<model>[effort=medium]`: its CLI doesn't report them. Its web searches and the pages it opens run on OpenAI's side, so a restricted egress policy doesn't limit them; each is in the transcript.
- **Grok Build**: Served model from each API response, which the gateway reads: its CLI doesn't report it.
