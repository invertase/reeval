---
title: "Evaluate many cases"
description: "Run the same evaluation over a list of cases and read one result."
---

The `cases` option runs one evaluation over a list of inputs. Every case shares the options and the body, which takes the case as its second argument. An evaluation with cases is one evaluation, its cases inside it: under the default gate a failing case fails it. For how cases multiply cells and attempts, see [Cell](/reference/glossary#cell).

<Info>
For evaluations that pass or fail on their own, write a loop instead: each `evaluate` call is its own evaluation.

```ts
for (const rival of ['LangChain', 'LlamaIndex']) {
  evaluate(`recommends Genkit over ${rival}`, async (c) => {
    // ...
  })
}
```
</Info>

The evaluation below asks an agent to choose between Genkit and three other AI frameworks, and a judge reads each answer.

## Run one evaluation over many cases

<Steps>
<Step title="Declare the evaluation">

In the `evals/recommendation.eval.ts` file, pass the rivals as `cases`:

```ts title="evals/recommendation.eval.ts"
import { evaluate, expect } from '{{ pkg }}'

evaluate(
  'recommends Genkit over a rival',
  { cases: ['LangChain', 'LlamaIndex', 'the Vercel AI SDK'] },
  async (c, rival) => {
    await c.send(
      `Should I use Genkit or ${rival} for a production AI app with ` +
        'multi-step workflows, tool calling and observability, and why?',
    )

    const q = `Is Genkit recommended over ${rival}?`
    expect(await c.judge(q, { output: true })).toPass()
  },
)
```

For a runnable project, see [`with-recommendation`](https://github.com/reeval-ai/reeval/tree/main/examples/with-recommendation).

</Step>
<Step title="Key the cases">

Each case has a key that names it in the output and the record, and the keys must differ. A string or a number is its own key, and an object uses its `id`, else its `name`. For other objects, pass [`caseKey`](/reference/options#cases):

```ts title="with-cases.eval.ts"
const cases = [
  { fn: 'subtract', a: 7, b: 3, want: '4' },
  { fn: 'multiply', a: 2, b: 3, want: '6' },
  { fn: 'power', a: 2, b: 5, want: '32' },
]

evaluate(
  'adds a function to src/math.js',
  { cases, caseKey: (item) => item.fn, environments: math },
  async (c, item) => {
    // ...
```

Renaming the evaluation or a key starts that case's history again. For a runnable project, see [`with-cases`](https://github.com/reeval-ai/reeval/tree/main/examples/with-cases).

</Step>
<Step title="Verify the run plan">

With the `reeval run --dry-run` command, plan the run without starting a sandbox or a harness:

```bash
npx reeval run --dry-run
```

The evaluation lists its case count in the `notes` column:

```text
eval                                                 harnesses  variants  runs  attempts  notes
with-cases.eval.ts › adds a function to src/math.js  1          —         1     3         3 cases
```

</Step>
<Step title="Run the evaluation">

Run the evaluation. It prints one row; a failure, or `-v`, adds a row per case and a column per cell:

```text
with-cases.eval.ts
  ✓ adds a function to src/math.js  3 of 3 runs passed · 3 cases
    Passed all 3 cases.
      case      fake
    ✓ subtract  1 of 1
    ✓ multiply  1 of 1
    ✓ power     1 of 1
```

Past eight cases, the table lists only the failed ones; `-v` lists every case. While the run goes, each attempt names its case: `fake · power #1 agent turn 1`.

</Step>
</Steps>

## Gate on the rate over the cases

With `gate: { passRate }`, each cell passes on its rate over the cases, the mean of each case's pass@1. A failing case doesn't fail the evaluation on its own:

```ts title="evals/rate.eval.ts"
import { evaluate, expect } from '{{ pkg }}'

evaluate(
  'rate',
  { gate: { passRate: 0.6 }, cases: ['a', 'b', 'c'] },
  async (c, key) => {
    await c.send(key)
    expect(key).not.toBe('c')
  },
)
```

Two of three cases pass, a rate of 67%, so the evaluation passes (shown with `-v`):

```text
evals/rate.eval.ts
  ✓ rate  2 of 3 runs passed · 3 cases
    2 of 3 cases passed; c failed.
    Pass rate over the cases: 67%, clearing passRate 0.6.
      case  fake
    ✓ a     1 of 1
    ✓ b     1 of 1
    ✗ c     0 of 1
    ✗ not.toBe c  failed on c
      expected 'c' not to be 'c' // Object.is equality · evals/rate.eval.ts:8
```

Under the default `'all'`, every case must pass, and a failing case fails the evaluation: `Failed on c; 2 of 3 cases passed.` A case whose every attempt hit an infra error makes the evaluation an infra error, unless another case fails.

In the record, the cases are rows in the evaluation's `cases`. Case `c` keeps its `fail`, and the rate over the cases decides the evaluation, its exit code and the tally. `reeval compare` shows a case that flipped as `now fails` or `now passes`, and `--fail-on-regression` reads the evaluation's gate over its cases.

## Run a case on some environments

`where` picks the case and environment pairs that run, at plan time. It reads each environment's `traits`, filter facts that the agent never sees:

```ts title="evals/stack.eval.ts"
const next = defineEnvironment('next-app', { traits: { stack: 'next' } })
const vite = defineEnvironment('vite-app', { traits: { stack: 'vite' } })

evaluate(
  'answers a stack question',
  {
    environments: [next, vite],
    cases: questions,
    where: ({ case: q, environment }) =>
      q.stacks.some((s) => s === environment.traits.stack),
  },
  async (c, q) => {
    // ...
```

The `reeval run --dry-run` notes list each pair left out, such as `where excludes 2 pairs · excluded on vite-app: q002, q004`, the run's case table shows `–` for them, and each case in the record's `cases` keeps its own in `excluded` (`whereExcluded` in `--dry-run --json`). The evaluation's own `excluded` lists every pair, including a case `where` leaves out everywhere, which runs nothing. With `compare`, the control's answer holds for every variant. Reading `harness` decides each harness on its own. `where` is TypeScript only.

`where` gives the same answer every run. To run only some environments now, filter the cells with [`reeval run --trait stack=next`](/reference/cli#filtering-cells-by-trait) or a profile's [`limit.traits`](/reference/profiles#traits) instead.

## Compare over cases

Cases with `compare` report one effect per variant, paired by case, and the case table puts the control's column first:

```text
evals/compare.eval.ts
  ✓ writes Drizzle schemas  6 of 6 variant runs passed · 6 cases
    The with-drizzle variant helped.
    arm            passed  verdict  vs control
    app (control)  1 of 6
    with-drizzle   6 of 6  helped   "schema compiles" +83 pts
      case      app (control)  with-drizzle
    ✓ users     1 of 1         1 of 1
    ✓ posts     0 of 1         1 of 1
    …
```
 For more information, see [Lift](/results/compare/lift) and [`compare`](/reference/options#compare). For a runnable project, see [`with-case-lift`](https://github.com/reeval-ai/reeval/tree/main/examples/with-case-lift).
