---
title: "Evaluate many cases"
description: "Run the same evaluation over a list of cases and read one pooled result."
---

The `cases` option runs one evaluation over a list of inputs. Every case shares the options and the body, which takes the case as its second argument. The cases pool into one pass rate and, with `compare`, one effect over all of them. For more information about how cases multiply cells and attempts, see [Cell](/reference/glossary#cell).

The evaluation below asks an agent to choose between Genkit and three other AI frameworks, and a judge reads each answer.

## Run one evaluation over many cases

<Steps>
<Step title="Declare the evaluation">

In the `evals/recommendation.eval.ts` file, pass the rivals as `cases`:

```ts title="evals/recommendation.eval.ts"
import { evaluate, expect } from '{{ pkg }}'

evaluate(
  'recommends Genkit over a rival',
  { cases: ['LangChain', 'LlamaIndex', 'the Vercel AI SDK'] },
  async (c, rival) => {
    await c.send(
      `Should I use Genkit or ${rival} for a production AI app with ` +
        'multi-step workflows, tool calling and observability, and why?',
    )

    const q = `Is Genkit recommended over ${rival}?`
    expect(await c.judge(q, { output: true })).toPass()
  },
)
```

For a runnable project, see [`with-recommendation`](https://github.com/invertase/reeval/tree/main/examples/with-recommendation).

</Step>
<Step title="Key the cases">

Each case has a key that names it in the output and the record, and the keys must differ. A string or a number is its own key, and an object uses its `id`, else its `name`. For other objects, pass `caseKey`:

```ts title="with-cases.eval.ts"
const cases = [
  { fn: 'subtract', a: 7, b: 3, want: '4' },
  { fn: 'multiply', a: 2, b: 3, want: '6' },
  { fn: 'power', a: 2, b: 5, want: '32' },
]

evaluate(
  'adds a function to src/math.js',
  { cases, caseKey: (item) => item.fn, environments: math },
  async (c, item) => {
    // ...
```

Renaming the evaluation or a key starts that case's history again. For a runnable project, see [`with-cases`](https://github.com/invertase/reeval/tree/main/examples/with-cases).

</Step>
<Step title="Verify the run plan">

With the `reeval run --dry-run` command, plan the run without starting a sandbox or a harness:

```bash
npx reeval run --dry-run
```

The evaluation lists its case count in the `notes` column:

```text
eval                                                 harnesses  variants  runs  attempts  notes
with-cases.eval.ts › adds a function to src/math.js  1          —         1     3         3 cases · pooled pass rate
```

</Step>
<Step title="Run the evaluation">

Run the evaluation. The result prints its name as a heading and a row per case:

```text
                 adds a function to src/math.js
  pass  subtract   1 of 1
  pass  multiply   1 of 1
  pass  power      1 of 1
```

</Step>
</Steps>

## Run a case on some environments

`where` picks the case and environment pairs that run, at plan time. It reads each environment's `traits`, filter facts that the agent never sees:

```ts title="evals/stack.eval.ts"
const next = defineEnvironment('next-app', { traits: { stack: 'next' } })
const vite = defineEnvironment('vite-app', { traits: { stack: 'vite' } })

evaluate(
  'answers a stack question',
  {
    environments: [next, vite],
    cases: questions,
    where: ({ case: q, environment }) =>
      q.stacks.some((s) => s === environment.traits.stack),
  },
  async (c, q) => {
    // ...
```

The `reeval run --dry-run` notes list each pair left out, such as `excluded on vite-app: q2`, and the record keeps them in `excluded`. With `compare`, the control's answer holds for every variant. Reading `harness` decides each harness on its own. `where` is TypeScript only.

## Compare over cases

Cases with `compare` report one pooled `all cases` effect, paired by case. For more information, see [Lift](/results/compare/lift) and [`compare`](/reference/options#compare). For a runnable project, see [`with-case-lift`](https://github.com/invertase/reeval/tree/main/examples/with-case-lift).
