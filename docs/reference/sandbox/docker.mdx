## The `docker()` factory

`docker()` returns a sandbox that runs each attempt in one Docker container on your machine. The `{{ pkg }}/sandbox` subpath exports `docker()` for the `sandbox` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { docker } from '{{ pkg }}/sandbox'

export default defineConfig({
  sandbox: docker({ memory: '8g', cpus: 4 }),
})
```

Every option is optional. `podman()` takes the same options; see [Podman sandbox](/reference/sandbox/podman). For more information about the `sandbox` option, see [Choose a sandbox](/sandboxes).

A recipe names the image the container starts from. `docker()` takes at most one of `image`, `from`, and `dockerfile`; without one, the container runs reeval's own sandbox image for your harness. For more information, see [Bake the tools](/sandboxes/toolchains).

Each limit applies to one container. reeval passes the limits to `docker run` as `--memory`, `--memory-swap`, `--cpus`, and `--pids-limit`.

For more information about the `egress` option and its automatic hosts, see [Control sandbox egress](/environments/egress).

## The `id` option

<Property name="id" type="string" optional>
  The last segment of the cell key. Defaults to `docker`, or `docker:<image>` when `image` or `from` names another image, plus a hash of `install`.
</Property>

## The `maxConcurrent` option

<Property name="maxConcurrent" type="number" optional>
  The most Docker containers reeval runs at once across the run, whatever their image. A whole number of at least 1. The run's `concurrency` option still caps attempts overall.
</Property>

## The `root` option

<Property name="root" type="boolean" optional>
  Runs the agent, the setup commands, and the checks as root, with the capabilities `apt-get` needs, instead of the unprivileged `reeval` user. Defaults to `false`.
</Property>

## The `capabilities` option

<Property name="capabilities" type="string[]" optional>
  Linux capabilities to add back, such as `['NET_RAW']`, with or without the `CAP_` prefix. The container drops every other capability and runs with `no-new-privileges`.
</Property>

## The `image` option

<Property name="image" type="string" optional>
  An image that already has the harness baked in. reeval uses it as is.
</Property>

## The `from` option

<Property name="from" type="string" optional>
  A Debian or Ubuntu based toolchain image, such as `python:3.12-slim`. reeval bakes Node, Git, and the harness on top on first use and caches the result. The image needs `apt-get` and glibc.
</Property>

## The `dockerfile` option

<Property name="dockerfile" type="string | URL" optional>
  A Dockerfile, relative to the file that calls `docker()`, absolute, or a `file:` URL. reeval builds it from its directory with `REEVAL_BASE` set to its sandbox image and caches the result by content hash. A Dockerfile that starts from another Debian or Ubuntu image gets the harness baked on, as for `from`.
</Property>

## The `install` option

<Property name="install" type="(string | { run: string; timeout?: Duration })[]" optional>
  Shell commands baked onto the base image in one cached layer. They run as root from `/`, in order, and see neither secrets nor the workspace. `install` does not combine with `dockerfile`.
</Property>

## The `memory` option

<Property name="memory" type="string | number" optional>
  The container's memory is `'4g'`, `'512m'`, or a byte count. Defaults to `'4g'`.
</Property>

## The `swap` option

<Property name="swap" type="string | number" optional>
  Swap on top of `memory`, in the same units. Defaults to as much as `memory`; `0` makes `memory` the hard ceiling. A host without swap has none to give.
</Property>

## The `cpus` option

<Property name="cpus" type="number" optional>
  The CPUs the container may use, fractions allowed. Defaults to `2`, capped at the Docker host's count.
</Property>

## The `pids` option

<Property name="pids" type="number" optional>
  Processes and threads at once. Defaults to `1024`.
</Property>
