---
title: "Glossary of terms"
description: "Agents, attempts, assertions, judgments, lift, and the other terms in a reeval run."
---

## Agent

An agent is a harness plus its model, named in the `harness` option, such as `claude-code:claude-sonnet-5`. For more information about an agent, see [Configuration](/core-concepts#configuration).

## Analysis

An analysis is what a language model writes about a run: answers and insights. `reeval analyze` writes the analysis from the run's digest. For more information about analysis, see [Analysis](/results/analysis).

## Answers

Answers are what an evaluation's questions found, such as `won 3 of 4` for each side of a pairwise question. For more information about answers, see [Results](/core-concepts#results).

## Artifacts

Artifacts are what the agent leaves in the workspace: the files it wrote, the diff, and screenshots from `c.capture()`. For more information about artifacts, see [Evaluation](/core-concepts#evaluation).

## Assertion

An assertion is a named, deterministic pass or fail on what an attempt produced, written with `expect`. For more information about assertions, see [Assertions](/evals/checks).

## Attempt

An attempt is one execution of a cell in a fresh sandbox, and its outcome is pass, fail, infra error, or skipped. For more information about an attempt, see [Configuration](/core-concepts#configuration).

## Baseline

The baseline is a comparison's environment without the change, and each variant is measured against it. `compare.baseline` optionally names it; the record's cell role calls it `'control'`. For more information about a baseline, see [Compare setups](/evals/compare).

## Cell

A cell is one agent, one environment, and one sandbox of an evaluation. In a comparison, the baseline and each variant are separate cells. For more information about a cell, see [Configuration](/core-concepts#configuration).

## Comparison

A comparison runs its baseline and each variant as separate cells. It measures a variant against the baseline only when the cells share an agent and sandbox, and reports `helped`, `made it worse`, or `can't tell yet`. For more information about a comparison, see [Compare setups](/evals/compare).

## Environment

An environment is what the agent receives in an attempt, such as skills, MCP servers, rules, files, setup steps, variables, and secrets. For more information about an environment, see [Define an environment](/environments).

## Evaluation

An evaluation is one task for the agent and the assertions and judgments on its result, declared with `evaluate()` or as one case of `evaluate.each()` in a `*.eval.ts` file. The evaluation fails when a cell that counts toward it fails. For more information about an evaluation, see [Write an evaluation](/evals/evaluate).

## Harness

A harness is the coding agent's program, such as Claude Code or Codex, and with a model it makes an agent. For more information about a harness, see [Choose a harness](/harnesses).

## Insights

Insights are what an analysis model says the agent did and why, not only whether it passed. For more information about insights, see [Analysis](/results/analysis#read-insights-after-a-run).

## Judgment

A judgment is an LLM verdict from `c.judge()` on a yes or no question about the agent's work. `toPass()` turns it into a pass or fail; the record stores it in `judgements`. For more information about a judgment, see [Score agent work](/evals/judges).

## Lift

Lift is a variant against the baseline: the difference in pass rate on the same agent and sandbox. For more information about lift, see [How reeval decides a change helped](/evals/statistics).

## Measures

The measures are pass rate, tokens, tool calls, turns, cost, and time. For more information about each measure, see [Results](/core-concepts#results).

## Past runs

Past runs are earlier recorded runs, and `reeval compare` diffs this run against one. For more information about past runs, see [Find run regressions](/results/regressions).

## Profile

A profile is a named preset that sizes a run, and the run's record stores the profile that sized it. For more information about a profile, see [Profiles](/runs/profiles).

## Question

A question in `questions` reads across attempts after they end, and never changes an outcome. For more information about a question, see [Evaluation](/core-concepts#evaluation).

## Record

A record is the saved JSON of a run. reeval writes a scratch copy in the `.reeval/runs/` directory, and recording copies that JSON into the history folder. For more information about a record, see [Recording](/runs/recording).

## Run

A run is one `reeval run` command and every attempt that command starts, and reeval saves them as one record. For more information about a run, see [Running](/runs/running).

## Sandbox

A sandbox is the container an attempt runs in, and every request that leaves it goes through that attempt's egress gateway. For more information about a sandbox, see [Choose a sandbox](/sandboxes).

## Task

The task is what the agent is asked to do, sent with `c.send()`. For more information about a task, see [Write an evaluation](/evals/evaluate).

## Transcript

A transcript records every message and tool call of an attempt as one JSON object per line in the `transcript.jsonl` file. For more information about a transcript, see [Read a transcript](/results/debugging#read-a-transcript).

## Turn

A turn is the agent's reply to one `c.send()` call. The turn holds the final message, transcript events, token usage, the served model, and the workspace diff. For more information about a turn, see [Turns](/evals/turns).

## Workspace

The workspace is the directory in the sandbox where the agent works, and grading reads it. For more information about a workspace, see [Evaluation](/core-concepts#evaluation).

## Shared words

### evaluation

**Evaluation** is `evaluate()`. The **evaluation model** is a `typesafe-ai/*` judge model, which only scores yes or no, as the error strings name it. A **language model** writes text.

### compare

**Compare** is the `compare` option. The **run diff** is `reeval compare`, and the Run history `compare` tool, which diffs two runs.

### effort

**Reasoning effort** is the harness `effort` option, an input, recorded as `reasoning_effort`. **Effort** is the `effort` table of measured tool calls, agent time, and tokens, an output.

### run

**Run** is one `reeval run`. `runs` is attempts per cell. A setup step's `run` is its command. The `runs` table is a query storage table.

### record

**Record** is the saved `RunRecord`. **Recording** is `reeval record`, the `record` key, and `--record`.

### history

The **history folder** is `.history`. `reeval history` is the pass/fail list over recent runs. **Run history** is the `reeval mcp` server. The `history` tool lists recorded runs; the code still titles that tool "Run history". `.reeval/history.db` is the database those commands read.

### gate

**Gate** is a cell's `gate`. The **comparison gate** is `compare.gate`.

### question

A **judge question** is the argument to `c.judge()`. A **question** in `questions` is asked after the attempts end; one with `across` is a **pairwise question**.

### model

The **harness model** is `model`. Separate from it are `judge.model`, `capture.model`, `question.model`, `analysis.model`, and the served model `turn.model`. An **evaluation model** scores yes or no. A **language model** writes text.

### artifacts

**Artifacts** are what the agent leaves in the workspace. **Judge artifacts** are `artifacts` on `c.judge()` and on a question. **Stored artifacts** are `history.artifacts` and `reeval record --artifacts`.

### verdict

A **judge verdict** is `Verdict`, checked with `toPass()`. A **family verdict** is `FamilyVerdict`. An **effort verdict** is `EffortVerdict`. An **assertion verdict** is `CheckVerdict`. An **outcome** (`pass`, `fail`, infra error, or `skipped`) is never called a verdict.

### effect

**Effect** is a variant against its baseline: `helped`, `made it worse`, `can't tell yet`, or blank. An **effort verdict** is `fewer`, `more`, `within noise`, or `too few attempts to test`. A **family verdict** is the family's paired lift.

### MCP server

An **MCP server** is one the harness receives, under `mcp`. **Run history** is reeval's read-only MCP server, `reeval mcp`.

### environment

An **environment** is `defineEnvironment()`. **Variables** are the sandbox `env`. **Host variables** are variables in the shell that runs reeval. The **environment digest** is one part of a cell fingerprint.

### digest

The **digest** is what `reeval analyze` hands the model. The **environment digest** is one part of a cell fingerprint.

### timeout

`timeout` defaults to `'15m'`. A setup step's `timeout` defaults to `'5m'`. `capture.timeout` defaults to `'60s'`. `startTimeout` limits how long a harness may take to start. `expect.poll`'s `timeout` defaults to 1000 milliseconds.

### id

The **harness id** is `id` on a harness, and the **sandbox id** is `id` on a sandbox. The **attempt id** is `<cell key>#<n>`. The **run id** names one run.

### maxConcurrent

Harness `maxConcurrent`, sandbox `maxConcurrent`, and `judge.maxConcurrent` are separate caps. `concurrency` is how many attempts run at once.

### only

`evaluate.only` and `group.only` mark which evaluations run. A **harness edit** is `{ add }`, `{ only }`, or a function of the inherited list. Skill `only` and `exclude` choose which files a skill directory keeps.

### placement

`placement` on a skill is `'harness'` or `'workspace'`. Those values are not the harness and not the workspace.

### assertion

An **assertion** is one deterministic pass or fail on an attempt's work, and a **judgment** is an LLM verdict. **Doctor checks** are what `reeval doctor` verifies, and are not assertions. The **assertion table** is the terminal table of assertions by cell, headed `check`.

### agent

An **agent** is a harness plus its model. **Agent mode** is `--ui agent`, output for an agent that is itself running reeval. `to: 'agent'` on a secret puts the value in the container's environment.

### summary

**Analysis** is what the model writes about a run. `summary.md` is the run written as Markdown. The **GitHub step summary** is `GITHUB_STEP_SUMMARY`, which receives `summary.md` when it is set.

### transcript

The **transcript** is `transcript.jsonl`, one file per attempt. `turn.transcript` is that turn's events. The Run history `transcript` tool is titled "Attempt transcript". `REEVAL_RAW_TRANSCRIPT` is the host variable.
