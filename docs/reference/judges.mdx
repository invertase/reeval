`c.judge(question)` asks a model a yes/no question about the latest turn and returns a verdict. `expect(verdict).toPass()` fails the eval when the answer is no.

```ts title="evals/greet.eval.ts"
import { evaluate, expect, group } from '{{ pkg }}'

group('greet', { judge: { threshold: 0.9 } }, () => {
  evaluate('explains its change', async (c) => {
    await c.send('Create greet.js exporting greet(name).')
    const verdict = await c.judge(
      "Does the agent's final message describe what it changed?",
    )
    expect(verdict).toPass()
  })
})
```

## Settings

`judge` is accepted in `reeval.config.ts`, profile `judge` and `defaults.judge`, groups, evals, and as the second argument of `c.judge()`. It merges field by field, the most specific level winning: the call, then the eval, then its groups, then the profile, then the config.

<Property name="model" type="string | FakeJudgeModel | DecisionModel" optional>
  `"provider/model"`, such as `typesafe-ai/jev-1.13.0` (reeval's recommended judge) or `google/gemini-3.8-flash`. `fakeJudge()` for tests. Groups, evals and calls also accept an AI SDK decision model object. There's no default: `c.judge()` without a model fails.
</Property>

<Property name="threshold" type="number" optional>
  The score, from 0 to 1, at or above which the verdict is `pass`. Default `0.8`.
</Property>

<Property name="providerOptions" type="Record<string, Record<string, JSONValue>>" optional>
  Passed to the provider as is, keyed by provider name.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most judge calls at once to this model's provider, across the run. A whole number of at least 1.
</Property>

<Property name="state" type="JudgeStateOptions" optional>
  What the judge is given beside your question: the judge's state, not the workspace's or the attempt's. An object keyed by the state's fields, described in [What the judge is given](#what-the-judge-is-given). It merges key by key, so a call's `state: { transcript: 'tools' }` keeps the config's `diff` patterns. A key's value replaces the outer one whole; lists aren't concatenated.
</Property>

`c.judge()` also takes `on`: a `Turn` this attempt's `c.send()` returned, to grade instead of the latest, or any JSON value to grade as the output (with the latest turn's task, files and diff). Only those `Turn` objects count as turns: a plain object shaped like one is a value, and a copy of a turn (`{ ...turn }`) is refused. `on` with a value and `state: { output: false }` is refused. `artifacts` is call-only: a list of `c.capture()` handles or their names. Each capture is sent as a file part. A provider that cannot take files fails the call with its own error.

<Property name="artifacts" type="Array<Capture | string>" optional>
  Captures this call sends the judge. A handle from `c.capture()` or that capture's `name`. The PNG is a file part (`{ type: 'file', mediaType: 'image/png', data }`). Ask about facts in the picture, not whether it "looks great". JSON-only calls (no `artifacts`) stay a JSON object.
</Property>

## What the judge is given

```ts
const verdict = await c.judge('Does sign-in handle a wrong password?', {
  state: { diff: ['src/', '!**/*.test.ts'], contents: ['README.md'] },
})
```

The judge gets your question and a JSON state, which `state` chooses. It's in `judge-input.json` as each call's `state`; the resolved option is beside it as `stateOptions`. With `artifacts`, the state is an ordered list: one JSON part, then each capture as a file part. The score is the model's probability that the answer is yes.

| `state` key | Type | Default | What the state holds |
|---|---|---|---|
| `task` | `boolean` | `true` | The graded turn's prompt |
| `output` | `boolean` | `true` | The graded turn's final message, or `on`'s value |
| `files` | `boolean` | `true` | The changed files, `status path`, filtered by `diff`'s patterns; dependency and build directories as one line each |
| `diff` | `boolean \| string[]` | `true` | The diff since the eval started, without the paths in `contents`. A list is gitignore-style patterns over workspace paths, matched like [`directory()`'s `glob`](/reference/helpers#directory): the last match wins and `!pattern` excludes |
| `contents` | `string[]` | `[]` | Workspace files whole, as they are when you call `c.judge()`, changed or not, keyed by path in path order. Exact paths or the same patterns as `diff`. A missing exact path is `null`; a pattern that matches nothing adds nothing |
| `transcript` | `boolean \| 'tools' \| 'full'` | `false` | The graded turn's transcript as text lines: `true` messages and tool calls, `'tools'` tool calls only, `'full'` reasoning and unclipped tool output too |
| `turns` | `'last' \| 'all'` | `'last'` | `'all'` moves `task`, `output` and `transcript` into `turns`, one entry per turn up to the graded one |
| `checks` | `boolean \| string[]` | `false` | The `c.exec` results so far as `{ command, exitCode, stdout, stderr }`; a list keeps only those commands, as passed to `c.exec` |
| file parts | | | With `artifacts`: each capture as `{ type: 'file', mediaType: 'image/png', data }` |

A key that's off leaves its field out of the state. Patterns in `contents` expand over the workspace as git sees it, so its `.gitignore` applies, and a binary file's value is `[reeval: dropped binary file]`. Transcript lines clip each tool's output to 300 characters, except under `'full'`:

```text
tool shell: npm test → ok · 0ms
  14 passing
edit src/app.ts (create, +1 −0) · 1ms
```

The diff leaves out what nobody wrote by hand, each file or directory replaced by a `[reeval: dropped …]` marker. To show one anyway, name it in `contents`.

| Left out | Matched by |
|---|---|
| Installed dependencies | `node_modules/`, `.venv/`, `.dart_tool/`, `.pub-cache/`, `__pycache__/` |
| Build output | `dist/` and `.next/` at any depth; `build/` and `out/` at the top of the workspace |
| Lockfiles | `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lock`, `bun.lockb` |
| Generated files | `*.map`, `*.tsbuildinfo` |
| Minified files | A changed line of more than 1,000 characters |
| Binaries | Anything git diffs as binary |

What was left out, and why, is the judge input's `dropped` in `judge-input.json`, such as `dist/ (3 files): build output` or `notes.md: not in state.diff`. The workspace's own `.gitignore` keeps the rest of the noise out of the diff; see [Environment](/reference/environment#fields).

## Provider errors

reeval sends the judge everything `state` selects, uncut. When the provider refuses it, or a judge call fails with any other error from the provider's API, the message keeps the provider's wording and adds one line: the input's estimated size, at four characters a token, its biggest parts and files, and the `state` keys that were on, largest first. reeval knows no model's limit and doesn't read the provider's message, so the line comes with every provider error.

```text
judge failed for "Is it done?" (typesafe.evaluation/jev-under-test): {"error_type":"max_tokens_exceeded"}
The judge's input was ~22k tokens (estimated): diff 19k, of which src/pages/SignIn.tsx is 17k, src/firebase.ts is 2k; transcript 3k. Narrow state.diff, state.transcript, state.files, state.task or state.output.
```

## Failed calls

A call that fails (a provider error after its retries, or a missing key) doesn't throw. `c.judge()` returns a `JudgeFailure`, the call's error is recorded with its input, and the judges and checks after it still run. When the eval's body is done, the attempt fails as a `judge` error with every failed call's message.

```ts
{ verdict: 'error', score: null, threshold, question, model, error }
```

`toPass()` and `.not.toPass()` both fail on it, with the call's error. `c.judge()` still throws on a mistake in the call itself (no model, an empty question, a bad threshold, an unknown option or `state` key, a `state.checks` command it hasn't run) and when the run is cancelled or times out.

## Providers and keys

reeval calls a provider's own package when its key is set, and the Vercel AI Gateway otherwise:

| Provider prefix | Direct key | Package |
|---|---|---|
| `typesafe-ai/` | `TYPESAFE_AI_API_KEY` | `@ai-sdk/typesafe-ai` |
| `google/` | `GOOGLE_GENERATIVE_AI_API_KEY` | `@ai-sdk/google` |
| Any other | None | The AI Gateway, with `AI_GATEWAY_API_KEY` or `VERCEL_OIDC_TOKEN` |

[reeval analyze](/reference/cli/analyze) routes its `analysis.model` the same way: a direct key when the provider has one, the AI Gateway otherwise. It needs a language model, though, so an evaluation model such as `typesafe-ai/jev-1.13.0` can judge but can't write an analysis.

The run checks the judge's key before it starts, with the harness's. When the run's profile sets a judge `model`, that judge's key is the one checked, and a `fakeJudge()` needs none:

```text
reeval: Missing credentials: CURSOR_API_KEY, TYPESAFE_AI_API_KEY or AI_GATEWAY_API_KEY or VERCEL_OIDC_TOKEN. Set them in the environment or .env.local.
```

## Retries

A transient provider error (408, 409, 425, 429, a 5xx, or a message about high demand, overload, rate limits or a reset connection) is retried up to six tries in all, with exponential backoff from 2 seconds, capped at 30 seconds, and at least any `retry-after`.

Each retry is recorded on the verdict as `{ error, delayMs }`. A judge that still fails is a [failed call](#failed-calls): a judge error for the attempt, not a failed check.

## fakeJudge

```ts
import { fakeJudge } from '{{ pkg }}/judge'

judge: { model: fakeJudge({ score: 0.95 }) }
```

A judge that returns `score` (default `1`) for every question, with no key and no call. Its model name is `fake`. Per group, eval or call, `score` can be a function of the state the judge would see, to test what reaches it: `fakeJudge({ score: (state) => (String(state.diff).includes('dist/') ? 0 : 1) })`. The config takes a number. `'{{ pkg }}/judge'` also exports `RECOMMENDED_JUDGE_MODEL` (`'typesafe-ai/jev-1.13.0'`) and `DEFAULT_THRESHOLD` (`0.8`).

## fakeAnalysis

```ts
import { fakeAnalysis } from '{{ pkg }}/judge'

analysis: { model: fakeAnalysis({ output: { … } }) }
```

The same idea for `reeval analyze`: it answers with `output`, or `output(digest)` when you pass a function, and reeval parses and validates it as it would a real model's answer. Use it to test the analysis without a key. See [reeval analyze](/reference/cli/analyze).

```ts
analysis: {
  agent: true,
  model: fakeAnalysis({
    note: ({ harness, attempts }) =>
      `${attempts.length} attempts on ${harness}`,
  }),
}
```

With `analysis.agent`, each note calls the real tools as a model would: it lists the attempts and compares up to three failed-vs-passing pairs. Then it answers with `note`, a string or a function of `{ eval, harness, attempts, compared }`. `note: { error: '…' }` throws instead, to test a failed note. Its summary of the run reads up to three dropped evidence items and three failing attempts with the tools, then answers with `output`; an `output` function gets the digest with the evidence it read, and one that throws tests a failed summary.

```ts
analysis: {
  model: fakeAnalysis({
    vote: (pair) => (pair.a.includes('Ahoy') ? 'A' : 'tie'),
  }),
}
```

`vote` answers [compare questions](/guide/compare#ask-questions): `'A'` (the attempt shown first), `'B'` or `'tie'` for every pair, `{ winner, reason? }` to record a reason, or a function of the blinded pair (`{ question, prompt, a, b }`, where `a` and `b` are the two diffs in the order shown). `{ error: '…' }` fails every call, to test an answer's `error`. Without `vote`, every pair is a tie; without `output`, `reeval analyze` refuses the fake, and `analysis.agent`'s summary fails.

## Errors

| Mistake | Message |
|---|---|
| No model | `c.judge() has no model. Set judge: { model: 'typesafe-ai/jev-1.13.0' } in reeval.config.ts, on the group or eval, or pass { model } to this call.` |
| No turn yet | `c.judge() has no turn to grade: call c.send() first` |
| No provider prefix | `config.judge: Judge model "gemini-3.8-flash" needs a provider prefix, e.g. "typesafe-ai/jev-1.13.0" or "google/gemini-3.8-flash"` |
| A model object in the config | `config.judge.model must be a "provider/model" string or fakeJudge(). Pass model objects per group, eval or call instead.` |
| A bad threshold | `judge.threshold must be between 0 and 1 (got 2) in reeval.config.ts`, or `in group("g")` on a group or eval; on a call, `c.judge() threshold must be between 0 and 1 (got 2)` |
| An empty question | `c.judge() needs a question: a non-empty string (got "")`, before the judge is called |
| A bad `maxConcurrent` | `maxConcurrent must be a whole number of at least 1 (got 0) for judge in evaluate("x")` |
| An unknown option | `Unknown judge option "diff" in reeval.config.ts. Did you mean "state.diff"?`; on a call, `… in c.judge(). …`. `on` outside a call: `on is per call: c.judge(question, { on }).` |
| An unknown `state` key | `Unknown judge.state key "transcipt" in reeval.config.ts. Did you mean "transcript"?` |
| A bad `state` value | `judge.state.turns must be 'last' or 'all' (got "first") in evals/a.eval.ts › lands`; `state` itself must be an object such as `{ transcript: 'tools' }` |
| A check it hasn't run | `c.judge() state.checks names a command this attempt hasn't run: "npm tset"` |
| `on` with no output | `c.judge() on gives the output, but state.output is false` |
| A bad `artifacts` | `c.judge() artifacts must be a list of capture handles or names (got "form")` |
| An unknown capture name | `c.judge() artifacts names a capture this attempt doesn't have: "form"` |
| A score function in the config | `config.judge.model: fakeJudge({ score }) in the config takes a number. Pass a score function per group, eval or call instead.` |
| The provider refuses the input | The provider's message, then `The judge's input was ~29k tokens (estimated): diff 28k, of which …`, as a failed call |
| No key at call time | `No credentials for judge model "google/gemini-3.8-flash". Set GOOGLE_GENERATIVE_AI_API_KEY to call @ai-sdk/google directly, or AI_GATEWAY_API_KEY (or VERCEL_OIDC_TOKEN) to go through the Vercel AI Gateway.` |
