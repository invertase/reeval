---
title: Environment variables
description: Every environment variable ES reads, and the flag each one stands in for.
---

`es run` loads `.env.local`, then `.env`, from the config's directory: where the `es.config.ts` ES found (or the `--config` file) lives, not the current directory. Variables already set in your shell win over both files, and `.env.local` wins over `.env`. `es analyze` loads them the same way, for its model key; other commands don't read env files.

```bash title=".env.local"
CURSOR_API_KEY=...
TYPESAFE_AI_API_KEY=...
```

## Credentials

| Variable | Used for |
|---|---|
| `CURSOR_API_KEY` | `cursor()`. Stays on the host: the sandbox sees a placeholder, swapped for the key only on Cursor's endpoints. |
| `ANTHROPIC_API_KEY` | `claudeCode()`, the same way. Its adapter never reads `AI_GATEWAY_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL` or a Claude subscription. |
| `GEMINI_API_KEY` | `antigravity()`: a Gemini API key, the same way. |
| `TYPESAFE_AI_API_KEY` | `typesafe-ai/*` judges, such as Jev, directly |
| `GOOGLE_GENERATIVE_AI_API_KEY` | `opencode()`, `goose()` and `pi()`: a Gemini API key, brokered the same way. Also `google/*` judges, directly. |
| `AI_GATEWAY_API_KEY`, `VERCEL_OIDC_TOKEN` | Any `provider/model` judge whose own key isn't set, through the Vercel AI Gateway |
| Any name in `secret.fromEnv('NAME')` | Read on the host and passed into the sandbox (or brokered, or to checks only), redacted everywhere |

A credential with whitespace or a line break in it (a key copied from a wrapped terminal line) stops the run with exit 2, naming the variable and the character.

## ES settings

| Variable | Same as | Effect |
|---|---|---|
| `ES_PROFILE` | `--profile` | The profile to size the run with; the flag wins |
| `ES_CONCURRENCY` | `--concurrency` | Beats the config's `concurrency`, loses to the flag |
| `ES_UI` | `--ui` | `live`, `plain` or `agent` |
| `ES_LOG_ORDER` | `--log-order` | `stream` or `grouped` |
| `ES_LOG_PREFIX` | `--log-prefix` | `task` or `none` |
| `ES_OUTPUT_LOGS` | `--output-logs` | `full`, `errors-only` or `none` |
| `ES_HEARTBEAT` | | Plain mode's "still running" line after silence, e.g. `30s`. Default `60s`; `0` turns it off |
| `ES_DEBUG` | | `1` streams the hidden engine's output and the Docker sandbox and image-build logs to stderr, and prints stacks for unexpected errors |
| `ES_RAW_TRANSCRIPT` | | `1` also writes the harness's unnormalised stream to `transcript.raw.jsonl` |
| `ES_BASE` | | Not read from your shell: the build argument ES passes to a `docker({ dockerfile })` build, naming ES's image for the cell's harness. Start a Dockerfile `ARG ES_BASE` / `FROM ${ES_BASE}` |

## CI and agent detection

| Variable | Effect |
|---|---|
| `CI` (not `false`) | Auto-records under `record: 'ci'`, refuses `.only` (exit 2), picks `defaultProfile.ci`, names runs with `ci` |
| `BUILD_NUMBER`, `BUILD_ID`, `RUN_ID`, `TEAMCITY_VERSION`, … | Plain output with grouped logs (Turborepo's CI list). Only `CI` affects recording and `.only` |
| `GITHUB_ACTIONS=true` | `::group::` blocks for passing attempts, `::error` annotations for failing ones, colour on |
| `GITHUB_STEP_SUMMARY` | `summary.md` is appended to it |
| `GITHUB_*`, `GITLAB_CI`, `CI_JOB_URL`, `CI_COMMIT_REF_NAME` | Branch, PR and CI run URL in the record |
| `CURSOR_AGENT`, `CLAUDECODE`, `AI_AGENT=<name>`, … | Agent output (std-env's agent detection). Set `ES_UI=plain` to see everything |
| `NO_COLOR`, `FORCE_COLOR` | Colour off or on. Otherwise on for a TTY or GitHub Actions, never in agent mode |
