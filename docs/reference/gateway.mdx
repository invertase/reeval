title: Gateways
description: The config's gateway list, which gateway each harness's and the judge's model calls go through, pinning one, Vercel AI Gateway, OpenRouter, and the errors reeval raises at plan time.
---

`gateway` lists the routes model calls may take, in the order you prefer them. Each harness, the judge, analysis and captures take the first gateway in the list that can serve them.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { vercel } from '{{ pkg }}/gateway'
import { claudeCode, codex, cursor } from '{{ pkg }}/harness'

export default defineConfig({
  harness: [
    claudeCode({ model: 'claude-sonnet-4-5' }),
    codex({ model: 'gpt-5.4-mini' }),
    cursor({ model: 'composer-2.5' }),
  ],
  gateway: [vercel()],
})
```

Every list ends with `direct()`, each harness's own key, so Cursor here falls back to `CURSOR_API_KEY` and the plan says so ([Fallback](#fallback)). The default is `[direct()]`: every harness calls its own provider with its own key, as on [Harnesses](/guide/harnesses). Setting it to that changes nothing but the plan's notes and the record's `gateway` field.

## Helpers

| Helper | YAML | Serves | Key |
|---|---|---|---|
| `direct({ enabled? })` from `'{{ pkg }}/gateway'` | `direct` or `{ direct: { enabled: false } }` | every harness; judge and analysis models whose provider reeval calls directly (`anthropic/*`, `google/*`, `openai/*`, `typesafe-ai/*`) | each harness's or provider's own, such as `CURSOR_API_KEY` |
| `vercel()` from `'{{ pkg }}/gateway'` | `vercel` or `{ vercel: {} }` | Claude Code, Codex, Goose, OpenCode, fx, Grok Build, pi; any analysis, compare-question or capture model; judges that are decision models, such as `typesafe-ai/jev-1.14.0` | `AI_GATEWAY_API_KEY`, else `VERCEL_OIDC_TOKEN` |
| `openrouter({ fallbacks })` from `'{{ pkg }}/gateway'` | `openrouter` or `{ openrouter: { fallbacks: true } }` | Claude Code, Codex, Goose, OpenCode, Grok Build, pi; any analysis, compare-question or capture model; judges that are decision models, such as `typesafe/jev-1.14` | `OPENROUTER_API_KEY` |
| `vertex({ project?, location?, regions? })` from `'{{ pkg }}/gateway'` | `vertex` or `{ vertex: { project: p } }` | Claude Code, Antigravity, OpenCode, Goose, pi, Grok Build and fx ([below](#vertex-ai)); `google/*` and `anthropic/*` judge and analysis models | Application Default Credentials |

## Vercel AI Gateway

```bash title=".env.local"
AI_GATEWAY_API_KEY=vck_...
```

One key serves every harness and model on `vercel()`, with judges limited to decision models ([below](#the-judge-analysis-and-captures)). The egress gateway swaps it in only on Vercel's model paths (`ai-gateway.vercel.sh`), so it never enters the sandbox, as with any [brokered credential](/concepts/credential-brokering).

| Harness | How it reaches Vercel | Brokered on | Model ids | Served model |
|---|---|---|---|---|
| Claude Code | `ANTHROPIC_BASE_URL` on Vercel, the key as `AI_GATEWAY_API_KEY` | `POST /v1/messages`, `POST /v1/messages/count_tokens` | as written, e.g. `claude-haiku-4-5` | as the harness reports it, e.g. `claude-haiku-4-5` |
| Codex | a Responses API provider on Vercel in `config.toml` | `POST /v1/responses` | `openai/` prefixed | Vercel's, from each response, e.g. `openai/gpt-5.6-luna[effort=medium]` |
| Goose | its `vercel_ai_gateway` provider, a Bearer key | `POST /v1/chat/completions`, `POST /v1/responses`, `GET /v1/models` | `google/` prefixed | Vercel's, from each response |
| OpenCode | its `vercel` provider, a Bearer key | `POST /v1/messages`, `POST /v4/ai/messages` | `<provider>/<model>` as written, run as `vercel/<provider>/<model>` | Vercel's, from each response |
| fx | its AI Gateway provider | `GET /coding-agent/v1/…`, `POST /v<n>/ai/language-model` | a gateway id as written; a bare id `openai/` prefixed | Vercel's, from each response; a stream that names none (Gemini's) records none, and the model each call asked for goes in `askedModels` |
| Grok Build | a `[model."xai/<id>"]` table on Vercel's Chat Completions API, keyed by `env_key` | `POST /v1/chat/completions` | `xai/` prefixed | Vercel's, from each response, e.g. `spacexai/grok-4.6` where direct records `grok-4.6` |
| pi | a provider of reeval's in pi's `models.json`, on Vercel's Chat Completions API with a Bearer key | `POST /v1/chat/completions` | `google/` prefixed; a Gemini model in pi's own catalog | Vercel's, from each response, e.g. `google/gemini-3.8-flash` |

pi takes its model's limits, prices and thinking levels from its own catalog, as on Gemini's API, and sends each level as Gemini's own `thinkingConfig` under Vercel's `providerOptions`. A Gemini model on a thinking budget, or one outside pi's catalog, fails the attempt. `effort` runs as [Effort on a gateway](#effort-on-a-gateway) says.

A Vercel project's token from `vercel env pull` (`VERCEL_OIDC_TOKEN`) works when `AI_GATEWAY_API_KEY` isn't set. It lasts about 12 hours, so the plan refuses an expired one before anything runs, and `reeval doctor` fails on it.

## OpenRouter

```ts title="reeval.config.ts"
import { openrouter } from '{{ pkg }}/gateway'

export default defineConfig({
  harness: claudeCode({ model: 'claude-haiku-4-5' }),
  gateway: [openrouter()],
  judge: { model: 'typesafe/jev-1.14' },
})
```

One key, `OPENROUTER_API_KEY`, serves every harness and model on `openrouter()`. The egress gateway swaps it in only on OpenRouter's model paths (`openrouter.ai`), so it never enters the sandbox.

| Harness | How it reaches OpenRouter | Brokered on | Model ids |
|---|---|---|---|
| Claude Code | `ANTHROPIC_BASE_URL` at `https://openrouter.ai/api`, the key as `ANTHROPIC_AUTH_TOKEN` (a Bearer token) | `POST /api/v1/messages`, `POST /api/v1/messages/count_tokens` | `anthropic/` prefixed and dotted: `claude-haiku-4-5` runs as `anthropic/claude-haiku-4.5` |
| Codex | a Responses API provider at OpenRouter in `config.toml`, sending `X-OpenRouter-Metadata: enabled` so each response names its upstream | `POST /api/v1/responses` | `openai/` prefixed |
| Goose | its `openrouter` provider, a Bearer key | `POST /api/v1/chat/completions`, `GET /api/v1/models` | `google/` prefixed |
| OpenCode | its `openrouter` provider, a Bearer key | `POST /api/v1/chat/completions` | `<provider>/<model>` as written, run as `openrouter/<provider>/<model>` |
| Grok Build | a `[model."x-ai/<id>"]` table on OpenRouter's Chat Completions API, keyed by `env_key` | `POST /api/v1/chat/completions` | `x-ai/` prefixed |
| pi | its own `openrouter` provider, a Bearer key | `POST /api/v1/chat/completions` | `google/` prefixed; a Gemini model in pi's own catalog for OpenRouter |

An id that already names a provider (`anthropic/claude-sonnet-4.5`) runs as written. Every response names the served model and the upstream provider that served it, and the gateway reads both, with the call's `usage.cost`.

pi takes its model's limits, prices and thinking levels from its own catalog for OpenRouter, and sends each level as OpenRouter's `reasoning.effort`; a model outside the catalog fails the attempt.

Cursor, Antigravity and fx don't run on `openrouter()`, and fall through to the next entry. `effort` runs as [Effort on a gateway](#effort-on-a-gateway) says.

## Effort on a gateway

| Harness | On `vercel()` | On `openrouter()` |
|---|---|---|
| Claude Code | as on Anthropic's API | refused: OpenRouter turns Claude Code's adaptive thinking into a thinking budget for a model that takes none, such as Haiku 4.5 |
| Codex | the Responses API's `reasoning.effort`, which each response names | the same |
| Goose | refused: its `vercel_ai_gateway` provider sends none | a Gemini model: OpenRouter's `reasoning.effort`, which it sends Gemini as its thinking level |
| OpenCode | a Gemini model: Gemini's `thinkingConfig` under `providerOptions` | a Gemini model: OpenRouter's `reasoning.effort` |
| Grok Build | `reasoning_effort`, which xAI's models take | the same |
| pi | Gemini's `thinkingConfig` under `providerOptions` | a Gemini model: OpenRouter's `reasoning.effort` |

The plan refuses `effort` for a harness and model the table doesn't cover, since nothing checks the model gets it as its own setting, and such a cell falls through to the next entry. fx takes `effort` only on `vertex()`. Each request's reasoning settings are in `.reeval/debug` (see [Debug data](/reference/debug-data)).

### Upstream providers and fallbacks

```text title="reeval run"
pass             fixes the bug
  …
  served by Anthropic 12 · Amazon Bedrock 3; judge served by Typesafe 2
```

OpenRouter can serve one model from several upstream providers. The record keeps which served each call, whatever the setting: `attempts[].upstreams` (each provider and its calls), `attempts[].reportedCostUsd`, and each judgement's `upstream` and `costUsd`. The output prints a line per harness under the eval.

`openrouter({ fallbacks: true })` lets reeval's own calls (the judge, analysis, compare questions and captures) fail over to another upstream when the first one fails; by default they send `allow_fallbacks: false`, so a call fails rather than moves. The plan notes when it's on.

<Warning>
`fallbacks` covers reeval's own calls only. The harnesses' calls take OpenRouter's own routing, which may fail over, whatever the setting; their `upstreams` show where each went.
</Warning>

On `openrouter()` a judge must be a decision model, which OpenRouter answers on its Decisions API, such as `typesafe/jev-1.14`. Any other model fails each judge call, naming it.

## Vertex AI

```ts title="reeval.config.ts"
gateway: [vertex({ project: 'my-project', regions: { anthropic: 'us-east5' } })],
```

`vertex()` takes the Google Cloud project the calls are billed to (`project`, default `GOOGLE_CLOUD_PROJECT`), the region they're made in (`location`, default `global`), and a region per publisher where it differs (`regions`, keyed `anthropic`, `google` or `xai`). The plan checks the shape, and stops with exit 2 when neither `project` nor `GOOGLE_CLOUD_PROJECT` names a project.

There's no key. reeval mints a Google Cloud access token on the host from Application Default Credentials (`gcloud auth application-default login`, or a credentials file in `GOOGLE_APPLICATION_CREDENTIALS`), and the egress gateway adds it to the agent's model calls only. The token never enters the sandbox, and reeval swaps in a fresh one five minutes before each expires. An attempt whose first token can't be minted fails as an infrastructure error.

| Harness | How it reaches Vertex | Brokered on | Model ids | Served model |
|---|---|---|---|---|
| Claude Code | `CLAUDE_CODE_USE_VERTEX`, with `ANTHROPIC_VERTEX_PROJECT_ID` and `CLOUD_ML_REGION` from the entry, and `CLAUDE_CODE_SKIP_VERTEX_AUTH` | `POST /v1/projects/<project>/locations/<region>/publishers/anthropic/models/<id>:streamRawPredict` (and `:rawPredict`) on the region's host | Vertex's, e.g. `claude-haiku-4-5@20251001`, or the Anthropic API's (`claude-haiku-4-5-20251001`), sent as Vertex's; an `anthropic/` prefix is dropped | from each call's path |
| Antigravity | `AGY_ADC_AUTH`, with `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` | `POST /v1/…/publishers/google/models/<id>:streamGenerateContent` | its own, e.g. `gemini-3.8-flash-low` | from each call's path |
| OpenCode | its `google-vertex` provider, with `GOOGLE_CLOUD_PROJECT` and `GOOGLE_VERTEX_LOCATION` | `POST /v1beta1/…/publishers/google/models/<id>:streamGenerateContent` | `google/<id>` or `<id>`, run as `google-vertex/<id>` | from each call's path |
| Goose | its `gcp_vertex_ai` provider, with `GCP_PROJECT_ID` and `GCP_LOCATION` | `POST /v1beta1/…/publishers/google/models/<id>:streamGenerateContent` | Gemini's, e.g. `gemini-3.8-flash`; a `google/` prefix is dropped | from each call's path |
| pi | `--provider google-vertex`, with `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` | `POST /v1/…/publishers/google/models/<id>:streamGenerateContent` | Gemini's, e.g. `gemini-3.8-flash`; a `google/` prefix is dropped | from each call's path |
| Grok Build | a `[model."xai/<id>"]` table on Vertex's OpenAI-compatible Chat Completions API, its `env_key` a placeholder | `POST /v1/projects/<project>/locations/<region>/endpoints/openapi/chat/completions` in the `xai` region | xAI's, e.g. `grok-4.6`, run as `xai/grok-4.6` | from each response |
| fx | a configured provider on Vertex's OpenAI-compatible Chat Completions endpoint, with no auth of its own | `POST /v1/…/endpoints/openapi/chat/completions` | Gemini's, `google/<id>` or a bare `gemini-…` id, run as `google/<id>`; no Claude, and no other bare id | from each response, which names it |

The Gemini CLIs call Vertex in the `google` region (`regions.google`, else `location`) and authenticate with Application Default Credentials of their own, so reeval writes them a service account beside the workspace with a key made up for the attempt, in `GOOGLE_APPLICATION_CREDENTIALS`. The egress gateway answers its token exchange (`POST oauth2.googleapis.com/token`) itself with a placeholder token, and Antigravity's account lookup (`GET www.googleapis.com/oauth2/v2/userinfo`) too, so neither reaches Google. It adds the real token to the model calls as it does for Claude Code. A restricted policy allows those hosts automatically.

Grok Build calls Vertex in the `xai` region (`regions.xai`, else `location`) and reads no credentials file: its `env_key` holds a placeholder, and the gateway puts the real token on its Chat Completions calls. The xAI model must be enabled for the project in Model Garden. `effort` goes as `reasoning_effort`.

fx speaks only Chat Completions to a provider of your own, so it runs on Vertex's OpenAI-compatible endpoint, which serves Gemini but not Claude: an `anthropic/…` model, or a bare id that isn't `gemini-…` (OpenAI's everywhere else), falls through to the next gateway. It needs no service account; the gateway adds the token to its calls. Its relay in the sandbox puts back the thought signature Gemini needs on each tool call fx returns, and adds fx's `effort` as `reasoning_effort`, the only gateway where fx takes one. See [fx on Vertex AI](/reference/harness/fx#vertex-ai).

Every other harness falls through to the next gateway in the list, and the plan's hint says so. Cursor and Codex never can: Cursor's agent calls only Cursor's API, and Codex only OpenAI's Responses API.

The judge, `analysis.model`, captures and compare's questions call `google/*` and `anthropic/*` models on Vertex too, from the host with the same token, in the publisher's region. Other prefixes fall through.

```ts title="reeval.config.ts"
gateway: [vertex()],
judge: { model: 'anthropic/claude-haiku-4-5-20251001' },
```

A Claude model's Anthropic API id, ending in its date (`-20251001`), is sent to Vertex as Vertex's id (`@20251001`), for Claude Code and for reeval's own calls. So one model string works on `vertex()` and on the `direct()` it falls through to; Vertex's own id works too. `reeval doctor` checks each entry's project and where its credentials come from; with `--online` it mints a token, names its account, checks the Vertex AI API is enabled in the project, and asks Vertex for a free token count on each model the config sends there (but Grok Build's, which has none). [Run on Vertex AI](/recipes/vertex) is the whole set-up.

## Fallback

```text title="reeval run --dry-run"
eval                      harnesses  variants  runs  attempts  notes
evals/g.eval.ts › greets  3          —         1     3         gateway: claude-code:claude-sonnet-4-5 → vercel · gateway: codex:gpt-5.4-mini → vercel · gateway: cursor:composer-2.5 → direct (fallback)
…
hint: gateway: cursor:composer-2.5 falls back to direct (vercel can't serve it: Cursor's agent only calls Cursor's own API)
```

A harness the first gateway can't serve falls through to the next, and each eval notes where its harnesses resolved. When a harness falls past an entry, the plan prints one hint for it, naming the gateway and why; a cell that ends on `direct()` is marked `(fallback)`. `--dry-run --json` has it as each cell's `gateway`: `{ name, skipped: [{ gateway, why }] }`, and `reeval doctor` marks it too.

Every list ends with `direct()`, so a harness or model no other entry serves falls back to its own key. List `direct()` yourself only to move it: `[direct(), vercel()]` tries each harness's own key first and Vercel for what it can't serve, such as an fx gateway id.

```ts title="reeval.config.ts"
gateway: [vercel(), direct({ enabled: false })],
```

`direct({ enabled: false })` turns the fallback off, for strict routing: a harness or model no entry serves stops the plan with exit 2 before anything runs, naming every gateway it tried. Where it sits in the list doesn't matter. A list may name `direct` once, so `direct()` and `direct({ enabled: false })` together are refused.

## Pinning a harness

```ts title="evals/g.eval.ts"
import { vercel } from '{{ pkg }}/gateway'
import { codex } from '{{ pkg }}/harness'

const harness = codex({ model: 'gpt-5.4-mini', gateway: vercel() })
evaluate('pinned', { harness }, async () => {})
```

Every harness factory takes `gateway`: the helper, or its name (`'vercel'`). A pin skips the fallback. It must name a gateway in the list, and one that can serve the harness; a pin never falls back to another.

To compare two gateways, list the same harness twice with different pins and distinct `id`s.

## The judge, analysis and captures

```ts title="reeval.config.ts"
gateway: [vercel()],
judge: { model: 'anthropic/claude-haiku-4-5', gateway: 'direct' },
```

With a `gateway` list set, the judge's, `analysis.model`'s and captures' models take the first entry that can serve them, and only that gateway's key: `direct()` uses the provider's own key, `vercel()` Vercel's, `openrouter()` OpenRouter's, and `vertex()` a token from Application Default Credentials. The judge also takes a `gateway` pin, in the config, a profile, a group, an eval or `c.judge()`; a judge model nothing in the list can serve stops the plan with exit 2.

On `vercel()`, a judge must be a decision model: Vercel AI Gateway serves `typesafe-ai/jev-1.14.0`, `openai/gpt-6-luna-decisions` and its other decision models as judges, and refuses every language model. Analysis, compare questions and captures take language models there as usual.

<Warning>
The plan can't tell a decision model from a language model, so a language-model judge such as `anthropic/claude-haiku-4-5` resolves to `vercel()` when it comes first, and each judge call fails: `the judge model "anthropic/claude-haiku-4-5" is a language model, and Vercel AI Gateway judges only with decision models. …`. Pin such a judge to `direct()`, as above, or judge with Jev.
</Warning>

Without a list, reeval uses no gateway: the list is `[direct()]`, so a model takes only its provider's own key, as on [Judges](/reference/judges), and a model `direct()` can't serve stops the plan. With a list, a model no listed gateway serves falls back to `direct()` unless it's turned off, and the plan notes `gateway: judge <model> → direct (fallback)`. A set `AI_GATEWAY_API_KEY` is never read until you add `vercel()`; the missing-key message says so.

## In a profile

```ts title="reeval.config.ts"
profiles: {
  local: { gateway: [direct()] },
},
```

A profile's `gateway` replaces the config's list for its runs. See [Profiles and budgets](/reference/profiles).

## In the record

Each cell resolved under a configured `gateway` or a pin records its gateway as `cells[].gateway`, and each judgement its gateway as `judgements[].gateway`. On OpenRouter, each attempt also records `upstreams` and `reportedCostUsd`, and each judgement `upstream` and `costUsd`. A gateway other than `direct` is part of the cell's fingerprint (`fingerprintParts.gateway`), so `reeval compare` treats a change of gateway as a new measurement; `direct` leaves the fingerprint as it was without the key. See [The record](/reference/record).

|---|---|
| An empty list | `gateway in reeval.config.ts must be a list of gateways in the order you prefer them, e.g. gateway: [vercel()] (got [])` |

| `direct({ enabled: false })` alone | `gateway in reeval.config.ts turns direct() off and lists no other gateway, so no model call has one. Add a gateway such as vercel(), or drop direct({ enabled: false }).` |
