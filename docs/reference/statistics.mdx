These statistical thresholds are fixed; you can't configure them.

For more information about the run model, see [Run](/reference/glossary#run). For more information about configuring a comparison, see [Measure lift against a baseline](/results/compare/lift).

## Pass rates and the Wilson interval

`pass@1` is passes divided by counted attempts, which include only passes and failures. A 95% Wilson score interval stays between 0 and 1, including with all passes, all failures, or no counted attempts.

## Lift and Newcombe's interval

Lift is the variant's pass rate minus the baseline's, between -1 and 1. Newcombe's hybrid score interval at 95% combines the two Wilson intervals and treats the sides as independent. Zero on or between the ends does not separate the rates.

## Variant outcomes

`helped` means the variant's pass rate is above the baseline's, `made it worse` below it, and `same` equal to it, at any number of counted attempts. The interval says whether the difference holds: zero inside it, or a small sample, raises the `too-few-tries` remark. An assertion uses the same rule.

For more information about the printed effect words, see [Read the result](/results/compare/lift#read-the-result). For more information about the printed outcomes, see [Read a run's output](/results/output).

## Too few runs

A small sample is a side with fewer than four counted attempts, or an interval that spans zero and still reaches past 20 points either way. The effect word always prints. On a small sample, whatever the direction, the `too-few-tries` remark prints beside it, and so does a difference whose interval spans zero.

| Result | Remark |
|---|---|
| 1 of 1 against 0 of 1 | better by 100 points, but on too few runs for the difference to hold |
| 2 of 2 against 0 of 2 | better by 100 points, on only 2 runs a side |
| 0 of 4 against 0 of 4 | the same, but 4 runs a side can't rule out a difference of up to 49 points |
| 4 of 4 against 0 of 4 | none: the difference holds |

The remark names the `runs`, never fewer than four, at which a difference that size would hold, or at which equal rates would rule out 20 points either way. Two of two against zero of two raises it though its interval excludes zero: when nothing changed, that split comes up about one run in eight. A family raises it when its pooled lift is insufficient, within noise with different rates, or `same` with an interval past 20 points.

`reeval query`'s `contrasts` and `factor_effects` add `small_sample` beside `pass_verdict`, and the `reeval analyze` digest adds `smallSample: true` beside a lift's verdict, by the same rule.

## Cases as pairs

reeval pools every case from one evaluation into a family of pairs on each run. Attempts inside a case are not independent.

For more information about declaring cases, see [Cases](/evaluations/task/cases).

One attempt per side uses Newcombe's paired interval and needs six discordant pairs, where only one side passed. Several attempts per case use a t interval over the pass-rate differences and need six paired cases. Six is the first count whose exact test can reach a p below 0.05.

The pooled pass rates give `helped`, `made it worse`, or `same`, the 95% interval says whether it holds, and below six the result is insufficient. The reported McNemar or Wilcoxon p decides nothing.

## Tokens, tool calls and time

reeval compares tool calls, agent time, and tokens by median and quartiles. A two-sided Mann-Whitney rank-sum test, exact unless the samples are large, calls `fewer` when the variant ranks lower and `more` when it ranks higher, at a p below 0.05. Only tokens, tool calls, and time let a p below 0.05 decide.

Counts that cannot reach a p below 0.05 are `insufficient`, and counts that can, but do not, are `noise`. With no ties, four against four can reach 2/70, and three against three can reach 2/20. Ties raise that floor. reeval omits the token comparison when either side has no token samples.

## Flaky cells

A cell is flaky when comparable runs, pooled, include a pass and a fail over at least six counted attempts. Comparable runs share sources, harness, environment, and image. Changes to an agent CLI's runtime files do not make runs incomparable. Six is a threshold, not a test, and a shorter pool is not flaky.

For more information about the `flaky_cells` view, see [Query views](/reference/query-views).

## Comparison questions as pairwise judging

A pairwise question is blinded judging of which unlabeled attempt did better, in both orders.

For more information about adding a pairwise question, see [Ask which side did better](/evaluations/grading/questions#ask-which-side-did-better).

The same side in both orders, or a tie and a named side, is a win. No named side is a tie. Opposite sides are a split.

A pairwise question never changes the outcome or the exit code. For more information about the `question_pairs` view, see [Query views](/reference/query-views).
