title: opencode()
description: The OpenCode 2 harness on any provider whose key ES can broker, its options and id, the providers it runs on and refuses, the tokens it can't report, its settings, web search and MCP servers.
---

`opencode()` runs [OpenCode](https://opencode.ai) 2 in the Docker sandbox over its ACP server (`opencode acp`), on the model's provider: Google, Anthropic, OpenAI, OpenRouter and nearly 200 more. `model` is required, and its provider picks the key.

```ts title="es.config.ts"
import { defineConfig } from '{{ pkg }}'
import { opencode } from '{{ pkg }}/harness'

export default defineConfig({
  harness: [
    opencode({ model: 'google/gemini-3.8-flash' }),
    opencode({ model: 'anthropic/claude-haiku-4-5' }),
    opencode({ model: 'openai/gpt-5.4-mini' }),
  ],
})
```

## Options

<Property name="model" type="string">
  OpenCode's model id, `<provider>/<model>`, such as `google/gemini-3.8-flash`, `anthropic/claude-haiku-4-5` or `openrouter/anthropic/claude-haiku-4.5`. The provider, before the first `/`, picks the key: only that provider's key is needed and brokered. A bare id with no provider, or a provider ES can't broker ([below](#refused-providers)), exits 2 at plan time. Required.
</Property>

<Property name="id" type="string" optional>
  The harness's id in cell keys, filters and the record. Default `opencode:<model>`, with the model's last segment: `opencode:claude-haiku-4-5`. Two cells whose models end the same, on different providers, need an `id` each.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most OpenCode attempts at once across the run, for example for your key's rate limits.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long its session may take to become ready (bootstrap and session start) before the attempt is an infra error, such as `'3m'`. Default `'90s'`. A start that times out is aborted and started once more; a second timeout fails the attempt with `opencode: session did not become ready within 90s (tried twice)`, and the record's `startRetries` notes a retried start.
</Property>

| | |
|---|---|

| Sandbox | `docker()` only |
| Image | `evalsuite-sandbox:opencode-0.2.0` |
| Rules file | `AGENTS.md` |

Build its image once with `es image build` in a project whose config uses `opencode()`.

## The key

```text title="es run -v"
broker    ANTHROPIC_API_KEY stays on the host · the gateway swaps it in on POST api.anthropic.com/v1/messages
…
gateway   POST https://api.anthropic.com/v1/messages → 200 · allowed · … · substituted ANTHROPIC_API_KEY (x-api-key)
```

ES reads the model's provider's key from the host, passes it to the adapter explicitly, and it never enters the container. The container gets only that provider's variable, holding a placeholder, so OpenCode can't reach another provider with another key. The gateway swaps the key in on the requests OpenCode 2.0.18 sends it on, in the header it uses:

| Provider | Header | Endpoint |
|---|---|---|
| `google` | `x-goog-api-key` | `POST generativelanguage.googleapis.com/v1beta/models/<model>:streamGenerateContent` |
| `anthropic` | `x-api-key` | `POST api.anthropic.com/v1/messages` |
| `openai` | `Authorization: Bearer` | `POST api.openai.com/v1/responses` |
| `openrouter` | `Authorization: Bearer` | `POST openrouter.ai/api/v1/chat/completions` |

Each provider's hosts, paths and headers come from running the pinned OpenCode against a mock server, once per provider and model API, and are listed [below](#supported-providers). A request that carries the placeholder anywhere else gets a 403 from the gateway. The adapter refuses to run in a sandbox that can't broker the key. `@ai-sdk/harness-opencode` brokers only a few providers' keys, for OpenCode 1, so ES uses its own thin config over `@ai-sdk/harness-acp` instead.

## Served model

```json title="record (turn)"
{ "model": "gpt-5.4-mini-2026-03-17[effort=none]", … }
```

OpenCode's ACP server names no model, so each turn records the one the gateway saw serve its last model call. Gemini's API names it in the URL; every other provider's response body does, as its first `"model"` field, with the reasoning effort when the response reports one (OpenAI's Responses API). ES runs the provider's calls over HTTP (`transport: 'http'`, below): OpenCode's default for OpenAI and xAI is a WebSocket, whose frames the gateway doesn't read.

## Tokens

None are recorded: every turn's `usage` is `null`. OpenCode's ACP server reports its last model call's tokens as the turn's, not the turn's total (still so in 2.0.18), so ES records nothing rather than an undercount. Its `usage_update` doesn't help either: `used` is the last call's context size and `cost` the whole session's. The served model is still recorded, from the gateway's requests.

## Settings

ES starts OpenCode with this config in `OPENCODE_CONFIG_CONTENT`, plus `OPENCODE_DISABLE_AUTOUPDATE=1` and `OPENCODE_DISABLE_MODELS_FETCH=1`. The CLI stays the image's, and its model catalog is the one it shipped with:

```json
{
  "update": "disable",
  "share": "disabled",
  "permissions": [
    { "action": "question", "resource": "*", "effect": "deny" },
    { "action": "browser", "resource": "*", "effect": "deny" }
  ],
  "websearch": { "provider": "exa" },
  "agents": { "title": { "model": "<provider>/<model>" } },
  "providers": { "<provider>": { "settings": { "transport": "http" } } },
  "mcp": { "servers": { "<name>": { "…": "…", "codemode": false } } }
}
```

| Setting | Why |
|---|---|
| `update`, `share` | No self-update and no share links. |
| `question` denied | It waits for a person to answer. |
| `browser` denied | Its tools drive a desktop browser. |
| `websearch` | Web search on Exa, below. |
| `agents.title.model` | Session titles run on your model. OpenCode's default is a second, small one, such as `gemini-flash-lite-latest`. |
| `providers.<provider>.settings.transport` | Model calls go over HTTP, where the gateway reads the served model, not a WebSocket. |
| `mcp.servers` | The environment's MCP servers, below. |

Every other tool runs without asking, as on every harness: ES answers OpenCode's permission requests with allow.

## Your own opencode.jsonc

```jsonc title="opencode.jsonc (in the eval's files)"
{
  "agents": { "title": { "model": "google/gemini-2.5-flash" } },
  "permissions": [{ "action": "webfetch", "resource": "*", "effect": "deny" }],
  "mcp": { "servers": { "files": { "type": "local", "command": ["node", "files.mjs"] } } }
}
```

OpenCode loads `~/.config/opencode`, then the workspace's `opencode.json(c)`, then ES's config last. With the file above, session titles still run on your cell's model (a key both set is ES's), `files` loads beside the environment's MCP servers (objects merge, servers by name), and `webfetch` is off. Permission rules append, the last match winning, so ES's rules only deny: your own denies stand.

OpenCode reads `AGENTS.md`, not `CLAUDE.md`. Besides its own skill directories, it also reads `.claude/skills` and `.agents/skills` in the workspace and the home directory, and nothing turns that off, so keep other agents' skills out of an OpenCode eval's files.

## Web search

```json title="transcript.jsonl"
{"type":"web-search","toolCallId":"call_782405","query":"anomalyco opencode github","references":8,…}
```

OpenCode's `websearch` tool calls a search service it's configured with; with none, it asks the user to pick one, which in an eval ends "Web search cancelled". ES points it at Exa's hosted MCP server (`https://mcp.exa.ai/mcp`), which answers without a key. The search runs from the sandbox, so `mcp.exa.ai` is one of OpenCode's automatic hosts and works under `egress: 'deny-all'`.

Exa's free tier is rate-limited. OpenCode sends an Exa key as a URL parameter, which the gateway can't swap in, so ES uses none rather than put a key in the container.

## MCP servers

```json title="transcript.jsonl"
{"type":"tool","toolCallId":"call_451616","tool":"mcp__stamp__house_stamp","input":{},"output":{"metadata":{"truncated":false},"output":"STAMP-7Q"},"ok":true,…}
```

The environment's MCP servers go in OpenCode's config (`mcp.servers`), `stdio` as `local` and `http` as `remote`, with `codemode: false`, so the model calls their tools directly and the transcript has each call's input and output. An `sse` server is refused at plan time (exit 2). Over ACP's `session/new`, OpenCode would offer them only through Code Mode, its `execute` tool.

OpenCode connects config MCP servers in the background once the session exists. ES runs `opencode acp` behind a small gate that holds the first prompt until each server has connected or failed (at most 30 seconds), so the first step has their tools.

## Errors

| Situation | Message |
|---|---|
| No model | `opencode(): needs a model, <provider>/<model>, e.g. opencode({ model: 'google/gemini-3.8-flash' }) (got …)` |
| A model without a provider (at plan time, exit 2) | `opencode(): an OpenCode model id names its provider, <provider>/<model>, such as 'google/gemini-3.8-flash' or 'anthropic/claude-haiku-4-5' (got "gemini-3.8-flash")` |
| A provider OpenCode doesn't know (exit 2) | `opencode(): OpenCode has no provider "…" (in "…"); a model id is <provider>/<model>, such as 'google/gemini-3.8-flash'` |
| A provider ES refuses (exit 2) | `opencode(): ES can't run OpenCode on Amazon Bedrock (amazon-bedrock): its AWS credentials sign each request (SigV4), and its API keys go to a host per AWS region, so the gateway can't keep its key out of the sandbox` |
| No key for the run's providers | `Missing credentials: ANTHROPIC_API_KEY. Set them in the environment or .env.local.` |
| A non-Docker sandbox | `The OpenCode harness needs the Docker sandbox` |
| An `mcp.sse` server (at plan time, exit 2) | `evaluate("<eval>") on opencode:<model>: OpenCode has no SSE MCP transport, so it can't use the <name> server (mcp.sse): use mcp.http or mcp.stdio` |
| OpenCode doesn't start | `OpenCode harness failed to start: …` |
| A model OpenCode's catalog doesn't have | The turn fails with `Invalid params: model not found: <provider>/<model>` |
| A key the API rejects | The turn fails with `The API rejected GOOGLE_GENERATIVE_AI_API_KEY: set a valid key in the environment or .env.local. ACP prompt update stream failed: Internal error: API key not valid. …`, naming the provider's variable |
