title: opencode()
description: The OpenCode 2 harness, its options and id, its Gemini API key, the tokens it can't report, its settings and how its MCP calls are recorded.
---

`opencode()` runs [OpenCode](https://opencode.ai) 2 in the Docker sandbox over its ACP server (`opencode acp`), on a Google model with a Gemini API key. `model` is required.

```ts title="es.config.ts"
import { defineConfig } from '{{ pkg }}'
import { opencode } from '{{ pkg }}/harness'

export default defineConfig({
  harness: opencode({ model: 'gemini-3.8-flash' }),
})
```

## Options

<Property name="model" type="string">
  A Gemini model id, such as `gemini-3.8-flash`, without a provider: ES runs it on OpenCode's `google` provider (`google/gemini-3.8-flash`), since a Gemini API key is the only key it's given. Required.
</Property>

<Property name="id" type="string" optional>
  The harness's id in cell keys, filters and the record. Default `opencode:<model>`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most OpenCode attempts at once across the run, for example for your key's rate limits.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long its session may take to become ready (bootstrap and session start) before the attempt is an infra error, such as `'3m'`. Default `'90s'`. A start that times out is aborted and started once more; a second timeout fails the attempt with `opencode: session did not become ready within 90s (tried twice)`, and the record's `startRetries` notes a retried start.
</Property>

## At a glance

| | |
|---|---|
| Import | `'{{ pkg }}/harness'` |
| Credential | `GOOGLE_GENERATIVE_AI_API_KEY` (a Gemini API key) |
| Adapter | `@evalsuite/harness-opencode` 0.2.0 (over `@ai-sdk/harness-acp`), bundled with ES |
| CLI | `@opencode/cli` 2.0.18 |
| Sandbox | `docker()` only |
| Image | `evalsuite-sandbox:opencode-0.2.0` |
| Rules file | `AGENTS.md` |
| Skills (default placement) | `~/.config/opencode/skills` |
| Skills (`placement: 'workspace'`) | `.opencode/skills` in the workspace |
| Egress hosts added | `generativelanguage.googleapis.com` |
| Tokens | Not reported (below) |

Build its image once with `es image build` in a project whose config uses `opencode()`.

## The key

ES passes `GOOGLE_GENERATIVE_AI_API_KEY` to the adapter explicitly, and it never enters the container. The gateway swaps it in on one kind of request, the one OpenCode 2.0.18 sends it on (its model, and the same model for session titles):

| Host | Endpoint |
|---|---|
| `generativelanguage.googleapis.com` | `POST /v1beta/models/<model>:streamGenerateContent` |

The adapter refuses to run in a sandbox that can't broker the key. `@ai-sdk/harness-opencode` brokers Anthropic, OpenAI and other keys but not a Google one, so ES uses its own thin config over `@ai-sdk/harness-acp` instead.

## Tokens

None are recorded: every turn's `usage` is `null`. OpenCode's ACP server reports its last model call's tokens as the turn's, not the turn's total (still so in 2.0.18), so ES records nothing rather than an undercount. Its `usage_update` doesn't help either: `used` is the last call's context size and `cost` the whole session's. The served model is still recorded, from the gateway's requests.

## Settings

ES starts OpenCode with this config, as `OPENCODE_CONFIG_CONTENT`, and with `OPENCODE_DISABLE_AUTOUPDATE=1` and `OPENCODE_DISABLE_MODELS_FETCH=1`, so the CLI stays the image's and its model catalog is the one it shipped with:

```json
{
  "update": "disable",
  "share": "disabled",
  "permissions": [
    { "action": "*", "resource": "*", "effect": "allow" },
    { "action": "websearch", "resource": "*", "effect": "deny" },
    { "action": "question", "resource": "*", "effect": "deny" },
    { "action": "browser", "resource": "*", "effect": "deny" }
  ],
  "agents": { "title": { "model": "google/<model>" } }
}
```

| Setting | Why |
|---|---|
| `update`, `share` | No self-update and no share links. |
| The `allow` rule | Every tool runs without asking, as on every harness. |
| `websearch` denied | It needs a search integration the sandbox doesn't have; every call would end "Web search cancelled". |
| `question` denied | It waits for a person to answer. |
| `browser` denied | Its tools drive a desktop browser. |
| `agents.title.model` | Session titles run on your model. OpenCode's default is a second one, `gemini-flash-lite-latest`. |

An `opencode.json` in the eval's files still loads. OpenCode reads `AGENTS.md`, not `CLAUDE.md`. Besides its own skill directories, it also reads `.claude/skills` and `.agents/skills` in the workspace and the home directory, and nothing turns that off, so keep other agents' skills out of an OpenCode eval's files.

## MCP servers

```json title="transcript.jsonl"
{"type":"tool","tool":"execute","input":{"code":"const result = await tools.stamp.house_stamp();…"},"output":{"metadata":{"toolCalls":[{"tool":"stamp.house_stamp","status":"completed"}],…},"output":"STAMP-7Q"},"ok":true,…}
{"type":"tool","toolCallId":"call_554042/0","tool":"mcp__stamp__house_stamp","input":{},"output":{"status":"completed"},"ok":true,…}
```

MCP servers are passed in ACP's `session/new` shape; OpenCode accepts `stdio` and `http` servers. An `sse` server is refused at plan time (exit 2). OpenCode offers the servers' tools only through Code Mode: its model writes JavaScript for its `execute` tool, which calls them. ES records the `execute` call, then each MCP tool it called as `mcp__<server>__<tool>`, with OpenCode's status for it but no input or output, which OpenCode doesn't report per call.

## Errors

| Situation | Message |
|---|---|
| No model, or one with a provider | `opencode() needs a Gemini model id, without a provider, since it runs on a Gemini API key, e.g. opencode({ model: 'gemini-3.8-flash' }) (got …)` |
| No key when the attempt starts | `GOOGLE_GENERATIVE_AI_API_KEY isn't set, so the OpenCode harness can't authenticate. Set it in the environment or .env.local.` |
| A non-Docker sandbox | `The OpenCode harness needs the Docker sandbox` |
| An `mcp.sse` server (at plan time, exit 2) | `evaluate("<eval>") on opencode:<model>: OpenCode has no SSE MCP transport, so it can't use the <name> server (mcp.sse): use mcp.http or mcp.stdio` |
| OpenCode doesn't start | `OpenCode harness failed to start: …` |
| A model OpenCode's catalog doesn't have | The turn fails with `Invalid params: model not found: google/<model>` |
| A key the API rejects | The turn fails with `The API rejected GOOGLE_GENERATIVE_AI_API_KEY: set a valid key in the environment or .env.local. ACP prompt update stream failed: Internal error: API key not valid. …` |
