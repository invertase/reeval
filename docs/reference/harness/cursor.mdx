title: cursor()
description: The Cursor harness, its options and id, the key it needs, how reeval brokers that key, and the tokens it reports.
---

`cursor({ model })` runs Cursor's agent in the Docker sandbox, through the Cursor TypeScript SDK. `model` is required.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { cursor } from '{{ pkg }}/harness'

export default defineConfig({
  harness: cursor({ model: 'composer-2.5', params: { fast: 'true' } }),
})
```

With no `harness` in the config, reeval uses `cursor({ model: 'composer-2.5' })`.

## Options

<Property name="model" type="string">
  The model the agent uses, as Cursor names it (`composer-2.5`). Required: the SDK has no default for local agents.
</Property>

<Property name="params" type="Record<string, string>" optional>
  Model parameters, by id, such as `{ fast: 'true' }`. They can change the price. A parameter you don't set takes the default variant in Cursor's model catalogue, which reeval sends explicitly: `composer-2.5` runs as `composer-2.5[fast=true]`, the Fast variant, unless you pass `{ fast: 'false' }`. Cursor can change that default, so pin every parameter for reproducible evals. Fast is not reasoning effort.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, mapped onto the catalogue param `Cursor.models.list()` names for this model (`reasoning_effort`, `effort`, …). Not Fast: that stays `params.fast`. The catalogue names the id; reeval does not hard-code it. If the catalogue lists no effort param, the attempt fails, saying so. Values are whatever that param takes. It isn't the measured [effort](/concepts/lift#effort-next-to-lift).
</Property>

<Property name="id" type="string" optional>
  The harness's id in cell keys, filters and the record. Default `cursor:<model>`, such as `cursor:composer-2.5`, or `cursor:<model>[effort=<value>]` when `effort` is set. Letters, digits and `.`, `_`, `:`, `@`, `+`, `-`, `[`, `]`, `=`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most Cursor attempts at once across the run, for example to stay under your account's rate limits. A whole number of at least 1.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long its session may take to become ready (bootstrap and session start) before the attempt is an infra error, such as `'3m'`. Default `'90s'`. A start that times out is aborted and started once more; a second timeout fails the attempt with `cursor: session did not become ready within 90s (tried twice)`, and the record's `startRetries` notes a retried start.
</Property>

## At a glance

| | |
|---|---|
| Import | `'{{ pkg }}/harness'` |
| Credential | `CURSOR_API_KEY` (a user or service-account API key) |
| Adapter | `@reeval/harness-cursor-sdk` 0.1.6, bundled with reeval |
| Sandbox | `docker()` only |
| Image | `reeval-sandbox:cursor-0.1.6` |
| Rules file | `AGENTS.md` |
| Skills (default placement) | `~/.agents/skills` |
| Skills (`placement: 'workspace'`) | `.cursor/skills` in the workspace |
| Egress hosts added | `api2.cursor.sh`, `*.cursor.sh` |
| Tokens | Reported per turn |

## How it runs

| Part | Where it runs |
|---|---|
| The agent loop and its tools | In the sandbox, in one Node runner per attempt, acting on the workspace |
| Inference | Cursor's hosted models |
| The model catalogue | Fetched on the host and handed to the runner, so the sandbox only talks to `api2.cursor.sh` |
| The agent's stream | Over HTTP/1.1, through the sandbox's proxy and egress gateway like every other request |

The runner serves all of an attempt's turns and keeps the agent loaded between them, so a follow-up turn starts quickly and keeps the conversation. If the runner stops, or a turn is aborted, the next turn resumes the same agent. The agent runs every tool without asking, inside the sandbox.

## The key

reeval reads `CURSOR_API_KEY` on the host and passes it to the adapter explicitly: a host AI Gateway key, subscription or keychain is never used. The key never enters the container, and the adapter refuses a sandbox that can't broker it. The agent sees a placeholder (`aisdkhc_…`), and the egress gateway swaps in the real key on one endpoint only:

| Host | Endpoint |
|---|---|
| `api2.cursor.sh` | `POST /auth/exchange_user_api_key` |

The SDK exchanges the key for session tokens. The gateway replaces the `accessToken` and `refreshToken` in that response with placeholders too, and swaps the real ones back, in headers only, on `cursor.sh` and its subdomains, including the agent's `BidiService/BidiAppend` stream. With `-v`, the attempt's log shows it:

```text
broker    CURSOR_API_KEY stays on the host · the gateway swaps it in on POST api2.cursor.sh/auth/exchange_user_api_key
…
gateway   POST https://api2.cursor.sh/auth/exchange_user_api_key → 200 · allowed · ↑2 B ↓956 B · 76ms · substituted CURSOR_API_KEY (authorization)
broker    substituted CURSOR_API_KEY (authorization) for api2.cursor.sh (POST https://api2.cursor.sh/auth/exchange_user_api_key)
…
gateway   POST https://api2.cursor.sh/aiserver.v1.BidiService/BidiAppend → 200 · allowed · ↑437 B ↓0 B · 57ms · substituted CURSOR_API_KEY accessToken
```

A request carrying the placeholder anywhere else gets a 403, and the attempt prints `warning: the egress gateway refused …`. See [Credential brokering](/concepts/credential-brokering).

## Tokens and transcripts

Each turn records its token `usage` and the model that served it, with its parameters (`composer-2.5[fast=true]`). The stack's `resolvedModels`, `summary.md`'s Harnesses row, `-v`'s turn line and the studio show the same resolved variant. The line under the result blocks totals the tokens. From `reeval run hello` in `examples/hello`:

```text
17s · 132k in (49k cached) · 1,489 out · results .reeval/runs/…/summary.md
```

See [Transcripts](/reference/transcript#tokens-and-the-served-model).

File edits are reported relative to the workspace, with line counts. Cursor's SDK leaves web search and fetch calls out of its stream: Cursor's backend runs them on its own servers. reeval's adapter recovers them after each turn from the agent's stored conversation, with the backend's own times, so they're normal `web-search` and `web-fetch` events.

When it can't (the store is unreadable, or the turn ended before the result), the turn has `unreported: ['web-search', 'web-fetch']`. The record's `activity.webSearches` and `webFetches` are then `null` rather than 0, and the web matchers refuse the turn.

## Skills, rules and MCP

| What | Where |
|---|---|
| Rules | `AGENTS.md` in the workspace |
| Skills | `~/.agents/skills`, or `.cursor/skills` in the workspace with `placement: 'workspace'`. The SDK loads both, as the Cursor CLI does |
| MCP servers | Passed to the agent on every turn |

## Errors

| Situation | Message |
|---|---|
| No `model` | `cursor() needs a model, e.g. cursor({ model: 'composer-2.5' })` |
| Bad `params` | `cursor({ params }) maps parameter ids to string values, e.g. { fast: 'false' } (got …)` |
| Bad `effort` | `cursor({ effort }) is the value that CLI takes, e.g. cursor({ effort: 'high' }) (got …)` |
| Catalog has no effort param | `Cursor's model catalog has no effort parameter for <model>. Fast is params.fast, not effort.` |
| No key, before the run | `Missing credentials: CURSOR_API_KEY, … Set them in the environment or .env.local.` |
| A key with a line break | `Credentials with whitespace or a line break in them: CURSOR_API_KEY (character 4). …` |
| A non-Docker sandbox | `The Cursor harness needs the Docker sandbox: set sandbox: docker() …` |
| The agent doesn't start | `Cursor harness failed to start: …` |
| Its image can't be built | `Baking the Cursor CLI onto reeval-sandbox-base:latest failed: …` (`reeval run` builds a missing image before the run) |
