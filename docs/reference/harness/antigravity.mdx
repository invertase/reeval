`antigravity()` runs Google's Antigravity CLI (`agy`) in the Docker sandbox, with a Gemini API key. `model` is required.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { antigravity } from '{{ pkg }}/harness'

export default defineConfig({
  harness: antigravity({ model: 'gemini-3.8-flash-medium' }),
})
```

## Options

<Property name="model" type="string">
  A model slug that `agy models` lists for a Gemini API key, such as `gemini-3.8-flash-medium`. Required, since the CLI's default changes under you.
</Property>

<Property name="id" type="string" optional>
  The harness's id in cell keys, filters and the record. Default `antigravity:<model>`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most Antigravity attempts at once across the run, for example for your key's rate limits.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long its session may take to become ready (bootstrap and session start) before the attempt is an infra error, such as `'3m'`. Default `'90s'`. A start that times out is aborted and started once more; a second timeout fails the attempt with `antigravity: session did not become ready within 90s (tried twice)`, and the record's `startRetries` notes a retried start.
</Property>

| Egress hosts added | `generativelanguage.googleapis.com` |

Build its image once with `reeval image build` in a project whose config uses `antigravity()`.

## The key

The harness uses a Gemini API key only, never the CLI's Google sign-in, which Google's terms don't allow automating. reeval passes `GEMINI_API_KEY` to the adapter explicitly, and it never enters the container. The gateway swaps it in on one kind of request (what CLI 1.2.17 sends it on: its model, and a lite one for titles):

| Host | Endpoint |
|---|---|
| `generativelanguage.googleapis.com` | `POST /v1beta/models/<model>:streamGenerateContent` |

The adapter refuses to run in a sandbox that can't broker the key, so it can't leak through a plain environment variable.

## Settings

reeval writes the CLI's settings with `enableTelemetry: false` and `modelProvider: 'gemini'`, and sets `AGY_CLI_DISABLE_AUTO_UPDATE=true` (`1` doesn't turn it off). MCP servers go to `~/.gemini/config/mcp_config.json`, where remote servers take `serverUrl`. The adapter appends its own instructions to `~/.gemini/GEMINI.md`.

The CLI reads home skills from `~/.gemini/config/skills`, not the `~/.gemini/antigravity-cli/skills` its docs give; reeval uses the path it reads.

## Telemetry it sends anyway

CLI 1.2.17 opens `play.googleapis.com` (telemetry) and `antigravity-unleash.goog` (feature flags) in every session. No setting stops them, and neither gets the key.

Under a restricted egress policy the gateway refuses them, records them under the record's `egress.expectedBlocked` rather than `blocked`, and `-v` prints one `gateway` line at teardown instead of one per request: `expected blocks, not logged per request:`, each `host:port` with its connection count, then the reason ("Antigravity's telemetry and feature flags, which its CLI sends even with telemetry off").

## Tokens

Each turn records the tokens the CLI reports and the model that served it. The summary totals them on its `Tokens` line and the record keeps them per turn, per attempt and for the run; reeval prices no models, so there's no USD. The CLI's `input_tokens` leaves out cache reads, as reeval's `input` does, so a turn served mostly from the cache records more `cacheRead` than `input`; the prompt was `input + cacheRead`. See [Transcripts](/reference/transcript#tokens-and-the-served-model).

## Prompt size

The CLI takes the prompt as a command-line argument, so it must stay under 128 KiB. A longer one fails the turn with the shell's `Argument list too long`.

## Errors

| Situation | Message |
|---|---|
| No `model` | `antigravity() needs a model, e.g. antigravity({ model: 'gemini-3.8-flash-medium' })` |
| No key when the attempt starts | `GEMINI_API_KEY isn't set, so the Antigravity harness can't authenticate. Set it in the environment or .env.local.` |
| A non-Docker sandbox | `The Antigravity harness needs the Docker sandbox` |
| The CLI doesn't start | `Antigravity harness failed to start: …` |
