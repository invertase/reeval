## pi

`pi()` is one harness factory. It runs pi in the sandbox on a Gemini API key, as one `pi --mode json` process per turn that resumes the session's conversation.

`pi()` is exported from `{{ pkg }}/harness`. The following configuration passes it as the `harness` option:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { pi } from '{{ pkg }}/harness'

export default defineConfig({
  harness: pi({
    model: 'gemini-3.8-flash',
  }),
})
```

`model` is required. The other fields are optional.

<Property name="model" type="string" required>
  A Gemini model id with no provider prefix, which pi runs on its `google` provider. reeval refuses an id with a provider prefix at plan time with exit code 2.
</Property>

<Property name="effort" type="string" optional>
  Reasoning effort, passed as pi's `--thinking` flag. The value is one that flag takes, such as `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`.
</Property>

<Property name="id" type="string" optional>
  Cell id. Defaults to `pi:<model>`, or `pi:<model>[effort=<value>]` with `effort` set. The id uses letters, digits, and `._:@+-=[]`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most pi attempts that run at the same time, across the run. A whole number of at least 1.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long the session may take to become ready before the attempt is an infra error, after one retry. A duration, such as `3m`. Defaults to `90s`.
</Property>

In the sandbox, pi runs in print mode with the project trusted, its startup network operations off, and no extensions loaded besides its built-in `mcp` one for the environment's MCP servers.

For more information about choosing a harness, see [Choose a harness](/harnesses).

For more information about model ids and effort values, see [Models and providers for each harness](/harnesses/models).

## Credential

`pi()` reads `GOOGLE_GENERATIVE_AI_API_KEY` from the host. In the sandbox, pi sees a placeholder as `GEMINI_API_KEY`, and reeval swaps the real key into the `x-goog-api-key` header on `POST /v1beta/models/<model>:streamGenerateContent` at `generativelanguage.googleapis.com`. reeval refuses the key anywhere else, and that host is the harness's automatic egress host.

For more information about keeping API keys on the host, see [Keep API keys on the host](/environments/secrets#keep-api-keys-on-the-host).

For more information about provider keys, see [Provider keys](/reference/env-vars#provider-keys).

For more information about the automatic hosts, see [Block non-automatic hosts](/environments/egress#block-non-automatic-hosts).

## Rules and skills

The pi harness reads rules from the `AGENTS.md` file in the workspace. The pi harness reads skills from the `.pi/skills` directory in the workspace, which pi loads because the harness trusts the project, and from the `~/.pi/agent/skills` directory in the home directory.

For more information about writing rules, see [Add project rules](/environments/rules).

For more information about placing skills, see [Give the agent skills](/environments/skills).

## MCP servers

The pi harness accepts MCP servers on `stdio` and `http`. reeval refuses an `sse` server, or a server name with characters other than letters, digits, `_`, and `-`, at plan time with exit code 2.

The servers go in pi's `~/.pi/agent/mcp.json` file with direct exposure, so the model and the transcript name each tool `mcp__<server>__<tool>`. reeval escapes `$` and a leading `!` in `env` and header values, so each value reaches the server as written.

For more information about placing MCP servers, see [Connect MCP servers](/environments/mcp).

## Recorded usage and model

The pi harness records tokens for each model call, reasoning tokens included, and each turn's `usage` is their sum. `usage` is null when pi reports none.

Each turn's `model` is the model pi names on its first assistant message. The attempt's `servedModels` comes from the brokered request URL, without an effort suffix.

For more information about the record fields, see [Run record reference](/reference/record).

## Web events

The pi harness records no `web-search` or `web-fetch` events. pi's built-in tools are `bash`, `read`, `write`, and `edit`, so `toHaveSearched` and `toHaveFetched` fail on a pi turn.

For more information about the web matchers, see [toHaveSearched](/reference/matchers#tohavesearched).
