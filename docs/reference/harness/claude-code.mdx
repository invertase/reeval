title: claudeCode()
description: The Claude Code harness, its options and id, the key it needs, and the endpoints reeval brokers it on.
---

`claudeCode()` runs the Claude Code CLI in the Docker sandbox. `model` is required.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'
import { claudeCode, cursor } from '{{ pkg }}/harness'

export default defineConfig({
  harness: [
    cursor({ model: 'composer-2.5' }),
    claudeCode({ model: 'claude-sonnet-5' }),
  ],
})
```

## Options

<Property name="model" type="string">
  A model id or alias the `claude` CLI accepts, such as `claude-sonnet-5` or `sonnet`. Required, since the CLI's default changes under you.
</Property>

<Property name="effort" type="'low' | 'medium' | 'high' | 'xhigh' | 'max'" optional>
  Reasoning effort the Agent SDK `/effort` control takes: `low`, `medium`, `high`, `xhigh` (Extra in the UI) or `max`. Adaptive thinking stays on. A value outside that set is refused. It isn't the measured [effort](/concepts/lift#effort-next-to-lift).
</Property>

<Property name="id" type="string" optional>
  The harness's id in cell keys, filters and the record. Default `claude-code:<model>`, or `claude-code:<model>[effort=<value>]` when `effort` is set.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most Claude Code attempts at once across the run, for example for your account's rate limits.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long its session may take to become ready (bootstrap and session start) before the attempt is an infra error, such as `'3m'`. Default `'90s'`. A start that times out is aborted and started once more; a second timeout fails the attempt with `claude-code: session did not become ready within 90s (tried twice)`, and the record's `startRetries` notes a retried start.
</Property>

## At a glance

| | |
|---|---|
| Import | `'{{ pkg }}/harness'` |
| Credential | `ANTHROPIC_API_KEY` |
| Adapter | `@ai-sdk/harness-claude-code` 1.0.158, with a fix reeval patches in (below) |
| Sandbox | `docker()` only |
| Image | `reeval-sandbox:claude-code-1.0.158-patch.6c1cff12` |
| Rules file | `CLAUDE.md` |
| Skills (default placement) | `~/.claude/skills` |
| Skills (`placement: 'workspace'`) | `.claude/skills` in the workspace |
| Egress hosts added | `api.anthropic.com`, `*.anthropic.com` |

Build its image once with `reeval image build` in a project whose config uses `claudeCode()`.

reeval ships the adapter with one fix, which its image bakes: 1.0.158 never reports the served model, because its bridge starts the stream on the `command_lifecycle` message Claude Code sends before `system/init`. With the fix, each turn records the model Claude Code used. The tag's `patch.6c1cff12` names that patch.

## The key

| Method | Path on `api.anthropic.com` |
|---|---|
| `POST` | `/v1/messages` |
| `POST` | `/v1/messages/count_tokens` |
| `GET` | `/api/claude_code/settings` |
| `GET` | `/api/claude_code/policy_limits` |

The harness authenticates only with `ANTHROPIC_API_KEY`, passed to the adapter explicitly. A host `AI_GATEWAY_API_KEY`, a Claude subscription login or a keychain entry is never used, so a run can't quietly bill a different account.

The key never enters the container. The gateway swaps it in on the endpoints above, the ones CLI 2.1.281 sends it on, and nowhere else.

A request carrying the placeholder anywhere else gets a 403 and a `warning: the egress gateway refused …` line, so a CLI update that needs a new endpoint fails loudly.

## Environment

reeval starts the CLI with two variables:

| Variable | Why |
|---|---|
| `IS_SANDBOX=1` | The CLI refuses to skip permission prompts as root otherwise. |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | No telemetry, error reporting or feature-flag fetches, so flags can't change between runs. |

The agent runs with every permission granted, inside the sandbox.

## Skills, rules and MCP

| What | Where |
|---|---|
| Rules | `CLAUDE.md` in the workspace |
| Skills | `~/.claude/skills`, or `.claude/skills` in the workspace with `placement: 'workspace'` |
| MCP servers | Passed to the CLI in the `.mcp.json` shape |

## Tokens

| The CLI reports, per model call | The turn records |
|---|---|
| Input tokens | `input` |
| Cache reads | `cacheRead` |
| Cache creation | `cacheWrite` |
| Output tokens | `output` |

The summary totals them on its `Tokens` line, and the record keeps them per turn, per attempt and for the run. See [Transcripts](/reference/transcript#tokens-and-the-served-model).

## Errors

| Situation | Message |
|---|---|
| No `model` | `claudeCode() needs a model, e.g. claudeCode({ model: 'claude-sonnet-5' })` |
| No key when the attempt starts | `ANTHROPIC_API_KEY isn't set, so the Claude Code harness can't authenticate. Set it in the environment or .env.local.` |
| A non-Docker sandbox | `The Claude Code harness needs the Docker sandbox: set sandbox: docker() …` |
| The CLI doesn't start | `Claude Code harness failed to start: …` |

A turn that the API rejects (no credit, for example) ends with `status: 'error'`, and the eval's next check fails. The turn line, the failure and `summary.md` show the API's message, without `-v`:

```text
[creates#1 claude-code]  +0:01 turn 1 error: Credit balance is too low to access the Anthropic API 1s · 0 tool calls, 0 file edits
…
 ✗ evals/hello.eval.ts › greet module › creates a tested greet module
   Error: expected file greet.js to exist
   turn 1 error: Credit balance is too low to access the Anthropic API
```
