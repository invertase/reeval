## The cascade

reeval applies the `reeval.config.ts` file, then the selected profile's `defaults`, then each enclosing `group()`, outermost first, then the `evaluate()` call. A profile `limit` then narrows `runs`, `compare`, and `harness`, except the keys in `pin`.

A later level replaces most keys, `compare` whole. `env` merges by name, `judge` and `question` field by field, `capture` shallowly, and `tags` and `pin` keep every value. `--runs` then replaces `runs`. `--tag` filters which evaluations run, and `--concurrency` caps the attempts running at once; neither changes an evaluation's options.

For more information about overriding an option, see [Group evaluations](/evaluations/task/groups#see-how-options-cascade).

## `include`

`include` lists the glob patterns for evaluation files, relative to the `reeval.config.ts` file's directory.

<Property name="include" type="string[]" optional>
  The default is `evals/**/*.eval.ts` and `evals/**/*.eval.py`.
</Property>

## `gateway`

`gateway` lists the gateways that serve model calls, in order of preference.

<Property name="gateway" type="GatewayDescriptor[]" optional>
  Helpers from `{{ pkg }}/gateway`: `direct()` is each provider's own key, `vercel()` is Vercel AI Gateway, and `openrouter()` is OpenRouter. The default is `[direct()]`. Each harness and judge model takes the first gateway that can serve it. reeval refuses a gateway listed twice, and a plan where no listed gateway can serve a model.
</Property>

A selected profile's [`gateway`](/reference/profiles#gateway) replaces this list.

A harness or a judge that names its own `gateway` skips the list's fallback. For more information about pinning a gateway, see [Route models through a gateway](/configuration/gateways#pin-one-gateway).

### `openrouter()` options

`openrouter()` takes one option. `direct()` and `vercel()` take none.

<Property name="fallbacks" type="boolean" optional>
  Lets OpenRouter fail over to another upstream provider when the one it picked can't serve a call. The default is `false`, so reeval's own calls, the judge, analysis, questions, and captures, send `allow_fallbacks: false`. The harnesses' calls take OpenRouter's own routing either way. The plan notes where it is on.
</Property>

For more information about OpenRouter, see [Route through OpenRouter](/configuration/gateways/openrouter).

## `harness`

`harness` names the agents that run an evaluation, one cell each.

<Property name="harness" type="HarnessOption | string[]" optional>
  The config and profile defaults accept a descriptor or list, which replaces inherited harnesses. Groups and evaluations also accept `{ add }`, `{ only }`, or, in TypeScript, a function of the inherited list. A profile `limit` lists allowed ids. reeval refuses `add` beside `only`, an empty resolved list, an unknown `only` id, and repeated ids among the resolved descriptors.
</Property>

The default is:

```ts
harness: cursor({ model: 'composer-2.5' })
```

For more information about harness forms, see [Choose an agent](/configuration/agents).

### Harness factory options

Each factory in this table runs an agent and requires `model`. All but `fx()` take an optional `effort`. reeval refuses a missing `model`, an `effort` the harness doesn't take, or an unknown option at plan time with exit code 2. For `id`, `maxConcurrent`, `startTimeout`, and `gateway`, see [Set the harness options](/configuration/agents#set-the-harness-options).

`fakeHarness()` runs no agent, so it is not in the table. It is for tests and dry runs, takes no `model`, and records an optional `effort` on the cell without sending it anywhere.

| Factory | `model` | `effort` |
|---|---|---|
| `cursor()` | A model id `Cursor.models.list()` returns for the key. | Mapped onto the catalog parameter the model names, `reasoning`, `reasoning_effort` or `effort`. A model with no such parameter refuses it at plan time. |
| `claudeCode()` | A model id or alias the `claude` CLI accepts. | `low`, `medium`, `high`, `xhigh`, or `max`, for the Agent SDK `/effort` control. The Claude Code UI labels `xhigh` as Extra. reeval refuses any other value, and any value on a model Claude Code sends none to, such as `claude-haiku-4-5`. |
| `antigravity()` | A slug `agy models` lists for the key, such as `<model>-medium`. A `-low`, `-medium`, or `-high` suffix sets effort in the slug, and reeval refuses `effort` beside one. | Passed as `agy --effort`, such as `low`, `medium`, `high`, or `max`. The cell's `effort` field copies it. |
| `codex()` | An OpenAI model id with no provider prefix, passed as `--model`. | Written as `model_reasoning_effort` in `~/.codex/config.toml`: `low`, `medium`, `high`, `xhigh`, `max`, or `ultra`. |
| `goose()` | A model id with no provider prefix, run on Goose's `google` provider, using letters, digits, `_`, `.`, and `-`. | Passed as `GOOSE_THINKING_EFFORT`: `off`, `low`, `medium`, `high`, or `max`. |
| `grokBuild()` | An xAI model id with no provider prefix, using letters, digits, and `._-`. | For a model that takes one, such as `low`, `medium`, or `high`. Set as `default_reasoning_effort` in Grok Build's `config.toml` file. |
| `opencode()` | `<provider>/<model>`. The part before the first `/` picks the provider and its key. reeval refuses a bare id, an unknown provider, or a provider whose key it can't broker. | A value the provider takes, added to each request body in the API's own field: `output_config.effort` on `anthropic/`, `reasoning.effort` on `openai/` and `openrouter/`, and Gemini's `thinkingLevel` on `google/` and `google-vertex/`. reeval refuses a value the model's API answers with a 400, such as any value on `anthropic/claude-haiku-4-5`, `openai/gpt-4.1` or `google/gemini-2.5-flash` and any but `high` on `openai/gpt-5-pro`, and any value on a provider with no field it knows. On `openrouter()`, which maps the effort onto each model itself, nothing is refused. |
| `pi()` | A Gemini model id with no provider prefix, which pi runs on its `google` provider. | Passed as pi's `--thinking` flag: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`. |
| `fx()` | A Vercel AI Gateway id, `<provider>/<model>`, or a bare OpenAI model id. | Not accepted. |

<Property name="params" type="Record<string, string>" optional>
  `cursor()` only. Parameter ids mapped to string values, such as `{ fast: 'true' }`. An unset parameter takes the default variant in Cursor's model catalog, which reeval sends on the request. `fast` is `'false'` when the model accepts it and `params` leaves it unset.
</Property>

### Common harness options

Every factory takes these options beside `model`.

<Property name="id" type="string" optional>
  Cell id. Defaults to the harness name followed by the model, such as `claude-code:<model>`, with `[effort=<value>]` added when `effort` is set. An id with a `/`, such as the `<provider>/<model>` id of `opencode`, keeps only the part after its last `/`, so `google/gemini-3.8-flash` gives `opencode:gemini-3.8-flash`. The id uses letters, digits, and `._:@+-=[]`.
</Property>

<Property name="maxConcurrent" type="number" optional>
  The most attempts of this harness that run at the same time, across the run. A whole number of at least 1.
</Property>

<Property name="startTimeout" type="Duration" optional>
  How long the session may take to become ready before the attempt is an infra error, after one retry. A duration, such as `3m`. Defaults to `90s`.
</Property>

<Property name="gateway" type="GatewayName | GatewayDescriptor" optional>
  The gateway this harness's model calls go through: `'direct'`, `'vercel'`, or `'openrouter'`, or the descriptor that `direct()`, `vercel()`, or `openrouter()` from `{{ pkg }}/gateway` returns. It skips the config's `gateway` fallback, and the plan refuses a gateway that isn't listed or can't serve the harness. For more information about routing, see [Route models through a gateway](/configuration/gateways).
</Property>

#### MCP servers

- **Cursor:** `stdio`, `http`, and `sse`, as `{ type: 'stdio', command, args, env }` or `{ type, url, headers }`.
- **Claude Code:** `stdio`, `http`, and `sse`, in the shape of the `.mcp.json` file: `{ type: 'stdio', command, args, env }` or `{ type, url, headers }`.
- **Antigravity:** `stdio`, `http`, and `sse`, in the `~/.gemini/config/mcp_config.json` file. A `stdio` server is `command`, `args`, and `env`, and an `http` or `sse` server is `serverUrl` and `headers`.
- **Codex:** `stdio` and `http`, under `[mcp_servers]` in the `~/.codex/config.toml` file. A `stdio` server is `command`, `args`, and `env`, and an `http` server is `url` and `http_headers`. A call is named `mcp__<server>__<tool>`. An `sse` server fails at plan time with exit code 2.
- **OpenCode:** `stdio` and `http`, written as `{ type: 'local', command: [command, ...args], environment }` or `{ type: 'remote', url, headers, oauth: false }` in OpenCode's configuration. Code Mode is off, so the agent calls the tools directly, and the first prompt waits until every server has connected. reeval refuses an `sse` server at plan time with exit code 2.
- **Goose:** `stdio` and `http`, written as enabled extensions in the `.config/goose/config.yaml` file under the private home directory `~/.ai-sdk-harness/.harness-bootstrap/goose/home`. A `stdio` server is `cmd`, `args`, and `envs`, and an `http` server is `uri` and `headers`, with type `streamable_http`. Goose keys each extension by dropping whitespace, replacing every character outside letters, digits, `_`, and `-` with `_`, and lower-casing the name. reeval refuses an `sse` server, or two servers that share a key, at plan time with exit code 2.
- **pi:** `stdio` and `http`, in the `~/.pi/agent/mcp.json` file with direct exposure, so the model and the transcript name each tool `mcp__<server>__<tool>`. reeval escapes `$` and a leading `!` in `env` and header values, so each value reaches the server as written. reeval refuses an `sse` server, or a server name with characters other than letters, digits, `_`, and `-`, at plan time with exit code 2.
- **fx:** `stdio`, `http`, and `sse`, passed on the ACP `session/new` call: a `stdio` server as `command`, `args`, and `env`, and an `http` or `sse` server as `type`, `url`, and `headers`. fx's `http` and `sse` servers, like its web tools, don't go through the relay. fx names an MCP call `mcp_<server>_<tool>`, which the transcript renames `mcp__<server>__<tool>`, so [`toHaveCalledMcp()`](/reference/matchers#tohavecalledmcp) matches it.
- **Grok Build:** `stdio`, `http`, and `sse`, passed on the ACP `session/new` call like fx. Grok Build calls a server's tool through its `use_tool` tool, which the transcript names `mcp__<server>__<tool>`, so [`toHaveCalledMcp()`](/reference/matchers#tohavecalledmcp) matches it.

For more information about placing MCP servers, see [Connect MCP servers](/configuration/environments/mcp-servers).

#### Token usage

Each turn's `usage` is null when the harness reports no tokens.

- **Cursor:** `input` excludes cache reads and writes, so the prompt total is `input` plus `cacheRead` plus `cacheWrite`. `reasoning` is part of `output`.
- **Claude Code:** tokens on each turn.
- **Antigravity:** `input` excludes cache reads, `cacheRead` holds those reads, and `cacheWrite` is 0. `output` includes thinking tokens, and `reasoning` holds that count.
- **Codex:** one `usage` for the turn. `input` is uncached input, and `cacheRead` and `cacheWrite` hold cached input. `reasoning` is part of `output`.
- **OpenCode:** one total for the whole turn.
- **Goose:** always null. The adapter drops the session token count, which covers the last model call and would undercount the turn.
- **pi:** the sum of each model call's tokens, reasoning tokens included.
- **fx:** summed over the turn's model calls. `reasoning` is part of `output`.
- **Grok Build:** summed over the turn's model calls. `input` excludes cache reads, so the prompt total is `input` plus `cacheRead`. `cacheWrite` records cache creation tokens, and `reasoning` is part of `output`.

For more information about the token fields, see [`TokenUsage`](/reference/run-record#tokenusage).

#### Served models

- **Cursor:** each turn's `model` is the served model with its parameters, in the form `model[param=value]`. The attempt's `servedModels` is null, because the API requests name no model.
- **Claude Code:** each turn's `model` is the model id Claude Code reports. `servedModels` is null, because the API requests name no model.
- **Antigravity:** each turn's `model` is the model the CLI reports at the start of the turn, or else the last brokered request's model. `servedModels` lists the model id in each brokered path `/v1beta/models/<model>:streamGenerateContent`, which can include a model the CLI calls for a title or a checkpoint.
- **Codex:** the egress gateway reads the served model and effort from the response body. The turn's `model` and `servedModels` hold `<model>` or `<model>[effort=<value>]`. `servedEffort` is the reasoning effort in that label, and `effort` is the factory value, or `medium` when unset.
- **OpenCode:** the stream names only the model OpenCode was configured with, so each turn's `model` is the model on the turn's last brokered request. `servedModels` comes from the request URL for a provider whose model path names the model (`amazon-bedrock/`, `google/`, `ofox/`, `opencode/` and `opencode-go/`) and from the response body for every other provider, with `[effort=<value>]` when the response names an effort.
- **Goose:** each turn's `model` is the model id from the last brokered `POST /v1beta/models/<model>:streamGenerateContent` request in the turn, or null when that turn made none. `servedModels` lists every such id.
- **pi:** each turn's `model` is the model pi names on its first assistant message. `servedModels` comes from the brokered request URL, without an effort suffix.
- **fx:** fx names only its configured model over ACP, so the egress gateway reads the served model from each response, such as the dated snapshot OpenAI answers `gpt-5.5` with. On Vercel AI Gateway, a stream that names no model, such as Gemini's, leaves `servedModels` null and records the model each call asked for in `askedModels`.
- **Grok Build:** the stream names only the configured model, so each turn's `model` and `servedModels` come from the model xAI's responses name.

For more information about the attempt fields, see [`AttemptRecord`](/reference/run-record#attemptrecord).

#### Web search and fetch events

A turn's `unreported` list names the events a harness can't report, and the matchers refuse a turn that lists their event.

- **Cursor:** records both. The SDK's stream leaves those calls out, so reeval recovers them from the stored conversation. A turn reeval can't recover lists the event on `unreported`. A call of any tool that the stream leaves running at the end of the turn takes its result from the stored conversation too, or stays `ok: null` when that has none.
- **Claude Code:** records both. A `webSearch` call records `query` and `references`, and a `webFetch` or `WebFetch` call records `url`. `ok` is false when a call fails.
- **Antigravity:** records both, with `unreported` empty.
- **Codex:** records both, with `unreported` empty. A search stores its text on `query`, and an `open_page` or `find_in_page` action with a URL is a fetch. A web action the turn ends without completing is a search with `ok` false. Codex sends each to `POST api.openai.com/v1/alpha/search` on the brokered key, so the transcript keeps each event under a restricted egress policy.
- **OpenCode:** records both, with `unreported` empty. A search runs on a hosted MCP server at `mcp.exa.ai`, which needs no key and is one of the harness's automatic egress hosts.
- **Goose:** records neither, and `unreported` is empty.
- **pi:** records neither. Its built-in tools are `bash`, `read`, `write`, and `edit`, so the matchers fail on a pi turn.
- **fx:** records both, from fx's `web_search` and `web_fetch` tools. A search stores its text on `query`.
- **Grok Build:** records searches, which run through its `web_search` tool on xAI's Responses API at `api.x.ai`, one of the harness's automatic egress hosts. It records no fetches, so `toHaveFetched()` fails on a Grok Build turn.

For more information about the matchers, see [`toHaveSearched()`](/reference/matchers#tohavesearched) and [`toHaveFetched()`](/reference/matchers#tohavefetched). For more information about the automatic hosts, see [Block non-automatic hosts](/configuration/environments/egress#block-non-automatic-hosts).

## `docker()`

`docker()` and `podman()` take these options. Each limit applies to one container, and reeval passes them to the container engine's run command (`docker run` or `podman run`) as `--memory`, `--memory-swap`, `--cpus`, and `--pids-limit`. For more information, see [Docker sandbox](/configuration/sandboxes/docker).

<Property name="docker.id" type="string" optional>
  The last segment of the cell key. The default begins with the engine's name, `docker`, or `podman` for `podman()`. A hash of `install` follows.
</Property>

<Property name="docker.maxConcurrent" type="number" optional>
  The most containers reeval runs at once across the run, whatever their image. A whole number of at least 1. The run's `concurrency` option still caps attempts overall.
</Property>

<Property name="docker.root" type="boolean" optional>
  Runs the agent, the setup commands, and the assertions as root, with the capabilities `apt-get` needs, instead of the unprivileged `reeval` user. Defaults to `false`.
</Property>

<Property name="docker.capabilities" type="string[]" optional>
  Linux capabilities to add back, such as `['NET_RAW']`, with or without the `CAP_` prefix. The container drops every other capability and runs with `no-new-privileges`.
</Property>

<Property name="docker.image" type="string" optional>
  An image that already has the harness baked in. reeval uses it as is. At most one of `image`, `from`, and `dockerfile`; without one, the container runs reeval's own image for the harness.
</Property>

<Property name="docker.from" type="string" optional>
  A Debian or Ubuntu based toolchain image, such as `python:3.12-slim`. reeval bakes Node, Git, and the harness on top on first use and caches the result. The image needs `apt-get` and glibc.
</Property>

<Property name="docker.dockerfile" type="string | URL" optional>
  A Dockerfile, relative to the file that calls `docker()`, absolute, or a `file:` URL. reeval builds it from its directory with `REEVAL_BASE` set to its sandbox image and caches the result by content hash. To layer on that image, start the Dockerfile with `ARG REEVAL_BASE` and `FROM ${REEVAL_BASE}`. A Dockerfile that starts from another Debian or Ubuntu image gets the harness baked on, as for `from`.
</Property>

<Property name="docker.install" type="(string | { run: string; timeout?: Duration })[]" optional>
  Shell commands baked onto the base image in one cached layer. They run as root from `/`, in order, and see neither secrets nor the workspace. `install` combines with `from`, not with `dockerfile`: put those commands in the Dockerfile as `RUN` lines.
</Property>

<Property name="docker.memory" type="string | number" optional>

</Property>

<Property name="docker.swap" type="string | number" optional>

</Property>

<Property name="docker.cpus" type="number" optional>

</Property>

<Property name="docker.pids" type="number" optional>

</Property>

## `egress`

`egress` is where the sandbox may connect. An environment accepts it too.

<Property name="egress" type="'proxy' | 'allow-all' | 'deny-all' | { allow: string[] }" optional>
  `'proxy'` (the default) allows any host over HTTP and HTTPS through the egress gateway, `'allow-all'` also allows raw TCP and UDP around the gateway, `'deny-all'` blocks all but the automatic hosts, and `{ allow }` adds hosts to them. A group or an evaluation overrides the environment, which overrides the inherited policy.
</Property>

A plain `allow` entry matches that host only. A `*.` entry matches every subdomain, not the apex domain itself, and never an IP address. The gateway carries HTTP and HTTPS only, so SSH and database clients get no network under every policy but `'allow-all'`. Under `'allow-all'`, raw traffic leaves the sandbox directly, unfiltered and unrecorded, and the record marks the attempt's egress `partial`.

Spread [`DEFAULT_EGRESS_ALLOW`](/reference/authoring-api#defaultegressallow) into an `allow` list that still installs packages.

For more information about the automatic hosts, see [Egress](/configuration/environments/egress).

<Property name="compare" type="CompareOptions | false | { maxVariants: number }" optional>
