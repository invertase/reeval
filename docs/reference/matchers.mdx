title: Matchers
description: The three matchers ES adds to expect, what they accept, and the failure messages they print.
---

ES adds `toHaveFile`, `toSucceed` and `toPass` to `expect`, which you import from `'{{ pkg }}'`.

```ts title="evals/greet.es.ts"
import { evaluate, expect } from '{{ pkg }}'

evaluate('creates a tested greet module', async (t) => {
  const turn = await t.send('Create greet.js exporting greet(name).')
  await expect(turn).toHaveFile('greet.js', /export/)
  await expect(t.exec('node --check greet.js')).toSucceed()
  expect(await t.judge('Is greet.js small and readable?')).toPass()
})
```

`expect` is Vitest's, so its own matchers (`toBe`, `toContain`, `toMatch`, `toHaveLength`, `.not`, …) work too. A failed matcher fails the attempt.

## toHaveFile

```ts
await expect(turnOrT).toHaveFile(path, pattern?)
```

<Property name="actual" type="Turn | EvalContext">
  A turn from `t.send()`, or `t` itself. Both read the sandbox as it is now.
</Property>

<Property name="path" type="string">
  Workspace-relative, or `~/` for the home directory.
</Property>

<Property name="pattern" type="RegExp | string" optional>
  What the file must contain. A string matches when the file includes it; a `RegExp` when it matches. Without it, the file only has to exist.
</Property>

It's async, so `await` it. Failure messages:

```text
expected file greet.js to exist
```

```text
expected greet.js to match /welcome/
--- greet.js ---
<the file's last 20 lines>
```

Anything else as `actual` throws `toHaveFile() expects a turn from t.send(), or t`.

## toSucceed

```ts
await expect(t.exec(command)).toSucceed()
```

<Property name="actual" type="Promise<ExecResult> | ExecResult">
  What `t.exec()` or `turn.exec()` returns, awaited or not. It passes when `exitCode` is 0.
</Property>

It's async, so `await` it. On failure it shows the tail (last 20 lines) of both streams:

```text
expected command to succeed, exit code 1
--- stderr ---
…
--- stdout ---
…
```

Anything else throws `toSucceed() expects run.exec(...)`.

## toPass

```ts
expect(await t.judge(question)).toPass()
```

<Property name="actual" type="Verdict">
  A verdict from `t.judge()`. It passes when the verdict is `pass`: the score is at least the threshold.
</Property>

It's synchronous: await the judge, not the matcher. Failure messages:

```text
judge score 0.95 is below 0.99 for "Is greet.js small and readable?" (fake)
```

With `.not`, a passing verdict fails with `expected judge to fail: score … ≥ …`. Anything but a verdict throws `toPass() expects a t.judge() verdict`.
