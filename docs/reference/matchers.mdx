title: "Matchers reference"
description: "expect, expect.soft, and expect.poll assert on an attempt's files, commands, and strings, with matchers reeval adds."
---

Each matcher reads a turn from `c.send()`, the attempt context `c`, a `c.exec()` result, or a `c.judge()` verdict. Passed `c`, a transcript matcher reads every turn so far.

For more information about standard matchers, see [Vitest's `expect` reference](https://vitest.dev/api/expect).

For more information about checking an attempt, see [Assertions](/evaluations/grading/assertions).

## `expect()`

`expect(actual, label?)` checks `actual`.

```ts
const turn = await c.send('Add a test for getUserId.')
expect(turn, 'edited the test').toHaveEdited('src/user.test.ts')
await expect(c.exec('npm test'), 'tests pass').toSucceed()
```

<Property name="actual" type="unknown" required>
  The subject. Each matcher names the subjects it accepts. On any other subject, the matcher is a type error in the editor and throws a `TypeError` when the eval runs.
</Property>

<Property name="label" type="string" optional>
  The assertion's name in the output and the run record. Without a label, the name is the matcher and its first argument, such as `toHaveEdited src/user.test.ts`, or the command or question the subject carries. A repeated name gets a ` #2` or ` #3` suffix.
</Property>

`.not` inverts the matcher. `toHaveFile()` returns a promise, and so does `toSucceed()` on the promise `c.exec()` returns. On an awaited exec result, `toSucceed()` checks at once. An unawaited asynchronous assertion fails the attempt and names the assertion and its line, such as ``expect(…).toHaveFile() at evals/user.eval.ts:12 wasn't awaited``.

A reeval matcher on a subject it doesn't take doesn't typecheck. The error names the subjects the matcher takes:

```text
error TS2349: This expression is not callable.
  Type 'WrongSubject<"toPass() takes the verdict from await c.judge()">' has no call signatures.
```

<Info>
TypeScript can't flag a missing `await`. A linter with type information can: typescript-eslint's `@typescript-eslint/no-floating-promises` rule flags an unawaited `toHaveFile()` or `expect(c.exec(…)).toSucceed()`.
</Info>

## `expect.soft()`

`expect.soft(actual, label?)` records a failure and lets the body continue. The attempt fails at its end on the first soft assertion that did not pass. Soft assertions take the same matchers as `expect()`, including async ones; await those.

```ts
    await expect.soft(c, 'uses fromPartial').toHaveFile(
      'src/user.test.ts',
      /fromPartial\(/,
    )
```

The arguments are those of `expect()`.

## `expect.poll()`

`expect.poll(fn, options?)` calls `fn` and the matcher until the matcher passes, then resolves. It fails with the matcher's last error when `timeout` runs out. `fn` may return a promise.

```ts
    await expect
      .poll(() => c.readFile('build.log'), { timeout: 5000 })
      .toContain('done')
```

<Property name="fn" type="(options: { signal: AbortSignal }) => T" required>
  Returns the subject for one try, or a promise of it. `signal` aborts when `timeout` runs out.
</Property>

<Property name="options.interval" type="number" optional>
  Milliseconds between tries. Defaults to `50`.
</Property>

<Property name="options.timeout" type="number" optional>
  Milliseconds before the assertion fails. Defaults to `1000`.
</Property>

<Property name="options.message" type="string" optional>
  The label, as `expect()` takes it.
</Property>

## `toHaveFile()`

`toHaveFile(path, pattern?)` reads a file from the workspace or sandbox home directory. The subject is a turn from `c.send()` or `c`.

```ts
    await expect(turn, 'has the test').toHaveFile(
      'src/user.test.ts',
      /describe\('getUserId'/,
    )
```

<Property name="path" type="string" required>
  A workspace-relative path, or a `~/` path in the sandbox home directory.
</Property>

<Property name="pattern" type="string | RegExp" optional>
  Text the file contains, or a regular expression it matches. Without a pattern, the assertion passes when the file exists.
</Property>

When an existing file does not match `pattern`, the failure message ends with its last 20 lines, up to 2,000 characters. A missing file failure says that the file at `path` does not exist.

## `toSucceed()`

`toSucceed()` passes when the command's `exitCode` is `0`. The subject is the result of `c.exec()`, or its promise. On a result, `toSucceed()` checks at once. On the promise, it returns a promise to `await`.

```ts
    expect(await c.exec('npm run build'), 'builds').toSucceed()
    await expect(c.exec('npx vitest run'), 'tests pass').toSucceed()
```

The failure message names the exit code and ends with the last 20 lines of `stderr` and `stdout`.

## `toPass()`

`toPass()` passes when the judge's `verdict` is `'pass'`. The subject is the verdict `c.judge()` resolves to, so await the call first.

```ts
    const verdict = await c.judge('Does the test cover a missing user?')
    expect(verdict).toPass()
```

A failed judge call answers nothing, so `toPass()` and `.not.toPass()` both fail. A failed judge call reports the question, model, and error. A fail verdict reports the score, threshold, question, and model. A negated pass verdict reports the score, threshold, and question.

## `toHaveChanged()`

`toHaveChanged(paths?)` reads the workspace diff, including every write by a tool, shell command, or subprocess. The subject is a turn from `c.send()`, whose diff is cumulative over the turns before it, or `c`, which reads the latest turn's diff.

```ts
    expect(turn, 'changed a test').toHaveChanged(['test', '*.test.ts'])
```

<Property name="paths" type="string | RegExp | ReadonlyArray<string | RegExp>" optional>
  A glob, a regular expression, or a list of either. A glob matches dotfiles and every file under the directory it names, so the `test` path pattern also matches the `test/user.test.ts` file. A leading `./` and a trailing `/` are ignored. Without `paths`, any change passes.
</Property>

The assertion passes when at least one changed file matches one of the patterns. When no file matches, the failure message lists every changed file with its status. A negated failure lists only the matching files.

## `toHaveEdited()`

`toHaveEdited(path?)` reads the transcript's `file-edit` events. With a `path`, a tool call whose target or output mentions the path counts too. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'edited the test').toHaveEdited('src/user.test.ts')
```

<Property name="path" type="string | RegExp" optional>
  Text the edited path contains, or a regular expression it matches. Without a path, any `file-edit` event passes.
</Property>

## `toHaveRun()`

`toHaveRun(command?)` reads the transcript's shell tool calls, the ones named `bash` or `shell`. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'ran vitest').toHaveRun(/vitest/)
```

<Property name="command" type="string | RegExp" optional>
  Text the call's `command` input contains, or a regular expression it matches. Without a command, any shell call passes.
</Property>

The failure message lists every shell command the agent ran.

## `toHaveCalledTool()`

`toHaveCalledTool(name, input?)` reads the transcript's tool calls by the name in the transcript, with an MCP call named `mcp__<server>__<tool>`. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'read the schema').toHaveCalledTool(
      /read/i,
      'prisma/schema.prisma',
    )
```

<Property name="name" type="string | RegExp" required>
  The tool's name, or a regular expression it matches. A string must equal the name.
</Property>

<Property name="input" type="string | RegExp | Record<string, unknown>" optional>
  Text the call's input contains, a regular expression it matches, or an object. For an object, each expected key matches the corresponding input value. A string equals or is contained in the value, a regular expression tests it, and anything else compares as JSON. Text matching serializes a non-string input as JSON.
</Property>

The failure message lists every tool call, with its input when `input` is given.

## `toHaveCalledMcp()`

`toHaveCalledMcp(server, tool, input?)` passes when the transcript has a call to the tool named `mcp__<server>__<tool>`, which is how reeval names an MCP server's tools whatever the harness calls them. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'called the server').toHaveCalledMcp('docs', 'search', {
      query: /getUserId/,
    })
```

<Property name="server" type="string" required>
  The server's name, as the environment's `mcp` field declares it.
</Property>

<Property name="tool" type="string" required>
  The tool's name on that server.
</Property>

<Property name="input" type="string | RegExp | Record<string, unknown>" optional>
  The call's input, as `toHaveCalledTool()` takes it.
</Property>

The failure message lists every MCP call as `server/tool`.

## `toHaveCalledSkill()`

`toHaveCalledSkill(name)` passes when the agent loaded the skill. A load is a `skill`, `Skill`, or `load_skill` tool call whose `id` or `name` input is the skill's name, or any tool call whose target path, pattern, command, or URL includes the `skills/<name>/` path. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'used the skill').toHaveCalledSkill('api-conventions')
```

<Property name="name" type="string" required>
  The skill's directory name.
</Property>

The failure message lists every skill-like call, such as a read under a `skills/` directory.

## `toHaveSearched()`

`toHaveSearched(query?)` reads the transcript's `web-search` events. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'searched the docs').toHaveSearched(/vitest/i)
```

<Property name="query" type="string | RegExp" optional>
  Text the search query contains, or a regular expression it matches. Without a query, any web search passes.
</Property>

`toHaveSearched()` refuses a turn whose `unreported` lists `web-search`, and it refuses `c` when any turn so far lists `web-search`, since the harness did not report searches and the agent may have searched with no event. The refusal throws a `HarnessCapabilityError`, and the record marks the assertion as an error rather than a failure.

For more information about the error, see [`HarnessCapabilityError`](/reference/authoring-api#harnesscapabilityerror).

## `toHaveFetched()`

`toHaveFetched(url?)` reads the transcript's `web-fetch` events. The subject is a turn from `c.send()` or `c`.

```ts
    expect(turn, 'fetched the docs').toHaveFetched('example.com')
```

<Property name="url" type="string | RegExp" optional>
  Text the fetched URL contains, or a regular expression it matches. Without a URL, any web fetch passes.
</Property>

`toHaveFetched()` refuses a turn whose `unreported` lists `web-fetch`, and it refuses `c` when any turn so far lists `web-fetch`. The refusal throws a `HarnessCapabilityError`.

For more information about the same error, see [`toHaveSearched()`](/reference/matchers#tohavesearched).
