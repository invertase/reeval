---
title: es doctor
description: Check that a project is ready to run, with a fix for every problem.
---

`es doctor` checks what `es run` needs, without running anything, and prints the fix for each problem. It exits 0 when nothing failed and 1 when something did.

```bash
npx es doctor
npx es doctor --online --json
```


## Output

A real run in a project from `es init --yes`, before Docker was started or a key was set:

```text
es doctor · es.config.ts
✓ node       22.14.0 (ES needs >=22.13)
✓ config     es.config.ts: harness cursor:composer-2.5, sandbox docker, profiles fake, pr, nightly
✗ docker     isn't running, and the config's sandboxes need it
             fix: start Docker Desktop, or the Docker service (sudo systemctl start docker)
- image      Docker isn't running
✗ key        CURSOR_API_KEY for cursor:composer-2.5: not set
             fix: add CURSOR_API_KEY=... to .env.local
- judge      no judge model (t.judge needs one)
✓ egress     allow-all: the agents reach any host (the default); evals and environments may set their own
✓ gitignore  .env* and .es/ are ignored

2 problems, 0 warnings. Fix them and run es doctor again.
```

`✓` passed, `!` is a warning (exit 0), `✗` is a problem (exit 1), and `-` was skipped.

## Checks

| Check | Problem (`✗`) | Warning (`!`) |
|---|---|---|
| `node` | Older than the package's `engines` | |
| `config` | No `es.config.*` here or above, or it doesn't load | |
| `docker` | Not running, when a sandbox in the config or a profile is `docker()` | Under 4 GB of memory, one attempt's default limit |
| `image` | ES's sandbox image for a configured harness isn't built, or a `docker({ image })` isn't in Docker | Images for this harness from another ES version |
| `key` | A config harness's key isn't set, has whitespace in it, or (`--online`) its API rejects it | A key only a profile's harness needs isn't set; `--online` couldn't reach the API |
| `judge` | The judge model's key isn't set | The same, for a profile's judge |
| `egress` | A sandbox can't enforce its policy, such as a restricted policy on `fakeSandbox()` | |
| `gitignore` | `.env*` isn't ignored | `.es/` isn't ignored |

Keys come from the environment and the `.env.local` and `.env` beside the config, as `es run` reads them. `es doctor` names each key but never prints its value, in text or JSON.

When images are missing and `es doctor` runs in a terminal, it offers to build them with `es image build`.

## --online

```text
✗ key        CURSOR_API_KEY for cursor:composer-2.5: set, but api.cursor.com rejects it (HTTP 401)
             fix: set a valid CURSOR_API_KEY in .env.local
```

With `--online`, each key goes in one request to its API, only in a header: `GET /v0/me` on `api.cursor.com`, `GET /v1/models` on `api.anthropic.com`, `GET /v1beta/models` on `generativelanguage.googleapis.com` and `GET /v1/models` on `api.openai.com`. HTTP 401 or 403 is a problem. Other keys, such as `TYPESAFE_AI_API_KEY`, are only checked for being set.

## --json

```json
{
  "healthy": false,
  "problems": 2,
  "warnings": 1,
  "config": "es.config.ts",
  "checks": [
    { "id": "node", "status": "ok", "summary": "22.14.0 (ES needs >=22.13)" },
    …
  ]
}
```

`status` is `ok`, `warn`, `fail` or `skip`; a check with a fix has `fix`.
