---
title: reeval report
description: Collect a redacted bug report about reeval, review it locally, then file it as a GitHub issue.
---

`reeval report` collects what a maintainer needs to debug reeval: versions, `reeval doctor`, your config's shape, the last command's error and stack, and the run's failures with their debug logs. Everything is redacted. It prints a summary and writes the report on your machine; nothing is uploaded until you file it.

```bash
npx reeval report                 # summary, and the report in .reeval/reports/<time>/
npx reeval report --out bug.md    # bug.md, bug.json and bug-logs.tar.gz
npx reeval report --issue         # then a pre-filled GitHub issue
```

The run is `latest` unless you name one (see [run references](/reference/cli#run-references)). With `--last`, it's the run of the last `reeval` command that failed, when that was `reeval run`.

| File | Holds |
|---|---|
| `report.md` | Everything below, to read and attach to the issue |
| `report.json` | The same as one JSON document (`kind: "reeval-report"`); `--json` prints it |
| `report-logs.tar.gz` | Each failing attempt's `.reeval/debug` files, redacted; only when there are some |

## What it collects

| Part | What | What it leaves out |
|---|---|---|
| Versions | reeval, Node, npm, the package manager (from `npm_config_user_agent` or the lockfile), OS and architecture, CI and coding agent | |
| Variables | Names of the `REEVAL_*` and secret-looking variables that are set | Every value |
| Last command | Its arguments, exit code, duration, run and, when it failed, its error and stack | Flag values and arguments, shown as `<value>` and `<arg>` |
| `reeval doctor` | Every check, as `reeval doctor --json` without `--online` | |
| Config | The option keys it sets, its harness and sandbox kinds, and each profile's name and keys | Every value, model and path |
| Run | Its outcome and counts, `stack` from the record (reeval, packages, images, harnesses, judge), and up to 5 failing attempts: the error, turn errors, the last lines of `debug.log` and `trace.ndjson`, and refused or failed gateway requests | The trace's `config` entries, which hold the config's values |

reeval logs the last 20 `reeval` commands in `.reeval/cli.jsonl`, redacted, in a project that has an `.reeval/` folder. That's where the last command comes from.

## Redaction

```text
Outcome infra_error.
infra: agent failed: key [REDACTED] in <project>
```

Every string in the report goes through the same masking as a run record: the values of secret-looking variables and `secret()` values, raw or JSON-, URL- or base64-encoded, any stretch of 8 or more of their characters, and well-known token shapes. On top of that, every value in `.env.local` and `.env` of 8 or more characters is masked, whatever its name. Then your project folder becomes `<project>` and your home folder `~`. The `redacted` line counts every `[REDACTED]` in the report and its attached logs, one per place a value was masked, and says how many reeval had masked already in the records and logs it read.

<Warning>
  Read `report.md` before you share it. The failure messages and logs are your agent's and your evals' own output, and redaction only catches what looks like a secret.
</Warning>

## --issue

```text
Open this to file the issue (pre-filled; nothing is sent until you submit it):
https://github.com/invertase/reeval/issues/new?template=bug_report.yml&title=reeval%20run%3A%20infra%3A%20agent%20failed…
```

`--issue` writes the report as above, then opens reeval's bug-report form in your browser with the title and the summary filled in. The URL stays under 8,000 characters: a long summary is cut at a line and says to attach `report.md`. Drag `report.md` and `report-logs.tar.gz` into the issue.

With [`gh`](https://cli.github.com) installed, it asks first, then files the issue with `gh issue create` (the body is `issue.md` in the report's folder). `-y` answers yes. Without a terminal to ask in and without `-y`, it prints the URL. The repository comes from `bugs` in reeval's `package.json`.

## The hint

```text
hint: if this looks like a bug in reeval, reeval report collects a redacted report to file (REEVAL_NO_REPORT_HINT=1 hides this)
```

After an infra error (exit 3), a crash, an error reeval didn't expect, or an error a run reports that no eval owned, `reeval` prints this line on stderr. It doesn't in agent output, with `--json`, or with `REEVAL_NO_REPORT_HINT=1`.
