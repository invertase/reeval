---
title: es history, show, compare, checkout
description: Read recorded runs, diff two of them and reproduce one.
---

Four commands read the history: recorded runs, plus unrecorded scratch runs where noted.

```bash
npx es history             # pass/fail per eval across runs
npx es show latest --md    # one run as Markdown
npx es compare             # latest vs its nearest recorded ancestor
npx es checkout latest     # a worktree at that run's commit
```

## es history

{/* generated:cli-help:history */}
```text
es history [filter]       Pass/fail per recorded eval over recent runs
                          --limit <n> --all (include unrecorded runs) --json
```
{/* /generated:cli-help:history */}

The filter is a case-insensitive substring of the eval id. Runs go oldest to newest, left to right.

```text
2 runs, oldest → newest: 20260926T173922Z_7e5376d_ada-lovelace_31fh (7e5376d) … 20260926T173923Z_7e5376d_ada-lovelace_t2ea (7e5376d)

  ✓✓    2/2  evals/hello.es.ts › greet module › creates a tested greet module
  ✓✓    2/2  evals/hello.es.ts › greet module › adds a default name in a follow-up turn
…
✓ pass  ✗ fail  ! infra error  ↓ skipped  · not run  ¦ eval or stack changed
```

`¦` marks a run where the eval's fingerprint changed from the last run that had the same cell, so a filtered run and the full run after it don't count as a change.

## es show

{/* generated:cli-help:show */}
```text
es show [run]             One run: table, --md (summary.md) or --json (the record)
```
{/* /generated:cli-help:show */}

The default output is a state table (commit, dirty patch, lockfiles, images, harnesses, environments, judge, agent context, packages, runner), then a line per eval. `--md` prints the run's `summary.md`; `--json` prints the record.

## es compare

{/* generated:cli-help:compare */}
```text
es compare [base] [head]  Diff two runs; base defaults to head's nearest recorded ancestor
                          --md --json --fail-on-regression
```
{/* /generated:cli-help:compare */}

- **Defaults:** head is `latest`. Base is the nearest recorded, complete run on head's git ancestry, falling back to the previous run by time.
- **Statuses:** `regressed`, `fixed`, `changed (not comparable)`, `infra error`, `new`, `removed` and `same`.
- **Not comparable** means a fingerprint part or the grader changed, and ES says which: `not comparable: evals/helpers.ts changed`.
- **Filtered runs:** when base and head ran different cells of an eval, the eval is classified on the cells both ran, and the rest are listed (`same · cells removed: …`). With no cell in common, it's not comparable.
- `--md` prints a `### ES: head vs base` heading and a table for a PR comment. `--json` returns `{ base, head, changes, rows }`.
- `--fail-on-regression` exits 1 when any eval regressed. Without it, `es compare` exits 0.

```text
base 20260926T173923Z_7e5376d_ada-lovelace_t2ea (7e5376d) → head 20260926T173927Z_7e5376d_ada-lovelace_j03w (7e5376d, not recorded)
0 regressed · 0 fixed · 0 not comparable · 10 same

  ✓ → ✓  same                      evals/hello.es.ts › greet module › creates a tested greet module
…
```

## es checkout

{/* generated:cli-help:checkout */}
```text
es checkout [run] [dir]   A git worktree at the run's commit, with its worktree.patch applied
                          (default dir: .es/checkouts/<run>)
```
{/* /generated:cli-help:checkout */}

It runs `git worktree add --detach` at the run's commit, then applies the run's `worktree.patch` if it was dirty. Remove the worktree with `git worktree remove <dir>`.

<Warning>
  The default directory is inside `.es/`. Deleting `.es/` leaves a stale worktree entry until you run `git worktree prune`.
</Warning>
