---
title: reeval init
description: Scaffold a project with a config, a passing eval, profiles and .gitignore entries.
---

`reeval init` sets up reeval in the current directory, or in the directory you name. It asks which agent to configure, then writes a project whose eval passes on the fake agent straight away. `reeval run` and `reeval image build` need that config file: with none found they exit 2 and point here.

```bash
npx reeval init
npx reeval init evals --harness claude-code
```

## Flags

```text
reeval init [dir]             Scaffold a project in dir (default: here): reeval.config.ts, a passing
                              eval, .gitignore entries and a package.json script; asks which agent
  --harness <name>            cursor, claude-code, antigravity, opencode, goose, pi, codex, fx,
                              grok-build or none (fake agent only); the config's harness, with a
                              fake profile for no keys
  -y, --yes                   Don't ask: take the defaults (--harness cursor)
  --force                     Overwrite reeval.config.ts and the eval when they differ
  --dry-run                   Print what it would create or change, and write nothing
```

[//]: # (/generated:cli-help:init)

It only asks in a terminal. In a script or CI, pass `--harness` or `--yes`; without either, it exits 2.

## What it writes

A real `reeval init --yes` in an empty directory:

```text
reeval init · .
  create    reeval.config.ts       harness cursor:composer-2.5; profiles fake, pr, nightly
  create    evals/greet.eval.ts  one eval, passes on the fake agent
  create    .gitignore         .reeval/, .env*
  create    package.json       script eval, devDependency {{ pkg }}
Next:
  npm install
  npx reeval run --profile fake  passes now: the fake agent, no keys or Docker
  npx reeval image build         bakes Cursor into its sandbox image (needs Docker)
  npx reeval run                 on Cursor, with CURSOR_API_KEY in .env.local
```

| File | What `reeval init` does |
|---|---|
| `reeval.config.ts` | The chosen agent in `docker()`, with profiles `fake` (the fake agent and sandbox), `pr` (one attempt per cell, the CI default) and `nightly` (three, recorded). With `--harness none`, the fake agent is the config's harness. |
| `evals/greet.eval.ts` | One deterministic eval: the agent writes `greet.js`, and a command checks it |
| `.gitignore` | Appends `.reeval/` and `.env*` when they're missing |
| `package.json` | Adds an `eval` script (`reeval run`) and {{ pkg }} as a devDependency, unless it has them; creates the file when there's none |

## Existing files

`reeval init` plans every file before it writes one. When `reeval.config.ts` or the eval exists and differs, or another `reeval.config.*` exists, it exits 2 and writes nothing:

```text
reeval: reeval init won't overwrite files in .: reeval.config.ts exists and differs. Nothing was written. Pass --force to overwrite them.
```

`--force` overwrites them. It never removes lines from `.gitignore` or keys from `package.json`, and a second `reeval init` with the same answer changes nothing: each file says `keep`.
