`reeval record` copies runs from `.reeval/runs/` into the history folder, so you can commit them.

```bash
npx reeval record              # the latest run
git add evals/.history && git commit -m "Record eval run"
```

```text
reeval record [run...]        Copy runs (default: latest) from .reeval/runs into the history folder
                              --artifacts all|failures|none --allow-incomplete --skip-secret-scan
```

## Behaviour

- **Default run:** `latest`. Pass one or more [run references](/reference/cli#run-references) to record others.
- **Where:** the config's `history.dir`, by default `.history/` next to your evals (`evals/.history/` for the default `include`).
- **Idempotent:** recording a run that's already recorded does nothing.
- **Refusals** (exit 2): an interrupted or budget-stopped run, unless `--allow-incomplete` (`reeval run` records a budget-stopped run itself when it records); and any file that still looks like a secret after redaction, `worktree.patch` included, unless `--skip-secret-scan`.
- **Artifacts:** `--artifacts` overrides the config's `history.artifacts` for this copy: `all` (every attempt's files), `failures` (only failing attempts') or `none` (the record only).

A real record, after a run:

```text
recorded evals/.history/20260926T174005Z_b010670_ada-lovelace_xdb9.json + 9 artifact files in evals/.history/20260926T174005Z_b010670_ada-lovelace_xdb9/ (32.7 KB). Commit it with git.
```

## Recording automatically

`record` in `reeval.config.ts` (or a profile) picks when `reeval run` records by itself:

| Value | Records |
|---|---|
| `'ci'` (default) | When `CI` is set |
| `'always'` | Every run |
| `'manual'` | Only with `reeval run --record` or `reeval record` |

reeval never commits or pushes. Records are immutable once written, and file names sort by time, so branches that record runs merge without conflicts.
