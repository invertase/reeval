---
title: reeval query
description: Read-only SQL over every recorded and scratch run, with every view and table.
---

`reeval query` answers questions across runs with SQL. It reads `.reeval/history.db`, a gitignored SQLite projection of every record in the history folder and `.reeval/runs/`.

```bash
npx reeval query lift
npx reeval query "SELECT eval_key, variant, points, lo, hi FROM lift
  WHERE within_noise = 0"
```

## Behaviour

- **Argument:** a view or table name runs `SELECT * FROM <name>`. Anything else is a SQL statement. No argument lists the views and tables with examples.
- **Read-only, one statement at a time.**
- **Always current:** each query re-reads only records that are new or changed. A recorded run wins over its scratch copy. `--rebuild` rebuilds the database from scratch, and you can delete it at any time.
- **Output:** an aligned table, or JSON rows with `--json`. The sync line (`history.db: 13 runs`) goes to stderr, so output pipes cleanly.
- **Needs** Node 22.13 or later (`node:sqlite`).

A real query (`points`, `lo` and `hi` are fractions: 1 is +100 points):

```text
eval_key                                                   harness                              variant              variant_pass  variant_counted  control_pass  control_counted  points  lo    hi  within_noise
…
evals/skill.eval.ts › house greeting › greets in the house…  cursor:composer-2.5                  with-house-greeting  2             2                0             2                1       0.07  1   0
```

| View | One row per |
|---|---|
| `lift` | Variant cell per run: its control, both sides' counts, points, the 95% interval (`lo`, `hi`), `within_noise`, `min_lift` |
| `effort` | Cell per run: attempts, median and quartiles of tool calls, agent seconds and tokens; for a variant, its control's medians, the ratios, the exact Mann–Whitney p-values and verdicts. `tokens_verdict` is null when either side has no usage sample |
| `factor_effects` | One factor's contrast (`environment`, `harness`, `model`) by evidence tier (`controlled`, `pooled`, `observed`, `not_measured`), with pass-rate and effort verdicts |
| `skill_reads` | Attempt and skill its environment placed: the transcript line of its first read (a path under `skills/<name>/`, or a `skill` / `load_skill` call), and how many |
| `flaky_cells` | Cell with mixed outcomes pooled over comparable runs: counts, a Wilson interval, a verdict (`flaky` from 6 counted attempts) and a likely cause (`infra`, `judge`, `check` when the same change both passed and failed, else `agent`) |
| `drift` | Run where a cell's fingerprint changed from its previous run, the parts and context paths that changed, and `noise = 1` when only an agent CLI's own runtime state changed |
| `failing_attempts` | Failed or infra-error attempt, with the skill of its environment (joined by digest), harness, model, error and `oom_kills` (processes killed at the sandbox's memory limit) |
| `eval_trend` | Eval per run: outcome, pass rate, branch, PR and fingerprint |
| `contrasts` | Pair of arms on one harness and sandbox in a run, when an eval has two variants or more (a variant against the control, and variant against variant): pass counts, lift of `a` over `b`, effort ratios and verdicts, and the checks that tell them apart |
| `question_pairs` | Compare question and pair of sides (arms within a harness, `held`; harnesses across an arm): runs voted, wins when both orders agree (or one ties), ties, and `splits`, pairs whose two orders picked opposite sides (`splits_first`: to the side shown first both times) |
| `context_use` | Attempt and tool-call class: `context` (a placed skill, rules file or MCP tool), `dependency` (`node_modules`, `site-packages`, `vendor`, `.venv`, `--help`), `web`, `verify` (a check's command, or a test, build, lint or typecheck) or `workspace`, with the count, the first call's line and an example target. The classes are a heuristic over tool names and paths |
| `skill_files` | Attempt and file its environment declared (each skill's files, rules and config): how many tool calls opened it, directly or through a glob, and the first one's line (`NULL`: never opened) |

In the text table, `·` is SQL `NULL`; `--json` has `null`. On `factor_effects`, a `pooled` row has `run_id` `NULL` (it spans runs), and a row pooled across evals (with `strata` set and `runs` `NULL`) has `eval_key` and `runs` `NULL` too.

Several views repeat a cell's key across evals in a run, so join `attempts` and `cells` on `eval_key` as well as `cell_key`; on `cell_key` alone each attempt matches every eval's cell of that key and is counted once per eval.
| `verdict_flips` | Judge question per cell whose pass rate changed from its previous run |
