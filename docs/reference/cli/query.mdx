`es query` answers questions across runs with SQL. It reads `.es/history.db`, a gitignored SQLite projection of every record in the history folder and `.es/runs/`.

```bash
npx es query lift
npx es query "SELECT eval_key, variant, points, lo, hi FROM lift WHERE within_noise = 0"
```

## Help

{/* generated:cli-help:query */}
```text
es query [sql | view]     Read-only SQL over every recorded and scratch run (.es/history.db,
                          rebuilt from the records); views: lift, flaky_cells, drift,
                          failing_attempts, eval_trend, verdict_flips. No argument lists them
  --json                  Rows as JSON; --schema every table and column; --rebuild from scratch
```
{/* /generated:cli-help:query */}

## Behaviour

- **Argument:** a view or table name runs `SELECT * FROM <name>`. Anything else is a SQL statement. No argument lists the views and tables with examples.
- **Read-only, one statement at a time.**
- **Always current:** each query re-reads only records that are new or changed. A recorded run wins over its scratch copy. `--rebuild` rebuilds the database from scratch, and you can delete it at any time.
- **Output:** an aligned table, or JSON rows with `--json`. The sync line (`history.db: 13 runs`) goes to stderr, so output pipes cleanly.
- **Needs** Node 22.13 or later (`node:sqlite`).

A real query:

```text
eval_key                                                   harness              variant              variant_pass  variant_counted  control_pass  control_counted  points  lo      hi  within_noise
…
evals/skill.es.ts › house greeting › greets in the house…  cursor:composer-2.5  with-house-greeting  2             2                0             2                1       0.07    1   0
```

| `lift` | `run_id`, `started_at`, `branch`, `eval_key`, `harness`, `model`, `variant`, `control`, `variant_pass`, `variant_counted`, `control_pass`, `control_counted`, `points`, `lo`, `hi`, `within_noise`, `min_lift`, `outcome`, `fingerprint` |
| `verdict_flips` | `run_id`, `prev_run_id`, `eval_key`, `cell_key`, `judgement_key`, `question`, `prev_pass_rate`, `pass_rate`, `n` |
{/* /generated:query-views */}

| View | One row per |
|---|---|
| `lift` | Variant cell per run: its control, both sides' counts, points, the 95% interval (`lo`, `hi`), `within_noise`, `min_lift` |
| `flaky_cells` | Cell and fingerprint whose attempts disagreed within a run: how often, first and last seen |
| `drift` | Run where a cell's fingerprint changed from its previous run, with the parts that changed |
| `failing_attempts` | Failed attempt, with the skill of its environment (joined by digest), harness, model and error |
| `eval_trend` | Eval per run: outcome, pass rate, branch, PR and fingerprint |
| `verdict_flips` | Judge question per cell whose pass rate changed from its previous run |
