---
title: "Check an app"
description: "Verify what the agent-built app displays."
---

A file check can't tell you whether a page renders. The `nextApp` environment must contain the app project before you start. For more information about the `nextApp` environment, see [Environments](/environments).

Check the app the agent built in this order.

1. Start the app in the sandbox with `c.serve`.
2. Capture a page with `c.capture`.
3. Send the capture to the judge.

## Start a server

`c.serve` starts a command in the background and returns its port. reeval allocates a free port and sets it as `PORT`, so a server that reads `PORT` listens where reeval expects it. In the `evals/sign-in.eval.ts` file, build and start the app:

```ts title="evals/sign-in.eval.ts"
import { evaluate, expect } from '{{ pkg }}'
import { nextApp } from './environments.ts'

evaluate(
  'the sign-in page shows an email and a password field',
  { environment: nextApp },
  async (c) => {
    await c.send('Add a /login page with email and password fields.')
    await expect(c.exec('npm run build'), 'builds').toSucceed()
    const app = await c.serve('npm start')
    const shot = await c.capture(app, { path: '/login', wait: 'idle' })
    const q = 'Does the screenshot show an email field and a password field?'
    expect(await c.judge(q, { artifacts: [shot] }), 'two fields').toPass()
  },
)
```

For more information about every argument `c.serve` takes, see [`c.serve`](/reference/context#cserve).

## Run a background command

`c.exec` with `{ background: true }` starts a command the same way, without a port. It returns a handle with `kill()` only, so use a foreground `c.exec` for anything you assert on. After the server starts, in the `evals/sign-in.eval.ts` file, start a worker:

```ts title="evals/sign-in.eval.ts"
const worker = await c.exec('npm run worker', { background: true })
// ...
await worker.kill()
```

## Check the running app

`c.exec` runs in the sandbox, so a request to `localhost` on the server's port reaches the app. `c.serve` returns as soon as the command starts, so retry until the server answers. In the `evals/sign-in.eval.ts` file, check the page over HTTP:

```ts title="evals/sign-in.eval.ts"
const url = `localhost:${app.port}/login`
await expect(
  c.exec(`curl -fsS --retry 10 --retry-connrefused ${url}`),
  'serves /login',
).toSucceed()
```

`-f` makes an HTTP error a non-zero exit code, which fails `toSucceed`. To assert on the body, read `stdout` from the `c.exec` result.

## Capture a page

`c.capture` takes a `ServeHandle` or a port and opens a path on it in a headless browser on your machine through a tunnel to the sandbox. `c.capture` saves the image at the `artifacts/<name>.png` path in the attempt record. The sandbox image needs no browser, because reeval downloads one into its cache on the first capture.

`path` defaults to `/`. For the `/login` path, `name` defaults to the `login.png` filename, and a name can't repeat in one attempt. `wait` defaults to `'load'`; use `'idle'` to wait until there are no pending network requests, or `{ ms: 500 }` to wait a fixed time.

In the `evals/sign-in.eval.ts` file, name a second capture:

```ts title="evals/sign-in.eval.ts"
const error = await c.capture(app, {
  name: 'login-error',
  path: '/login?error=1',
})
```

To interact with the page before the capture, pass `instructions` as goal strings, which a vision model from `capture.model` drives. For more information about every field, see [`c.capture`](/reference/context#ccapture).

## Set the viewport and browser

In the `evals/sign-in.eval.ts` file, set the capture width and height:

```ts title="evals/sign-in.eval.ts"
{ environment: nextApp, capture: { viewport: { width: 390, height: 844 } } },
```

For more information about every key, see [the `capture` option](/reference/options#capture).

## Judge a capture

The `artifacts` field on `c.judge` sends captures to the judge as images: the handles from `c.capture`, their names, or `true` for every capture so far. The default evaluation model takes PNG captures, and a provider that can't take files fails the call. Ask what the picture shows, such as a field or a label, not whether it looks good.

In the `evals/sign-in.eval.ts` file, send both captures:

```ts title="evals/sign-in.eval.ts"
const q = 'Does the error page keep both fields and show one error message?'
expect(await c.judge(q, { artifacts: true }), 'error state').toPass()
```

For more information about the judge, its model, and its threshold, see [Judges](/evals/judges).

In a compare, a question shows each side's own capture when `artifacts` names the captures, or is `true`, on the question or the `question` option, so the model sees the control's page beside the variant's. For more information about compare questions, see [Compare](/comparisons/compare#ask-which-did-better).
