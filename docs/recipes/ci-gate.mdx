---
title: "Fail a pull request"
description: "Fail a pull request when an evaluation regresses."
---

Fail a pull request when a variant misses the minimum lift, or when an evaluation regresses. For a runnable project, see [`with-github-pr-gate`](https://github.com/invertase/reeval/tree/main/examples/with-github-pr-gate).

## Gate pull requests

<Steps>
<Step title="Size the profile">

Add a `pr` profile to the `reeval.config.ts` file. A run uses it when `CI` is set to anything other than `false` and you omit `--profile`.

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'

export default defineConfig({
  defaultProfile: { ci: 'pr' },
  profiles: {
    pr: {
      budget: { attempts: 20 },
    },
  },
})
```

`budget.attempts` caps the plan. The profile sets no `limit`, so the variant still runs. For more information about profiles, see [Profiles](/runs/profiles).

</Step>
<Step title="Require a minimum lift">

The `evals/shoehorn.eval.ts` file compares a baseline `plain` with a variant `withShoehorn`, as in [Measure a skill](/recipes/skill-comparison). Set `compare.minLift` on its comparison:

```ts title="evals/shoehorn.eval.ts"
-  { runs: 4, compare: { baseline: plain, variants: [withShoehorn] } },
+  {
+    runs: 4,
+    compare: { baseline: plain, variants: [withShoehorn], minLift: 0.25 },
+  },
```

`compare.minLift` is the smallest lift you accept, from -1 to 1. The variant fails when the low end of its lift interval is below `0.25`, and its row adds `not by minLift 25`, even when the effect reads `helped`. `reeval run` then exits 1, and the job fails.

Only the variant's cells decide the outcome by default, so a baseline that fails its assertions does not fail the run. For more information about the other `compare.gate` values, see [Gate on lift](/results/compare/lift#gate-on-lift).

</Step>
<Step title="Add the workflow">

Add the workflow that runs the `pr` profile, records each run, and commits the history directory. For more information about the workflow file, the API key, and the record step, see [CI](/runs/ci).

</Step>
<Step title="Fail on a regression">

In the workflow, run the regression check after the run is recorded:

```bash
npx reeval compare --fail-on-regression
```

`reeval compare` diffs the run against the newest recorded run on an ancestor commit, so it needs the history directory the record step commits. It exits 1 when an evaluation `regressed`. For more information about the other results that exit 1, see [Compare with past runs](/results/compare/past-runs).

</Step>
<Step title="Read the job summary">

When the run finishes, `reeval run` appends the run's `summary.md` file to the job summary, so the variant's row and its `not by minLift 25` show on the pull request's checks. To print the same summary on your machine, run:

```bash
npx reeval show --md
```

For more information about the command, see [Show one run](/results/output#show-one-run).

</Step>
</Steps>
