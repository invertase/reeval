---
title: "Measure MCP servers"
description: "See whether an MCP server helped your harness."
---

You measure an MCP server by running one task on a baseline with no server and a variant with the server. The effect reads `helped`, `made it worse`, or `can't tell yet`. For more information about adding MCP servers, see [Connect MCP servers](/environments/mcp).

The example server is `releases`, a stdio server that knows the latest `acme-cli` release.

## Run one task with and without the server

<Steps>
<Step title="Define the environment with the server">

In the `evals/environments.ts` file, define the environment. It copies the project and the server's script into the workspace, and starts the server in the sandbox:

```ts title="evals/environments.ts"
import { defineEnvironment } from '{{ pkg }}'

export const app = defineEnvironment(
  'acme-cli',
  ({ directory, file, mcp }) => ({
    files: {
      ...directory('./project'),
      'mcp/releases.mjs': file('./mcp/releases.mjs'),
    },
    mcp: { releases: mcp.stdio('node', ['mcp/releases.mjs']) },
  }),
)
```

</Step>
<Step title="Write the evaluation">

In the `evals/releases.eval.ts` file, declare the evaluation. `toHaveCalledMcp` fails the attempt when the harness never calls the server's tool, and the file assertion decides whether the task was done:

```ts title="evals/releases.eval.ts"
import { evaluate, expect } from '{{ pkg }}'
import { app } from './environments.ts'

evaluate('bumps to the latest release', { environment: app }, async (c) => {
  const turn = await c.send(
    "Set package.json's version to the latest acme-cli release. " +
      "The releases MCP server's latest_version tool knows it.",
  )

  expect(turn).toHaveCalledMcp('releases', 'latest_version')
  await expect(turn).toHaveFile('package.json', /"version": "2\.4\.0"/)
})
```

For more information about the matcher, see [`toHaveCalledMcp`](/reference/matchers#tohavecalledmcp). For a runnable project, see [`with-mcp`](https://github.com/invertase/reeval/tree/main/examples/with-mcp).

</Step>
<Step title="Run and read the call">

Run the evaluation with the harness named in the `reeval.config.ts` file:

```bash
npx reeval run releases
```

The attempt's `transcript.jsonl` file, under `.reeval/runs/<run>/`, names the call `mcp__<server>__<tool>`, which is what `toHaveCalledMcp` matches:

```text
{"turn":0,…,"type":"tool","toolCallId":"call_1","tool":"mcp__releases__latest_version","input":{},"output":"acme-cli 2.4.0","ok":true,"durationMs":178}
```

</Step>
<Step title="Compare with a baseline">

To measure what the server changed, run the same evaluation on a baseline without `mcp`, and the environment with the server as the variant ([Measure lift against a baseline](/results/compare/lift)). Set `runs: 4`, because below four counted attempts a side the effect reads `can't tell yet`.

The baseline has no server, so `toHaveCalledMcp` fails on every baseline attempt. Read the file assertion's row for the task. When the file assertion passes on both sides, the harness finds the version without the server, and this task can't show what the server changed. For more information about the rows, see [Read the results summary](/results/output).

</Step>
</Steps>
