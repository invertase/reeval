title: Table-driven evals
description: Write one eval body and run it over a list of cases with evaluate.for.
---

**Goal:** check the same kind of task over many inputs without copying the eval for each one.

`evaluate.for(cases)` registers one eval per case. Each gets its own name, id, cells and history, and the body receives the case as its second argument.

## The file

```ts title="evals/strings.eval.ts"
import { evaluate, expect } from '{{ pkg }}'

const cases = [
  { fn: 'slugify', input: 'Hello World', want: 'hello-world' },
  { fn: 'camelCase', input: 'hello big world', want: 'helloBigWorld' },
  { fn: 'titleCase', input: 'hello world', want: 'Hello World' },
]

evaluate.for(cases)('writes $fn', async (c, item) => {
  await c.send(
    `Create ${item.fn}.js exporting ${item.fn}(text) as an ES module. ` +
      'Add a package.json with "type": "module". No dependencies.',
  )
  const run = await c.exec(
    `node -e "import('./${item.fn}.js')` +
      `.then((m) => console.log(m.${item.fn}('${item.input}')))"`,
  )
  await expect(run).toSucceed()
  expect(run.stdout.trim()).toBe(item.want)
})
```

`$fn` in the name becomes each case's `fn`, so the three evals are `writes slugify`, `writes camelCase` and `writes titleCase`.

## Run it

```bash
npx reeval run strings --dry-run
```

## Name placeholders

| Placeholder | Becomes | Example name |
|---|---|---|
| `$key` | That property of an object case; left as is when the case has no such key | `'writes $fn'` → `writes slugify` |
| `%s` | A string case as is; any other case as JSON | `'documents install with %s'` → `documents install with pnpm` |
| `%#` | The case's index, from 0 | `'case %#'` → `case 0` |

With a list of strings, `%s` is all you need:

```ts title="evals/managers.eval.ts"
import { evaluate, expect } from '{{ pkg }}'

evaluate.for(['npm', 'pnpm', 'yarn'])(
  'documents install with %s',
  { tags: ['docs'] },
  async (c, pm) => {
    const turn = await c.send(
      `Write INSTALL.md explaining how to install lodash with ${pm}.`,
    )
    await expect(turn).toHaveFile('INSTALL.md', new RegExp(`${pm} (add|i)`))
  },
)
```

Options go between the name and the body, as with `evaluate`, and apply to every case.

<Warning>
  Give every case a distinct name. Two cases that render to the same name become one eval with twice the attempts, and the plan doesn't warn. Avoid `%#` as the only difference too: reordering the list renames the evals and starts their history again.
</Warning>

## Checks per case

A case is any value, so it can carry its own checks. Optional fields add a check only where you need it:

```ts title="evals/percase.eval.ts"
import { evaluate, expect } from '{{ pkg }}'

type Case = { fn: string; check: string; question?: string }

const cases: Case[] = [
  { fn: 'slugify', check: 'node -e "import(\'./slugify.js\')"' },
  {
    fn: 'camelCase',
    check: 'node -e "import(\'./camelCase.js\')"',
    question: 'Does the reply explain how camelCase treats extra spaces?',
  },
]

evaluate.for(cases)('exports $fn', async (c, item) => {
  await c.send(`Create ${item.fn}.js exporting ${item.fn}(text).`)
  await expect(c.exec(item.check)).toSucceed()
  if (item.question) expect(await c.judge(item.question)).toPass()
})
```

```text
 evals/percase.eval.ts
   ✓ exports slugify           76ms  1 turn
   ✓ exports camelCase         83ms  judge 0.95  1 turn
…
```

## Options per case

`evaluate.for` shares one set of options. When cases need different options (tags, a sandbox, a timeout), a plain loop works, since `evaluate` is an ordinary function:

```ts title="evals/percase.eval.ts"
for (const pm of ['npm', 'pnpm']) {
  evaluate(`adds lodash with ${pm}`, { tags: [pm] }, async (c) => {
    await c.send(`Add lodash to this project with ${pm}.`)
  })
}
```

```bash
npx reeval run --tag pnpm --dry-run
```

```text
plan  1 eval · 1 cell · 1 attempt · ~3m 00s serial
eval                                         harnesses  variants  runs  attempts  notes
evals/percase.eval.ts › adds lodash with pnpm  1          —         1     1
```

## Variations

- **Cases in their own module:** `import { cases } from './cases.ts'`. reeval records every local file an eval imports among its sources, so an edit to the list shows up when you [compare runs](/guide/history).
- **Inside a group:** `evaluate.for` works in `group(…)`, and the group's options (`compare`, `runs`, `environment`) apply to every case.
- **Competitors:** see [Check a recommendation](/recipes/recommendation) for one judge-only eval per competitor.
