description: Give the agent the toolchain your task needs, from an official image, extra packages or your own Dockerfile.

**Goal:** run evals whose tasks need more than Node: Python, a CLI tool, a seeded database or a heavy SDK such as Flutter.

What's baked into the image belongs to the [sandbox](/guide/sandboxes), `docker()`. ES adds what the agent needs on top of it: Node, git and the harness's CLI.

| You need | Use | Example |
|---|---|---|
| A language's official image | `docker({ from })` | Python |
| A few packages on ES's image | `docker({ install })` | `jq` |
| Files, a database, several steps | `docker({ dockerfile })` starting `FROM ${ES_BASE}` | SQLite |
| A large SDK image | `docker({ from })` with a longer timeout | Flutter |

All three of the first examples are in `examples/hello`.

## Python from the official image

```ts title="evals/python.es.ts"
import { evaluate, expect } from '{{ pkg }}'
import { docker } from '{{ pkg }}/sandbox'

// A non-Node toolchain: ES bakes Node (for the harness bridge) and the Cursor CLI onto the
// official Python image the first time this runs, then reuses it.
evaluate(
  'writes and tests fizzbuzz in python',
  { sandbox: docker({ from: 'python:3.12-slim', id: 'python' }) },
  async (t) => {
    await t.send(
      'Write fizzbuzz.py with a function fizzbuzz(n) returning the usual FizzBuzz string for n, ' +
        'and test_fizzbuzz.py with unittest tests for 3, 5, 15 and 7. Standard library only.',
    )
    await expect(t.exec('python3 --version')).toSucceed()
    await expect(t.exec('python3 -m unittest -q')).toSucceed()
  },
)
```

`from` takes any Debian or Ubuntu based image. `id: 'python'` names the sandbox in cell keys (`cursor:composer-2.5/-/python`).

## Packages on ES's image

```ts title="evals/jq.es.ts"
import { evaluate, expect } from '{{ pkg }}'
import { docker } from '{{ pkg }}/sandbox'

const withJq = docker({
  install: [
    'apt-get update && apt-get install -y --no-install-recommends jq && rm -rf /var/lib/apt/lists/*',
  ],
})

evaluate('summarises a JSON file with jq', { sandbox: withJq }, async (t) => {
  await t.send(
    'Write orders.json with five orders (id, customer, total), then count.sh, a bash script that ' +
      'prints the number of orders over 100 using jq. Make it executable.',
  )
  await expect(t.exec('jq --version')).toSucceed()
  await expect(t.exec('./count.sh')).toSucceed()
})
```

`install` commands run once, as root, with no secrets and no workspace. ES caches the result by the base image and the exact command list, so any edit builds a new layer.

## Your own Dockerfile

```dockerfile title="docker/sqlite/Dockerfile"
ARG ES_BASE
FROM ${ES_BASE}

RUN apt-get update \
  && apt-get install -y --no-install-recommends sqlite3 \
  && rm -rf /var/lib/apt/lists/*

COPY seed.sql /opt/seed.sql
```

```ts title="evals/sqlite.es.ts"
import { evaluate, expect } from '{{ pkg }}'
import { docker } from '{{ pkg }}/sandbox'

evaluate(
  'queries a seeded SQLite database',
  { sandbox: docker({ dockerfile: '../docker/sqlite/Dockerfile' }) },
  async (t) => {
    await t.send(
      'Load /opt/seed.sql into app.db with sqlite3, then write report.sql that lists customer ' +
        'names alphabetically, one per line.',
    )
    const report = await t.exec('sqlite3 app.db < report.sql')
    await expect(report).toSucceed()
    expect(report.stdout).toBe('Ada\nGrace\nLinus\n')
  },
)
```

ES passes `--build-arg ES_BASE=<ES's image for the harness>`, so `FROM ${ES_BASE}` layers on an image that already has the agent's CLI. The path is relative to the eval file, and the build context is the Dockerfile's directory.

## A heavy SDK: Flutter

Large toolchain images work the same way. This one was checked with `--dry-run` only:

```ts title="evals/flutter.es.ts"
import { evaluate, expect } from '{{ pkg }}'
import { docker } from '{{ pkg }}/sandbox'

const flutter = docker({
  from: 'ghcr.io/cirruslabs/flutter:3.38.10',
  id: 'flutter',
})

evaluate(
  'adds a counter widget test',
  { sandbox: flutter, timeout: '20m' },
  async (t) => {
    await t.send(
      'Create a Flutter app called counter with flutter create, then ' +
        'add a widget test that taps the + button twice and expects 2.',
    )
    await expect(t.exec('cd counter && flutter test')).toSucceed()
  },
)
```

```text
images  1 sandbox image (nothing built: --dry-run)
flutter · 1 eval
  from ghcr.io/cirruslabs/flutter:3.38.10  evalsuite-sandbox:cursor-1.0.37-ghcr-io-cirruslabs-flutter-3-38-10-ef09bba3  (rebuild: Node, git and the harness bootstrap on top)
```

- Pin the tag. A moving tag (`stable`) changes the toolchain between runs.
- Image builds and setup steps don't count towards `timeout`, but `flutter create` and the first `flutter test` inside the turn do, so give the eval room.
- An idle agent container takes about 300 MB, and an SDK's builds take far more. Lower `--concurrency` on small machines.

<Warning>
  Keep the image's user as `root` and leave `/es` alone: ES's bootstrap and the harness live there. `install` doesn't combine with `dockerfile`; put those commands in the Dockerfile as `RUN` lines.
</Warning>

## Variations

- **An image that already has the harness:** `docker({ image: 'ghcr.io/acme/agent:1' })` is used as is.
- **Per-attempt steps with secrets:** `npm ci` or a database migration belongs in an environment's `setup`, not in `install`, which never sees secrets or the workspace.
- **Other harnesses:** a `FROM ${ES_BASE}` Dockerfile builds once per harness, on that harness's image (see [Compare agents](/recipes/compare-agents)).
- **Registries only:** add `egress: { allow: [...DEFAULT_EGRESS_ALLOW] }` so the agent can install packages but reach nothing else (see [Offline evals](/recipes/offline)).
