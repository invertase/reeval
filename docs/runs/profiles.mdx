---
title: "Size runs with profiles"
description: "Size a run for pull requests, nightly runs, and local work."
---

A profile is a named preset in the `reeval.config.ts` file that sizes a [run](/core-concepts#run): what evaluations get by default, caps over every evaluation, a budget, and which tags run. One set of evaluation files then serves a cheap pull-request run and a thorough nightly one. For more information about wiring a profile into a workflow, see [CI](/runs/ci).

## Define a profile

In the `reeval.config.ts` file, add a `profiles` map with one entry per kind of run:

```ts title="reeval.config.ts"
import { defineConfig } from '{{ pkg }}'

export default defineConfig({
  defaultProfile: { ci: 'pr' },
  profiles: {
    pr: { limit: { runs: 1 }, budget: { attempts: 10 } },
    nightly: {
      defaults: { runs: 4 },
      record: 'always',
      budget: { duration: '2h' },
    },
  },
})
```

`defaultProfile.ci` picks `pr` whenever the `CI` variable is set. For a runnable project, see [`with-profiles`](https://github.com/invertase/reeval/tree/main/examples/with-profiles). For one profile per harness, each in Docker with its own judge, see the examples' shared [`profiles.ts`](https://github.com/invertase/reeval/blob/main/examples/profiles.ts).

reeval applies a profile's `defaults` after the `reeval.config.ts` file and before groups and evaluations, so an evaluation that sets its own `runs` keeps it. A profile's `tags` select evaluations like `--tag` does, and `'!slow'` excludes a tag. `record: 'always'` copies every run under that profile into the history folder.

To pick a profile, pass `--profile`:

```bash
npx reeval run --profile nightly
```

The relevant start of the plan line names the profile and its selection source:

```text
plan  profile nightly (--profile) · 5 evals · 13 cells · 35 attempts · …
```

The `REEVAL_PROFILE` environment variable names a profile the same way. `--profile` takes precedence when both are set.

## Limit a profile

A profile's `limit` applies after every group and evaluation, and it only narrows. `runs` caps the attempts per cell, `compare: false` runs the baseline alone, `compare: { maxVariants: n }` keeps the first `n` variants, and `harness` lists the harness ids the run may use. In the `reeval.config.ts` file, restrict the `pr` profile to one harness:

```ts title="reeval.config.ts"
    pr: {
      limit: {
        runs: 1,
        compare: false,
        harness: ['claude-code:claude-sonnet-5'],
      },
      budget: { attempts: 10 },
    },
```

The relevant notes show each cut. reeval skips an evaluation when a profile leaves it with no harness:

```text
runs 4 → 1 (profile pr)
compare off (profile pr)
skipped: no harness left: profile pr allows claude-code:claude-sonnet-5
```

The `--runs` flag replaces every evaluation's `runs` outright, so a profile's `limit.runs` does not apply to it.

## Pin an evaluation

An evaluation or group's `pin` option names the keys a profile's `limit` may not narrow: `'runs'`, `'compare'`, or `'harness'`. For a regression that must keep its variant on every run, pin `compare` and `runs` in the `evals/brand.eval.ts` file:

```ts title="evals/brand.eval.ts"
pin: ['compare', 'runs'],
```

Under the `pr` profile, the plan lists both cells and notes `pinned: compare, runs`. A group's `pin` covers every evaluation in it.

## Set a budget

reeval merges a profile's `budget` over the `budget` in the `reeval.config.ts` file, key by key. `attempts` caps the plan. reeval exits with code 2 before starting a run over the cap. `--force` starts it anyway. `duration` starts with the first attempt. At the limit, reeval lets running attempts finish and skips queued attempts. Preview a run against its budget:

```bash
npx reeval run --profile pr --dry-run
```

The relevant end of the plan line shows whether the plan fits:

```text
… · 6 attempts · budget 5 attempts ✗
```

A run over `budget.attempts` stops with the same numbers:

```text
reeval: this run plans 6 attempts, over budget.attempts 5 (profile pr).
Narrow it with --tag or --runs, or raise the budget.
(--force runs it anyway)
```

When `budget.duration` stops a run, reeval records the status as `budget`.

## Pick a default profile

The `defaultProfile` option chooses a profile when neither `--profile` nor `REEVAL_PROFILE` names one. In the `reeval.config.ts` file, make pull-request runs the default in CI:

```ts title="reeval.config.ts"
  defaultProfile: { ci: 'pr' },
```

reeval picks `defaultProfile.ci` when the `CI` variable is set, else `defaultProfile.local`, else no profile. The plan line reports the choice as `profile pr (auto: CI is set)`, or `no profile`. reeval exits with code 2 and lists the profiles in the `reeval.config.ts` file when no profile defines the requested name.
