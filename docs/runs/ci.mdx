---
title: "Run evaluations in CI"
description: "Fail a CI job when a recorded run regresses."
---

Run evaluations on each pull request opened from this repository so the job keeps a recorded run and fails when an evaluation regresses. Create a profile named `pr` before adding the workflow. For more information about profiles, see [Profiles](/runs/profiles).

## Add the workflow

<Steps>
<Step title="Run evaluations">

Add the `.github/workflows/reeval.yml` file. It runs the evaluations on each pull request opened from this repository.

```yaml title=".github/workflows/reeval.yml"
name: Evaluations
on:
  pull_request:
jobs:
  reeval:
    if: >-
      ${{ github.event.pull_request.head.repo.full_name ==
      github.repository }}
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          ref: ${{ github.head_ref }}
      - uses: actions/setup-node@v4
        with:
          node-version: {{ node }}
      - run: npm ci
      - id: reeval
        env:
          CURSOR_API_KEY: ${{ secrets.CURSOR_API_KEY }}
        run: npx reeval run --profile pr
```

The `ubuntu-latest` runner includes the container runtime the sandbox uses. `fetch-depth: 0` keeps every ancestor commit, so `reeval compare` can pick a base run from one of them. The `ref` input checks out the pull request branch, and the `contents: write` permission lets a later step push to that branch.

The run step's id is `reeval`. At the start of the run, the `reeval run` command writes `run-id=<id>` to `GITHUB_OUTPUT` and appends `run <id>` to `GITHUB_STEP_SUMMARY`.

When the run finishes, the `reeval run` command appends the run's `summary.md` file to the job summary. A failed run receives that file too. With `GITHUB_ACTIONS` set, a failing attempt stays expanded in the log and adds an error annotation on its evaluation file.

The `reeval run` command exits 0 when the outcome is a pass, 1 when it is a fail, and 3 when it is an infrastructure error. Any other non-zero code fails the job too.

An ungated cell, a control by default, can fail on a run that exits 0. A `budget.duration` stop counts as a failed run. For more information about exit codes, see [Exit codes](/reference/cli#exit-codes).

</Step>
<Step title="Add the API key">

Add your harness's API key to the repository secret used by the run step.

</Step>
<Step title="Record results">

In the `.github/workflows/reeval.yml` file, add this step to commit the history directory and push it, so a later run can use this one as its base.

```yaml title=".github/workflows/reeval.yml"
      - name: Commit the history directory
        if: ${{ !cancelled() }}
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "reeval-ci@example.com"
          git add evals/.history
          git commit -m "chore: record reeval run"
          git push
```

The default `record` value is `'ci'`. It copies each finished run into the history directory when the `CI` variable is set to anything other than `false`. With the default include patterns, that directory is `evals/.history`.

When that copy finishes, reeval prints a line that ends with `Commit it with git`.

The copy includes a run whose evaluations fail. reeval leaves an interrupted run in the `.reeval/runs` directory. A run that `budget.duration` stops is recorded with status `budget`, and a later `reeval compare` skips a run with that status when it picks a base.

The commit step runs when `reeval run` passes or fails. `if: ${{ !cancelled() }}` skips it when the job is cancelled.

The job skips pull requests opened from forks because their default token has no push access.

</Step>
<Step title="Fail on a regression">

In the `.github/workflows/reeval.yml` file, add these two steps. `reeval compare` reads the history directory and picks the newest complete run on an ancestor of the pull request's commit. The steps append the diff to the job summary and fail the job on a regression, and they run unless the job is cancelled.

```yaml title=".github/workflows/reeval.yml"
      - if: ${{ !cancelled() }}
        run: npx reeval compare --md >> "$GITHUB_STEP_SUMMARY"
      - if: ${{ !cancelled() }}
        run: npx reeval compare --fail-on-regression
```

The `reeval compare --fail-on-regression` command exits 1 when the diff says `regressed`, when an evaluation marked `new` fails, or when an evaluation marked `can't compare` fails. The gate ignores an evaluation whose only failures are attempts an interrupt cancels.

With no earlier recorded run, `reeval compare` lists every evaluation as `new`, and the gate fails only when one of them fails.

For more information about `regressed`, `new`, and `can't compare`, see [Regressions](/results/regressions).

</Step>
</Steps>
