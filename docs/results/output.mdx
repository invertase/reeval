---
title: "Read a run's output"
description: "Read the outcomes, the tally, and the remarks that reeval run and reeval show print."
---

`reeval run` ends with a status list: each evaluation file, one line per evaluation under it, then a tally of the run. `reeval show` prints the full result blocks with their tables.

## Read the outcomes

```text
with-reeval-mcp.eval.ts
└─ ✗ adds a tested multiply function  0 of 1 run passed
     Failed on fake.
     Every failure was the same check:
       "toSucceed node --test" failed once
         expected command to succeed, exit code 1
         …
         at with-reeval-mcp.eval.ts:13

Done in 1s · 1 failed
Browse it: reeval studio · summary .reeval/runs/…/summary.md
```

Each line is an icon, the evaluation's name and `N of M runs passed`: `✓` passed, `✗` failed or hit an infra error, `●` ran (no cell is gated, as under [`gate: 'observe'`](/reference/options#gate)), `–` skipped or todo, and `○` canceled. A passing evaluation is one line. A failed one, a comparison, and one with remarks add sentences under it: how each harness did, the control and each variant with its effect, an evaluation's rate over its cases under `gate: { passRate }` and the cases that failed, each failed assertion with its first message and file location, a failed evaluation's workspace snapshot, its observations, and each question's answers. For more information about what an assertion decides, see [Assertion](/reference/glossary#assertion). To print the sentences under every evaluation, pass `-v`.

`Done in` gives the run's time, then the tally, which omits zeros, as in `2 failed · 1 passed · 1 infra error`. A failure outside any evaluation prints first, as `error:`, and counts as a `run error`. `Browse it:` names the studio and the run's `summary.md` file. For more information about the trace of a failed assertion, see [Debug a failing attempt](/results/inspection/debugging).

On a terminal outside CI, unless `--ui` names a mode, the list draws while the run goes, and stays up once it ends so you can browse it: the up and down arrows move, the right arrow or enter opens an evaluation's sentences, the left arrow or escape folds them, and `q` quits and leaves the list in your scrollback. During the run, Ctrl-C cancels it, and so does `q` pressed twice within three seconds. Each attempt's own log lines print only with `--output-logs` (`-v` selects `full`), and then without the interactive list.

## Read remarks

Under an evaluation, `Worth knowing:` names concerns about it, such as a flaky assertion, a slow MCP server start, or too few runs for a difference to hold. reeval's own rules raise them from the run and its history, with no model. Each ends with `Fix at` and the file location to change. At most three concerns print, then `+N more remarks (-v)`. To print the rest and any suggestion, pass `-v`. A concern prints on the run that first raises it. A slow server start, or too few runs for a difference to hold, prints on every run where it happens. The same list also names an assertion that passed only on a retry.

A remark looks like this:

```text
└─ ✓ records the change in the changelog  1 of 1 run passed
     Control short-rules passed 0 of 1.
     Variants, by pass rate:
       detailed-rules  1 of 1  helped
     …
     Worth knowing:
       The detailed-rules variant passed 1 of 1 run and the control 0 of 1: better by 100 points, but on too few runs for the difference to hold. Fix at with-rules-ab.eval.ts:14: set runs: 4, where a difference this size would hold.
```

## Show one run

`reeval show` prints the most recent run as result blocks, with each arm's pass counts and a table of assertions per cell:

```bash
npx reeval show
```

To print one run, pass its id:

```bash
npx reeval show <run-id>
```

To print that run's `summary.md` file, pass `--md`:

```bash
npx reeval show <run-id> --md
```

To print the record as JSON, pass `--json`:

```bash
npx reeval show --json
```

For more information about the job summary in a pull request, see [Fail a pull request when results regress](/evaluations/recipes/gate-pull-requests).

For more information about every `reeval show` flag, see [the `reeval show` command](/reference/cli#reeval-show).
