---
title: "Read a run's output"
description: "Read the outcomes, the tally, and the remarks that reeval run and reeval show print."
---

`reeval run` ends with a status list: each evaluation file, one line per evaluation under it, then a tally of the run. `reeval show` prints the full result blocks with their tables.

## Read the outcomes

```text
with-reeval-mcp.eval.ts
└─ ✗ adds a tested multiply function  0 of 1 run passed
     Failed on fake.
     ✗ toSucceed node --test  failed 1 of 1 run
       expected command to succeed, exit code 1 · with-reeval-mcp.eval.ts:13

Done in 846ms · 1 failed
Browse it: reeval studio · summary .reeval/runs/…/summary.md
```

Each line is an icon, the evaluation's name and `N of M runs passed`: `✓` passed, `✗` failed or hit an infra error, `●` ran (no cell is gated, as under [`gate: 'observe'`](/reference/options#gate)), `–` skipped or todo, and `○` canceled. A passing evaluation is one line. A failed one, a comparison, and one with remarks add lines under it: how each harness did, a table of the arms, the rate over the cases under `gate: { passRate }` and the failed cases, and each failed [assertion](/reference/glossary#assertion) with the runs or arms it failed on, its first message line and its location.

`-v` prints them under every evaluation, with each full message, file excerpt, snapshot, interval and remark. `--ui agent` always prints each failure's full message, excerpt and snapshot.

`Done in` gives the run's time, then the tally, which omits zeros, as in `2 failed · 1 passed · 1 infra error`. A failure outside any evaluation prints first, as `error:`, and counts as a `run error`. `Browse it:` names the studio and the run's `summary.md` file. For more information about the trace of a failed assertion, see [Debug a failing attempt](/results/inspection/debugging).

On a terminal outside CI, unless `--ui` names a mode, the list draws while the run goes and stays up once it ends: ↑ and ↓ move, → opens an evaluation and, on an open one (`→ more`), shows what `-v` adds, enter opens or closes it, ← steps back, escape folds it, and `q` quits, leaving the list in your scrollback.

A spinner turns while reeval waits on a sandbox, an agent turn or a judge. An evaluation gets its `✓` or `✗` once all its runs end; until then a red spinner marks one with a failed run, which the footer counts: `9 of 10 evals done · 1 failing`. Piped output has no spinner. During the run, Ctrl-C cancels it, and so does `q` pressed twice within three seconds. Each attempt's own log lines print only with `--output-logs` (`-v` selects `full`), and then without the interactive list.

## Read remarks

Under an evaluation, `Worth knowing:` names concerns about it, such as a flaky assertion, a slow MCP server start, or too few runs for a difference to hold. reeval's own rules raise them from the run and its history, with no model. Each names the file location to change. At most three concerns print, then `+N more remarks (-v)`. To print the rest, each remark's whole sentence and any suggestion, pass `-v`. A concern prints on the run that first raises it; a slow server start, or too few runs, on every run. The same list also names an assertion that passed only on a retry.

A remark looks like this, on one line when it's the only one:

```text
└─ ✓ records the change in the changelog  1 of 1 variant run passed
     The detailed-rules variant helped.
     arm                    passed  verdict
     short-rules (control)  0 of 1
     detailed-rules         1 of 1  helped
     ✗ changelog entry  failed on the control · expected
       expected CHANGELOG.md to match /## Unreleased\s+- feat: / · with-rules-ab.eval.ts:20
     Worth knowing: 1 run per side; set runs: 4 at with-rules-ab.eval.ts:14 to confirm this difference.
```

A control that isn't gated fails as `expected`. With `-v`, the remark prints its whole sentence:

```text
     Worth knowing: The detailed-rules variant passed 1 of 1 run and the control 0 of 1: better by 100 points, but on too few runs for the difference to hold. Fix at with-rules-ab.eval.ts:14: set runs: 4, where a difference this size would hold.
```

## Show one run

`reeval show` prints the most recent run as result blocks, with each arm's pass counts and a table of assertions per cell:

```bash
npx reeval show
```

To print one run, pass its id:

```bash
npx reeval show <run-id>
```

To print that run's `summary.md` file, pass `--md`:

```bash
npx reeval show <run-id> --md
```

To print the record as JSON, pass `--json`:

```bash
npx reeval show --json
```

For more information about the job summary in a pull request, see [Fail a pull request when results regress](/evaluations/recipes/gate-pull-requests).

For more information about every `reeval show` flag, see [the `reeval show` command](/reference/cli#reeval-show).
