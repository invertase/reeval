title: "Read the results summary"
description: "Interpret a run's results summary."
---

`reeval run` ends with one block per evaluation, then a tally of the run.

## Read the outcomes

The outcome word is `pass`, `fail`, `infra error`, `cancelled`, `skipped`, `todo`, or `not gated`. `not gated` replaces `pass` on the block when no cell is gated. The tally counts that block as `pass`. A `todo` block counts as `skipped`.

A `fail` block lists each assertion that failed or did not run. For more information about what an assertion decides, see [Assertion](/core-concepts#assertion).

On one attempt, a failed assertion prints `failed`. Several attempts add a tries row. Passed assertions print as `+N more passed`. For more information about the trace of a failed assertion, see [Debug a failing attempt](/results/debugging).

A failed evaluation prints like this:

```text
fail             adds a tested multiply function
  toSucceed node --test  failed
    expected command to succeed, exit code 1
  +2 more passed
```

The tally omits zeros, as in `2 fail · 1 pass · 1 infra error`. A failure outside any evaluation counts as a `run error`. With no analysis model, this line follows the tally:

```text
Set analysis.model in reeval.config.ts for answers to what each eval asks.
```

For more information about setting that model, see [Analyse a run with reeval analyze](/results/analysis).

## Read a comparison

Rows for the control and each variant print under `arm`, `harness`, or `sandbox`. The `pass` column is passed attempts out of counted attempts. The effect word is `helped`, `made it worse`, or `can't tell yet`. Equal pass rates, with at least four counted attempts a side, print no effect word. For more information about how reeval chooses an effect word, see [Comparison](/core-concepts#comparison).

Here `page` is the control and `brand-guidelines` is the variant:

```text
pass             styles the page in Anthropic's brand
  arm               pass
  page              0 of 4
  brand-guidelines  4 of 4  helped
```

When the variant does not reach `compare.minLift`, the row reads like `helped, not by minLift 50`. To print the interval under the variant, pass `-v`:

```text
    difference +100 points, 95% interval +31…+100
```

For more information about that interval, see [How reeval decides a change helped](/evals/statistics).

For the control and each variant, a pairwise question prints `won 3 of 4`. The outcome word does not change.

## Read the assertion and effort tables

The assertion table, headed `check`, has one column per cell and lists assertions that failed or did not run in some cell. Passed assertions print as `+N more passed`. `couldn't check` means the assertion raised an error.

The assertions in a comparison look like this:

```text
  check             page    brand-guidelines
  brand orange      0 of 4  4 of 4
    expected styles.css to match /#d97757/i
  brand fonts       0 of 4  4 of 4
    expected styles.css to match /Poppins[\s\S]*Lora|Lora[\s\S]*Poppins/
  +1 more passed
```

The `effort` table lists `tools` and `time`, plus `tokens` when a cell reported them. Each number is the median. The `effort` table prints when there are at least four counted attempts and either effort differs between cells or the evaluation failed.

The effort rows look like this, for two arms that pass alike:

```text
  effort           tools  time
  math             1      1.0s
  project-layout   1      <0.1s
```

## Read insights and Remarks

An analysis model adds an answer under the name and a headline before the tally:

```text
pass             adds a tested multiply function
  Yes: the agent added it and the tests pass.

Every eval passed.
```

On a comparison or a failure, it also adds a sentence under a row and a finding after the tables.

The outcome word stays the assertions' result. For more information about what insights and Remarks are, see [Analysis](/core-concepts#analysis).

After the tally, `Remarks:` names concerns about the evaluations. A `fix` or `at` line names the file location. At most three concerns print, then `+1 more (-v)`. To print the rest and any suggestion, pass `-v`. A concern prints on the run that first raises it. A slow server start prints on every run where it happens.

A remark looks like this:

```text
Remarks:
  reads an SSH banner over raw TCP: It failed with "Temporary failure in name resolution" and nothing reached the egress gateway: under egress 'proxy' only HTTP(S) through the gateway leaves the sandbox, so raw TCP, UDP, SSH and database connections fail.
    fix  with-egress-allow-all.eval.ts:5  set egress: 'allow-all' on the eval if it needs raw TCP or UDP, or point the client at HTTPS_PROXY
```

## Show one run

`reeval show` prints the most recent run, with the same blocks as `reeval run`:

```bash
npx reeval show
```

To print one run, pass its id:

```bash
npx reeval show <run-id>
```

To print that run's `summary.md` file, pass `--md`:

```bash
npx reeval show <run-id> --md
```

To print the record as JSON, pass `--json`:

```bash
npx reeval show --json
```

For more information about the job summary in a pull request, see [Fail a pull request when results regress](/recipes/ci-gate).

For more information about every `reeval show` flag, see [the `reeval show` command](/reference/cli#reeval-show).
