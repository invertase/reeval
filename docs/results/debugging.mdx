---
title: "Debug a failing attempt"
description: "Find why a failed attempt did what it did."
---

When an attempt fails, read the phase trace and the transcript to see what the harness did.

## Print the trace

The `-v` flag prints each attempt's phase trace as the attempt runs. The phase on a line is `plan`, `image`, `container`, `env`, `broker`, `harness`, `check`, `judge`, `gateway`, or `teardown`. With `-v`, a passing attempt prints its detail lines.

Print the phase trace for the run.

```bash
npx reeval run -v
```

Each line starts with the attempt's tag. This trace follows the evaluation in [Write an evaluation](/write), from the pinned checkout to the hidden test:

```text
[adds#1 fake] 15:04:40 env       workspace github:sindresorhus/camelcase#v10.0.0 at 328428291b2f (92160 bytes of tar, with a .git) in 25ms
[adds#1 fake] 15:04:40 env       workspace snapshot taken: the diff starts here
…
[adds#1 fake] 15:04:41 check     assert ✓ the repo's tests pass (toSucceed, pass)
[adds#1 fake] 15:04:41 check     assert ✓ toHaveFile readme.md (toHaveFile, pass)
[adds#1 fake] 15:04:41 check     assert ✓ the option works (toSucceed, pass)
```

This trace comes from the example's scripted agent, so its tag reads `fake`. For a runnable project, see [`with-existing-codebase`](https://github.com/invertase/reeval/tree/main/examples/with-existing-codebase).

After the attempt's tag, a failed command assertion has this shape.

```text
12:50:01 check     $ test -f src/user.test.ts → exit 1 · 4ms
```

The `-vv` flag adds raw payloads, container commands under the `docker` phase, request headers, and DNS decisions. `--trace` is the same flag. The terminal prints a short payload. The `trace.ndjson` file keeps the rest.

Print the raw trace for the run.

```bash
npx reeval run -vv
```

reeval replaces secret values with `[REDACTED]` in the trace.

For more information about every `reeval run` flag, see [reeval run](/reference/cli#reeval-run).

## Open the debug directory

The `.reeval/debug` directory holds one directory per run. reeval writes that directory on every run. Git ignores it with the rest of the `.reeval/` directory.

Attempt files sit at the `.reeval/debug/<run id>/<evaluation>/<cell>/<n>/` path. The evaluation and cell names are slugs, each with a short hash.

Open the `debug.log` file for that trace. Each line has a full timestamp.

```text
2026-09-26T12:50:01.234Z check     $ test -f src/user.test.ts → exit 1 · 4ms
```

The `requests.ndjson` file records one JSON object for each request the egress gateway handles. reeval writes the `trace.ndjson` file for a failing attempt and for every attempt with `-vv`. The first line of the `trace.ndjson` file counts entries the buffer dropped. The `debug.traceBufferMb` option caps that file.

For more information, see [the studio's **Debug** tab](/results/studio).

## Read a transcript

The `transcript.jsonl` file lists every message and tool call of an attempt, in order. reeval writes that file for an attempt with a turn, at the `.reeval/runs/<run id>/<evaluation>/<cell>/<n>/transcript.jsonl` path.

Each line is one JSON object. A turn starts with a `prompt` line, continues with that turn's events, and ends with a `turn-end` line carrying `status` and `durationMs`. A tool line names the tool and includes the input and the output. The `transcript.jsonl` file keeps the final message whole.

A prompt line has these fields.

```json
{
  "ts": "2026-09-27T16:10:34.029Z",
  "atMs": 0,
  "turn": 0,
  "type": "prompt",
  "text": "Add a Vitest test for getUserId."
}
```

To also write the `transcript.raw.jsonl` file in that directory, one stream part per line, set `REEVAL_RAW_TRANSCRIPT` to `1`.

## Prune debug data

Each run keeps the newest debug directories and deletes the older ones. The `debug.keep` option sets the number of directories to keep, and the default is 20. The `.reeval/runs/` directory stays on disk.

Remove the debug data.

```bash
npx reeval clean
```

reeval prints how many runs it removed and the size. To leave the newest runs in place, pass `--keep`.

```bash
npx reeval clean --keep 5
```

To also remove untagged sandbox images that reeval built, pass `--images`.

## Reference

In the `reeval.config.ts` file, add the `debug` option.

```ts
import { defineConfig } from '{{ pkg }}'

export default defineConfig({
  debug: { keep: 20, traceBufferMb: 8 },
})
```

The `debug.keep` option is a whole number of at least 1. The `debug.traceBufferMb` option is a number of megabytes above 0. Oldest entries in an attempt's buffer drop first.

In the shell that starts reeval, set these variables.

| Variable | Effect |
| :--- | :--- |
| `REEVAL_DEBUG` | Prints image prepare logs, container engine logs, an evaluation file's stdout and stderr, and an unexpected error's stack. |
| `REEVAL_RAW_TRANSCRIPT` | Writes the `transcript.raw.jsonl` file when set to `1`. |
| `REEVAL_NO_REPORT_HINT` | Hides the hint reeval prints after a crash when set to `1`. |

For more information about every variable, see [Environment variables](/reference/env-vars).

For more information about a redacted bug report, see [reeval report](/reference/cli#reeval-report).
