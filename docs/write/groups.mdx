description: "Apply the same options to several evaluations."

Use `group()` when several evaluations share an environment, tags, or a judge. The two evaluations below ask for Vitest tests in a `plain` environment, defined in the `evals/environments.ts` file.

## Group evaluations

A `group()` call wraps the evaluations that share its options. In the `evals/shoehorn.eval.ts` file, give both evaluations the `plain` environment and the `smoke` tag:

```ts title="evals/shoehorn.eval.ts"
import { evaluate, expect, group } from '{{ pkg }}'
import { plain } from './environments.ts'

group('request builders', { environment: plain, tags: ['smoke'] }, () => {
  evaluate('tests build only the request fields they read', async (c) => {
    await c.send('Add a Vitest test for getUserId in src/user.test.ts.')
    await expect(c, 'uses fromPartial').toHaveFile(
      'src/user.test.ts',
      /fromPartial(<\w+>)?\(/,
    )
  })

  evaluate('tests mock only the services they call', async (c) => {
    await c.send('Add a Vitest test for chargeCard in src/billing.test.ts.')
    await expect(c, 'uses fromPartial').toHaveFile(
      'src/billing.test.ts',
      /fromPartial(<\w+>)?\(/,
    )
  })
})
```

`group.skip` keeps a group in the file and skips every evaluation inside it, including a nested group. `group.only` runs only that group in its own file, and other files still run. reeval refuses `group.only` when the `CI` variable is set. `group.todo` takes a name and no body, and the plan lists it as `todo`. The groups around a `group.todo` still add their tags to it. For a runnable project with a group, `evaluate.skip`, and `evaluate.todo`, see [`with-groups`](https://github.com/invertase/reeval/tree/main/examples/with-groups).

In the `evals/shoehorn.eval.ts` file, focus the group and leave a placeholder:

```ts title="evals/shoehorn.eval.ts"
group.only(
  'request builders',
  // ...
)
group.todo('payment builders')
```

## Nest groups

An inner `group()` inherits the outer group's options and can set its own. In the `evals/shoehorn.eval.ts` file, put the billing evaluation in an inner group:

```ts title="evals/shoehorn.eval.ts"
  group('billing', { tags: ['billing'] }, () => {
    evaluate(
      'tests mock only the services they call',
      // ...
    )
  })
```

The inner evaluation keeps the outer group's `plain` environment and `smoke` tag, and adds the `billing` tag.

## Override an option in one evaluation

An `environment`, `timeout`, `runs`, `gate`, or `sandbox` on one `evaluate()` call replaces the group's value for that evaluation. The other evaluations keep the group's value. In the `evals/shoehorn.eval.ts` file, give one evaluation a longer timeout:

```ts title="evals/shoehorn.eval.ts"
    evaluate(
      'tests build only the request fields they read',
      { timeout: '30m' },
      // ...
    )
```

## See how options cascade

reeval applies options from the config, through each group, to the evaluation. A later level replaces `environment`, `runs`, `gate`, `timeout`, and `sandbox` when it sets them.

The table lists the levels that set an option before a profile limit, from first to last:

| Level | Set in |
| :--- | :--- |
| Config | the `reeval.config.ts` file |
| Profile defaults | the selected profile |
| Outer group | the outer `group()` call |
| Inner group | an inner `group()` call |
| Evaluation | the `evaluate()` call |

After the evaluation, a profile limit can narrow `runs`, `compare`, and `harness`. The `--runs`, `--tag`, and `--concurrency` flags come last. For more information about the full order, see [The cascade](/reference/options#the-cascade).

For more information about narrowing harnesses with `add` and `only`, see [Harnesses](/agents).

`tags` are added at each group and on the evaluation, so an evaluation keeps every tag from the groups around it. Run the evaluations tagged `smoke`:

```bash
npx reeval run --tag smoke
```

Start a `--tag` value with `!` to leave that tag out. Repeat `--tag` to keep an evaluation only when every filter matches. For more information about `tags`, see [the `tags` option](/reference/options#tags).

## Verify with the `reeval run --dry-run` command

The `reeval run --dry-run` command plans the run without starting a sandbox or a harness, so it needs no API key. Plan the run:

```bash
npx reeval run --dry-run
```

The `plan` line counts the evaluations, cells, and attempts, and estimates the time. Each row names an evaluation by its file, its groups, and its name, joined with `›`. A `group.todo` row is marked `todo`. If an evaluation is missing, check that its file ends in `.eval.ts` and sits under the `evals/` folder.

For more information about every argument `group()` takes, see [Authoring API](/reference/api#group).
